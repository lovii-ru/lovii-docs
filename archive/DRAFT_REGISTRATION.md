## 1. Профили в системе

| Тип профиля | Кто | Как становится | Промокод |
|---|---|---|---|
| **Пользователь** | Любой, кто скачал приложение / зашёл на сайт | Регистрация по телефону (без промокода) | Нет (пока не станет Представителем) |
| **Представитель** | Участник, приглашающий МСП на платформу | Ввод промокода при регистрации **или** при подписке | Промокод с префиксом пригласившего |
| **Амбасадор** | Руководитель локации / партнёр распространения | **Регистрируется на платформе** → Основатель находит профиль в админке → присваивает статус Амбасадора + промокод | Уникальный 2-символьный префикс; выдаёт промокоды Представителям |
| **Основатель** | Супер-админ системы (ООО «Аксиома») | Единственный в системе (seed-аккаунт) **ИЛИ** Амбасадор, который: 1) передал весь совокупный доход по ветке в компанию + 2) предложил не менее 2 Амбасадоров из числа своих Представителей | Префикс `AA`; привилегии: доступ к распределению бюджета дохода компании, создание акций, продуктовый бэклог, бюджеты мероприятий |

**Важно:**
- Роли не взаимоисключающие — один UDID может совмещать МСП + Представитель.
- Статус «Представитель» присваивается **только** при активации подписки с промокодом.
- Регистрация без промокода создаёт **Пользователя** (без статуса Представителя).
- **Амбасадор → Основатель:** только через передачу дохода + 2 кандидата от Амбасадора (см. §12).

## 2. Структура промокода

Формат: `PPXXXX` (6 символов)

| Часть | Символы | Описание |
|---|---|---|
| **Префикс (PP)** | Первые 2 | Код «ветки» — привязан к Амбасадору. При регистрации префикс наследуется от пригласившего |
| **Суффикс (XXXX)** | Последние 4 | Уникальный в рамках префикса. Генерируется случайно из 33-символьного алфавита |

**Алфавит промокода** (33 символа): `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`
Исключены: `0`, `1`, `I`, `O` (путаница с буквами/O).

**Пример:**
- Основатель выдаёт промокод `AAAAAA` (префикс `AA`, суффикс `AAAA`) — **рабочий промокод для всех**
- Амбасадор с префиксом `BJ` → его промокод: `BJ3M9K`
- Представитель зарегистрирован по `BJ3M9K` → его промокод: `BJ7P2L` (тот же префикс `BJ`)
- Пользователь зарегистрировался без промокода → промокода нет (пока не станет Представителем)

## 3. Процесс регистрации

### 3.1. Регистрация БЕЗ промокода

1. Пользователь вводит телефон, не указывает промокод.
2. Создаётся аккаунт **Пользователя** (без статуса Представителя).
3. Промокод **не генерируется** — появится позже при подписке.

### 3.2. Регистрация С промокодом

1. Пользователь вводит телефон и промокод (`INVITER_CODE`).
2. Система проверяет промокод:
   - Несуществующий → 404 `PROMO_NOT_FOUND`
3. Определяется префикс пригласившего (`PREFIX = INVITER_CODE[0:2]`).
4. Генерируется суффикс из 4 символов.
5. Промокод: `PREFIX` + суффикс (тот же префикс, что у пригласившего).
6. Пользователь получает статус **Представитель** в ветке пригласившего.

### 3.3. Активация Представителя через подписку

1. Пользователь (без статуса Представителя) заходит в настройки подписки.
2. Ему предлагается **ввести промокод** для получения скидки.
3. Вводит промокод → система применяет скидку:
   - `AAAAAA` (и другие промокоды с префиксом `AA`) → 199₽/мес вместо 599₽/мес
   - Другие промокоды → условия определяются Амбасадором (скидка, срок акции)
4. Пользователь оплачивает подписку и получает статус **Представитель**.
5. Генерируется **личный промокод** с тем же префиксом, что и введённый промокод.

### 3.4. Назначение Амбасадора (ручное)

1. **Будущий Амбасадор** регистрируется на платформе как обычный Пользователь.
2. **Основатель** (супер-админ) заходит в админ-панель.
3. Находит профиль будущего Амбасадора **по номеру телефона или другим данным**.
4. Присваивает статус **Амбасадор** и назначает промокод:
   - Вводит промокод (6 символов, формат `PPXXXX`) — **вручную**
   - Система проверяет уникальность префикса (первые 2 символа)
5. Амбасадор видит свой промокод и **спец-ссылки с промокодом** в профиле.
6. Амбасадор **выдаёт промокоды Представителям**: берёт свой префикс + генерирует случайный суффикс (4 символа). Например, Амбасадор `EGRPAT` выдаёт Представителю `EG5K2L`.

**Примеры назначения:**

| Промокод | Префикс | Суффикс | Статус |
|---|---|---|---|
| `EGRPAT` | `EG` | `RPAT` | ✅ Амбасадор 1 |
| `EG2345` | `EG` | `2345` | ❌ Префикс `EG` занят |
| `LOVII3` | `LO` | `VII3` | ✅ Амбасадор 2 |
| `LO7777` | `LO` | `7777` | ❌ Префикс `LO` занят |

## 7. Региональная привязка

### 7.1. Принцип

> **По умолчанию все пользователи ассоциированы с компанией LOVII.**
> Для Амбасадора присваивается ассоциация к регионам из списка.

### 7.2. Формат региона

| Параметр | Описание |
|---|---|
| **Справочник регионов** | Официальный список регионов России (области, края, республики, города федерального значения) |
| **Формат** | Строковое поле из справочника (например, `Ленинградская область`, `Москва`, `Краснодарский край`) |
| **Привязка** | Амбасадор привязывается к **одному или нескольким регионам** при назначении Основателем |
| **Одноместность** | Один регион может быть присвоен **только одному Амбасадору** |
| **Список с чекбоксами** | Основатель видит список всех регионов и выбирает чекбоксами нужные для Амбасадора |

### 7.3. Механика

1. **Пользователь по умолчанию** → ассоциация с компанией LOVII (без привязки к региону).
2. **Амбасадор** → при назначении Основатель указывает регион(ы) из справочника (чекбоксы).
3. **Представитель** → при регистрации определяется регион по:
   - **Геопозиции** (по умолчанию — определяем автоматически)
   - **Адресу точки** (более точная привязка)
   - **Городу** (средняя точность)
4. **Конфликт регионов** → автоматическое перераспределение (см. §8.3).
5. **Регион без привязки** → по умолчанию регион компании LOVII.

### 7.4. Правила распределения по регионам

1. **Амбасадор создаётся для региона.** Основатель при назначении Амбасадора указывает регион(ы) из справочника (чекбоксы).
2. **Представитель привязывается к региону** при регистрации (по геопозиции, адресу точки или городу).
3. **Если в регионе уже есть Амбасадор:**
   - Представитель, зарегистрированный по промокоду **другого** Амбасадора, но работающий в регионе первого — **автоматически попадает в структуру местного Амбасадора**.
   - Промокод Представителя сохраняется (префикс пригласившего), но **начисления 20% Амбасадору** идут местному Амбасадору региона, а не тому, чей промокод был использован.
4. **Разделение территории.** Если в одном регионе несколько Амбасадоров — территория делится между ними (районы, кварталы). Определяется при назначении Основателем.
5. **Регион без привязки** → по умолчанию регион компании LOVII.

### 7.5. Исключения

- **Онлайн-точки** без привязки к адресу — привязываются к региону юридического адреса компании.
- **Точки в пограничных зонах** — приоритет у Амбасадора, чей регион ближе к адресу точки.

## 5. Смена промокода

| Параметр | Значение |
|---|---|
| **Лимит** | Не чаще 1 раза в 30 дней |
| **Что меняется** | Только суффикс (4 символа). Префикс (ветка) **сохраняется** |
| **Прошлые начисления** | Не пересчитываются — остаются у прежнего промокода |
| **Причина смены** | Пользователь может сменить промокод по желанию (раз в 30 дней) |

## 6. Связь промокода и подписки

| Параметр | Значение |
|---|---|
| **Название тарифа** | **Статус Партнёр** |
| **Тариф по умолчанию** | 599 ₽/мес |
| **Тариф по промокоду** | 199 ₽/мес (**скидка 67%**) |
| **Тариф СТАРТ** | 0 ₽ (до 30 000 ₽ выручки) — для МСП |

**Как работает скидка:**
- Пользователь без промокода → подписка «Статус Партнёр» за 599₽/мес
- Пользователь вводит промокод при подписке → «Статус Партнёр» за 199₽/мес
- Промокод определяет **скидку** (67% от стоимости) и **срок действия акции**

**Срок действия акции:**
- Настраивается **Основателем** для каждого Амбасадора и его структуры
- Может быть разным для разных Амбасадоров (в зависимости от региона, кампании и т.д.)
- По истечении срока — подписка автоматически переходит на полную стоимость (599₽/мес)

**Виральность:** «Получи Статус Партнёр» — коротко, запоминается, мотивирует действие.

**Ключевой принцип:** Промокод — способ отследить структуру, а не причина начислений. Причина начислений — действующая подписка владельца промокода + транзакции в МСП, подключённых по этому промокоду.

**Активность промокода:**
- Подписка **активна** → начисления 40% идут владельцу промокода (Представителю)
- Подписка **истекла / не оплачена** → 40% уходит Компании (LOVII)
- Промокод **существует всегда** (создан при регистрации), аналитика работает
- Если промокод уже участвует в системе (по нему есть регистрации) — для них ничего не меняется
- Промокод **не умирает** — это цифровая принадлежность к структуре

**Ценность промокода:**
- Если нет транзакций и нет подключённых МСП → нет нагрузки
- Если есть подключённые МСП и идут транзакции → это актив
- Чем выше обороты по промокоду, тем выше ценность

## 7. Распределение пула (40/40/20)

Источник промокода для распределения — **регистрационный промокод МСП** (серверные данные), а не поле `promo_code` от клиента в запросе транзакции.

| Получатель | Доля | Откуда |
|---|---|---|
| **Компания (LOVII)** | 40% | Фиксировано |
| **Представитель** (владелец промокода МСП) | 40% | Только с транзакций точек, зарегистрированных **лично по его промокоду** (1 уровень) |
| **Амбасадор** (владелец ветки) | 20% | Со **всех** транзакций ветки (branch-wide) |

**Важно:**
- Self-referral разрешён: владелец точки, зарегистрировавший свою точку под своим промокодом, получает свои 40% как обычный Представитель.
- Представитель получает 40% **только** с прямых регистраций (1 уровень). Подчинённые Представители — это уже ветка Амбасадора.
- Статусы Мэр / Губернатор не дают дополнительных денежных начислений, только привилегии.

### 8.2. Механизм роста

```
Пользователь → вводит промокод → получает Статус Партнёр → выдаёт промокоды → рост ветки
```

**Ключевой принцип:** каждый новый Представитель **наследует префикс** пригласившего и создаёт свою «ветку» в рамках Амбасадора.

## 9. Сценарии получения Статуса Партнёр

### Сценарий 1: Регистрация по промокоду Амбасадора

```
Пользователь → вводит промокод AAAAAA (prefix AA) → Статус Партнёр → промокод AA5K2L
```

| Шаг | Действие | Результат |
|---|---|---|
| 1 | Пользователь вводит телефон | Аккаунт создан (без статуса) |
| 2 | Вводит промокод `AAAAAA` | Система проверяет: промокод валиден |
| 3 | Определяется префикс `AA` | Пользователь становится Представителем в ветке Основателя |
| 4 | Генерируется промокод `AA5K2L` | Представитель видит его в профиле |
| 5 | Оплачивает подписку «Статус Партнёр» 199₽/мес | Подписка активна, начисления идут |

### Сценарий 2: Регистрация без промокода → активация через подписку

```
Пользователь → регистрация → нет промокода → хочет Статус Партнёр → вводит промокод при подписке
```

| Шаг | Действие | Результат |
|---|---|---|
| 1 | Пользователь вводит телефон | Аккаунт создан (без статуса) |
| 2 | Не вводит промокод | Промокод не генерируется |
| 3 | Заходит в настройки подписки | Видит: «Введи промокод и получи скидку» |
| 4 | Вводит промокод `BJ3M9K` | Скидка 67%: 599₽ → 199₽/мес |
| 5 | Оплачивает подписку | Получает статус «Статус Партнёр» |
| 6 | Генерируется промокод `BJ7P2L` | Префикс `BJ` (от пригласившего) |

### Сценарий 3: Назначение Амбасадора Основателем


## 12. Путь Амбасадора → Основатель

### 12.1. Условия

Амбасадор может стать Основателем **только** при выполнении **двух условий одновременно:**

1. **Передача совокупного дохода по ветке в компанию** — весь доход, который Амбасадор получил по своей ветке (20% от транзакций), передаётся обратно в компанию LOVII.
2. **Предложение не менее 2 Амбасадоров** из числа своих Представителей — Амбасадор должен выдвинуть минимум 2 кандидатов из своей структуры, которых Основатель утвердит как новых Амбасадоров.

### 12.2. Процесс

```
Амбасадор → выполняет условия → Основатель проверяет → присваивает статус Основателя
```

| Шаг | Действие | Результат |
|---|---|---|
| 1 | Амбасадор передаёт весь совокупный доход по ветке в компанию | Доход возвращается в LOVII |
| 2 | Амбасадор предлагает минимум 2 кандидатов из Представителей | Кандидаты проходят проверку |
| 3 | Основатель проверяет условия | Удовлетворены → ОК |
| 4 | Основатель присваивает статус **Основатель** | Амбасадор получает права Основателя |

### 12.3. Права Основателя (после повышения)

| Право | Описание |
|---|---|
| **Доступ к распределению бюджета дохода компании** | Определяет, как распределяется доход LOVII |
| **Создание акций** | Устанавливает сроки действия акций для Амбасадоров и их структур |
| **Продуктовый бэклог** | Ведёт приоритизацию продуктовых задач |
| **Бюджеты мероприятий** | Определяет состав и бюджеты всех мероприятий |

### 12.4. Важные замечания

- **Основатель = супер-админ** — это не просто статус, а набор прав и ответственности.
- **Амбасадор не становится Основателем автоматически** — только по решению текущего Основателя после проверки условий.
- **Передача дохода** — это добровольный жест лояльности, подтверждающий серьёзность намерений.
- **2 кандидата** — необходимо для того, чтобы новый Основатель способен вырастить свою структуру.

## 10. Деактивация Амбасадора

### 10.1. Процесс

Деактивация осуществляется через **суперадминку** Основателем.

### 10.2. Варианты деактивации

| Вариант | Когда использовать | Что происходит |
|---|---|---|
| **Перенос промокода на профиль Основателя** | Амбасадор уходит, доход нужно сохранить за компанией | Промокод Амбасадора переносится на профиль Основателя; ветка сохраняется |
| **Перенос промокода на профиль Компании** | Амбасадор уходит, доход нужно передать в компанию LOVII | Промокод переносится на профиль Компании; ветка сохраняется |
| **Выдача нового префикса** | Амбасадор деактивирован, но его Представители остаются | Генерируется новый промокод с уникальным префиксом для нового Амбасадора |
| **Полная деактивация ветки** | Амбасадор нарушитель, ветка блокируется | Все промокоды ветки деактивируются; Представители теряют статус |

### 10.3. Сценарии

**Сценарий А: Амбасадор уходит, доход сохраняется**
```
Амбасадор EGRPAT (prefix EG) → деактивация → промокод переносится на Основателя
Представители EG5K2L, EG8R4P → остаются в ветке EG
Начисления 20% → теперь идут Основателю (вместо бывшего Амбасадора)
```

**Сценарий Б: Амбасадор деактивирован, нужен новый Амбасадор**
```
Амбасадор EGRPAT (prefix EG) → деактивация
Основатель находит нового кандидата → назначает Амбасадором → промокод XY7K9M (prefix XY)
Представители EG5K2L, EG8R4P → остаются в ветке EG (старый префикс)
Новые Представители → регистрируются по промокодам XY
```

**Сценарий В: Конфликт интересов (Амбасадор = Представитель)**
```
Амбасадор EGRPAT (prefix EG) →.registered自己的МСП под промокодом EG5K2L
Деактивация → МСП остаётся в ветке EG, Представитель EG5K2L получает 40%
Амбасадор EGRPAT → деактивирован, но МСП продолжает работу
```

### 10.4. Важные замечания

- **Деактивация не удалает данные** — все транзакции, промокоды, структура сохраняются.
- **Доход по ветке** перенаправляется на новый профиль (Основатель / Компания / новый Амбасадор).
- **Представители** остаются в системе и продолжают работать.
- **Повторное назначение** деактивированного Амбасадора возможно только через Основателя.

## 11. Edge cases (решённые вопросы)

| # | Сценарий | Решение |
|---|---|---|
| 1 | Представитель зарегистрировал свою же точку под своим промокодом | Разрешено, получает 40% как обычный Представитель |
| 2 | Два Амбасадора с одинаковым префиксом | Недопустимо — префикс уникален в системе |
| 3 | Представитель работает в регионе другого Амбасадора | Автоматически попадает в структуру местного Амбасадора (§8.3) |
| 4 | Массовая регистрация МСП под одним промокодом за короткий период | Не блокируется автоматически на MVP, логируется для ручной проверки (антифрод-бэклог) |
| 5 | Клиент передал `promo_code` в запросе транзакции, отличный от регистрационного кода МСП | Игнорируется; распределение по серверным данным МСП |
| 6 | Амбасадор деактивирован / блокируется | Промокод переносится на Основателя / Компанию; Представители остаются в системе (§10) |
| 7 | Пользователь зарегистрировался без промокода, потом хочет стать Представителем | Вводит промокод при подписке → получает статус и личный промокод |
| 8 | Пользователь хочет сменить промокод после активации подписки | Смена 1/30 дней; префикс сохраняется; начисления не пересчитываются |
| 9 | Амбасадор хочет назначить второго Амбасадора в том же регионе | Только с разрешения Основателя; территория делится (районы, кварталы) |
| 10 | Амбасадор хочет стать Основателем | Выполнить условия: передача дохода + 2 кандидата (§12) |
| 11 | Два Амбасадора в одном регионе конфликтуют | Определяет Основатель при назначении (районы, кварталы) |
| 12 | Возврат транзакции — возврат 40% Представителю | **Auto-deduction:** 40% вычитаются из следующей выплаты Представителю. Логируется в `return_amount` |
| 13 | Несколько точек одного МСП | **Разрешено.** Точка регистрируется по номеру телефона как клиент, потом создаёт любое число МСП или торговых точек одного МСП. Все точки под одним промокодом, 40% идут одному Представителю |
| 14 | Миграция Представителя между Амбасадорами | **Возможна по заявлению** через тикет-систему. Амбасадор вместе с Основателем решают кому передать структуру. Основатель перекидывает промокод Представителя на выбранный профиль |
| 15 | Деактивация Представителя (не Амбасадора) | **Руль — подписка.** Если подписка неактивна → все доходы Представителя идут Компании, доходы и структура Амбасадора сохраняются. Если неактивен Представитель → подписка не продлевается, все доходы Представителя уходят на Компанию. Амбасадор вместе с Основателем решают кому передать структуру (см. §14) |
| 16 | Лимит Представителей у Амбасадора | **Без лимита** — Амбасадор может приглашать бесконечно |

## 14. Деактивация Представителя (подписка = руль)

### 14.1. Принцип

> **Подписка — руль деактивации.** Запретить продление подписки → отключение статуса «Партнёр».

### 14.2. Сценарии

| Сценарий | Что происходит |
|---|---|
| **Подписка неактивна** | Все доходы Представителя идут Компании. Доходы и структура Амбасадора сохраняются |
| **Неактивен Представитель** | Подписка не продлевается, все доходы Представителя уходят на Компанию |
| **Деактивация по нарушению** | Амбасадор вместе с Основателем решают кому передать структуру. Основатель перекидывает промокод Представителя на выбранный профиль |

### 14.3. Процесс

```
Амбасадор / Основатель → запрещает продление подписки → статус «Партнёр» отключается → 40% идут Компании
```

| Шаг | Действие | Результат |
|---|---|---|
| 1 | Амбасадор или Основатель запрещает продление подписки | Подписка не продлевается после окончания периода |
| 2 | Подписка истекает | Статус «Партнёр» отключается |
| 3 | Все доходы Представителя (40%) идут Компании | Амбасадор (20%) продолжает получать доход с ветки |
| 4 | Структура Представителя сохраняется | МСП продолжают работать |
| 5 | Основатель решает кому передать структуру | Промокод Представителя переносится на выбранный профиль |

## 13. Спец-ссылки (лучшие практики)

### 13.1. Формат

| Параметр | Описание |
|---|---|
| **Базовый URL** | `https://lovii.ru/reg/` или `https://lovii.ru/partner/` |
| **Промокод** | Добавляется как path или query parameter |
| **Примеры** | `https://lovii.ru/reg/EG5K2L` (с промокодом) или `https://lovii.ru/reg?promo=EG5K2L` |

### 13.2. Типы ссылок

| Тип | Формат | Когда используется |
|---|---|---|
| **С промокодом** | `https://lovii.ru/reg/EG5K2L` | Амбасадор / Представитель делится ссылкой для приглашения |
| **Без промокода** | `https://lovii.ru/reg` | Общая ссылка на регистрацию (без привязки к ветке) |
| **Спец-акция** | `https://lovii.ru/promo/LOVII3` | Ссылка на акцию с промокодом Амбасадора |

### 13.3. Где отображаются

| Место | Описание |
|---|---|
| **Профиль Представителя** | Ссылка в разделе «Пригласить» |
| **Профиль Амбасадора** | Ссылка + QR-код для печатных материалов |
| **Рассылка / соцсети** | Амбасадор копирует ссылку для публикации |
| **Приложение** | Кнопка «Поделиться» с deep link |

### 13.4. Механика

1. **Пользователь переходит по ссылке** → открывается форма регистрации с предзаполненным промокодом.
2. **Если промокод валиден** → система привязывает пользователя к ветке Амбасадора/Представителя.
3. **Если промокод невалиден** → ошибка; пользователь может зарегистрироваться без промокода.
4. **QR-код** → генерируется автоматически для ссылки с промокодом.
