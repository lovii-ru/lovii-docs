# DELIVERY.md — Ворота поставки документации LOVII

Назначение: описывает, как собирается, проверяется и поставляется набор документации репозитория `lovii_docs`. Это ворота поставки (delivery gate), а не описание продукта.

## Что такое «поставка»

Поставка документации равна публикации актуальных публичных документов из приватного `lovii_docs` в публичное зеркало `axiiom-ru/lovii`, откуда они отдаются через GitHub Pages. Триггер — пуш в ветку `main`.

## Как собрать и запустить

Документация — это Markdown, отдельной сборки исходников нет. «Сборка» равна публикации.

### Локальная проверка перед поставкой

```bash
bash scripts/sync-public.sh --dry-run
```

Показывает для каждого из четырёх файлов решение по версии и публикации, ничего не записывая и не публикуя.

### Ручная публикация (если не полагаешься на CI)

```bash
bash scripts/sync-public.sh                # публикация, уровень бампа автоматически
bash scripts/sync-public.sh --level minor  # принудительный уровень бампа (major|minor|patch)
bash scripts/sync-public.sh --no-commit    # не коммитить бамп в lovii_docs
bash scripts/sync-public.sh --push         # после коммита сделать git push
```

### Автоматическая публикация (основной путь)

Пуш в `main` запускает `.github/workflows/sync-public.yml`. Workflow выполняет `bash scripts/sync-public.sh --push`. Для работы нужен секрет репозитория `PAT` с правами `contents: read/write` к `bestdeejay-design/lovii_docs` и `axiiom-ru/lovii`.

### Просмотр опубликованного

- Сайт: https://axiiom-ru.github.io/lovii/
- Инструмент сравнения версий: `compare.html` (публикуется на GitHub Pages, читает теги и контент через GitHub API + jsDelivr).

## Как проверить (verify)

1. **Решения по версиям.** `--dry-run` должен показать для каждого канон-дока одно из: «версия выше опубликованной → публикуем как есть», «версии равны и тело изменилось → бамп», «без изменений → пропуск», «версия ниже → защита (пропуск)».
2. **Состав публикации.** В публичное зеркало попадают ровно 4 файла: три канон-дока и `README.md`. Проверь через `gh api` содержимое `axiiom-ru/lovii`, что других файлов нет.
3. **Отсутствие утечки.** Убедись, что никакое содержимое `workspace/` (финмодели, договоры, ассеты, архив) не попало в публичный репо.
4. **Рендеринг.** GitHub Pages генерирует HTML из `.md`. Открой опубликованные страницы и проверь, что таблицы и формулы отображаются.
5. **Снепшот.** При новой версии проверь наличие или обновление `versions/vX.Y.Z/`.
6. **CI.** Workflow `Sync public docs` зелёный; при авто-бампе коммит появился в `lovii_docs` (забери через `git pull`).

## Что ВХОДИТ в поставку (IN scope)

Публикуемые и сопровождаемые артефакты:

- Три канон-дока: `docs/Публичная_оферта.md`, `docs/Оферта_присоединения.md`, `docs/money_flow_public.md`.
- `README.md` — лендинг и главная страница (публикуется без строки версии).
- `compare.html` — инструмент сравнения версий (публикуется на GitHub Pages).
- Инфраструктура публикации: `scripts/sync-public.sh`, `.github/workflows/sync-public.yml`.
- `versions/` — снепшоты опубликованных версий (v0.9.0, v1.0.0, v2.0.3 и новые).
- `REGISTRY.md` — реестр документов (ведётся в приватном репо).
- `.omo/doc-manifest.json` — машиночитаемый манифест (ведётся в приватном репо).
- Community-файлы: `LICENSE`, `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `SECURITY.md`, `SUPPORT.md`.

## Что НЕ входит в поставку (NOT in scope)

Не публикуется и не является частью публичной поставки:

- Вся папка `workspace/` целиком: рабочая документация (`workspace/docs/*`), финмодели (`workspace/financial/*`), комплект Т-Банка (`workspace/tbank/*`), презентации SOBA (`workspace/soba/*`), контракты (`workspace/contracts/*`), ассеты (`workspace/assets/*`), архив (`workspace/archive/*`).
- Первоисточник комиссий `workspace/tbank/05_Мультирасчеты_без_акта_ООО_АКСИОМА.md` — только чтение, не публикуется.
- Вспомогательные скрипты `scripts/gen_registry.py`, `scripts/debug-api.ts` — не часть публичной поставки.
- Любые секреты, токены (включая `PAT`), персональные данные.
- Черновики и исторические дубликаты из `workspace/archive/`.

## Критерии ворот поставки (gate checklist)

Поставка разрешена, если:

- [ ] `--dry-run` не показывает неожиданных бампов и не помечает файлы как «версия ниже».
- [ ] В публичное зеркало уходят ровно 4 файла, без утечки `workspace/`.
- [ ] Строки версий в трёх канон-доках корректны и не понижены.
- [ ] Нет секретов в публикуемом наборе и в коммите.
- [ ] CI `Sync public docs` прошёл успешно.
- [ ] При необходимости создан снепшот в `versions/` и обновлён `REGISTRY.md` с манифестом.
