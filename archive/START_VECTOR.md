## 0. Резюме одним абзацем

У LOVII есть работающая клиентская витрина (app.lovii.ru), API, продуманная бизнес-модель
и — теперь — банковский инструмент, который **заменяет собой половину запланированной
инфраструктуры**. Мультирасчеты Т-Банка делают ненужными на старте: БПА (ИТпэй),
холдинговую юрструктуру из 3+ юрлиц, собственный процессинг выплат. Критический путь
до первого рубля выручки — **включить оплату в приложении со сплитом через Мультирасчеты
и подключить 10–20 реальных точек одной локации**. Всё остальное (баллы, представители,
амбассадоры, франшиза, холдинг) — последовательно за этим, каждый этап через KPI-ворота.

## 1. Честная фиксация текущей стадии

### 1.1. Что реально есть (актив)

| Актив | Состояние |
|---|---|
| Клиентская PWA `app.lovii.ru` (Vue 3 + Pinia) | Работает: витрина, каталог, корзина, авторизация OTP. Production-grade дизайн-система |
| API `api.lovii.ru/api/v1` | Работает (гео, каталоги, авторизация) |
| Документация Т-Банк Мультирасчеты | Получена: регистрация ТСП через API, оплата со сплитом, выплаты, номинальный счёт |
| Номинальный счёт | В процессе оформления |
| Документальный корпус | PARAMS.md (канон), финконтур, юрструктура, конкурентный анализ, PRD демо |
| Презентации | invest.lovii.ru (инвесторы), lovii.ru (whitepaper) |
| Демо 4 ролей | lovii.mobiap.com (клиент/партнёр/представитель/амбассадор) |
| Основатель | 20+ лет ИТ, CTO-опыт, личные инвестиции >35 млн ₽ |

### 1.2. Что отсутствует (разрыв между документами и реальностью)

| Разрыв | Следствие |
|---|---|
| **Нет оплаты в приложении** — checkout упирается в авторизацию, платёжного шага нет | Нет транзакций → нет комиссии → нет выручки. **Это разрыв №1** |
| **Нет UI лояльности** в живом приложении — ни баллов, ни кэшбэка | Ядро позиционирования («оператор лояльности») пока не существует в продукте |
| **Нет кабинета партнёра** — ТСП не может управлять каталогом и заказами | Точки нельзя подключать самообслуживанием |
| **Каталог заполнен цифровыми товарами** (Литрес, Kaspersky, софт) — тестовый сид | Продукт ещё ни дня не работал с целевой аудиторией (пекарни, цветы, кофейни) |
| **Нет ни одной платящей точки** | Вся экономика — модель на бумаге |

### 1.3. Найденные противоречия в документах (проморгали)

1. **Бюджет MVP: 60 млн ₽ (план «окт 2025 — март 2026») против ~200–264 тыс. ₽
   (6-недельная смета)** — расхождение в 250 раз. Требуется решение владельца, какая
   реальность актуальна. Вектор ниже построен от экономной реальности.
2. **Финконтур описан через БПА (ИТпэй)**, а Мультирасчеты этот слой заменяют —
   FINANCIAL_MODEL.md и Юридическая_структура.docx не обновлены под новый инструмент.
3. **Комиссия 6% в старых MD против канонических 10%** — **ИСПРАВЛЕНО** (2026-08-30): PROJECT_CONTEXT, FACT_MAP, COMPETITOR синхронизированы с PARAMS v1.6.
4. **Лестница ролей**: **УНИФИЦИРОВАНО** (2026-08-30): `Представитель → Мэр → Губернатор → Амбасадор → Основатель` (PARAMS.md §1.4, PROJECT_CONTEXT.md).
5. **Экономика представителя на старте нежизнеспособна как мотиватор**: 40% с точки
   = ~4 650 ₽/мес. Представитель с 5 точками зарабатывает ~23 тыс. ₽/мес — меньше
   курьера. Лестница статусов заработает только при 20+ точках на представителя.
   На старте подключать точки должен сам основатель/команда, а не сеть.
6. **Комиссия 25% с кэшбэка** — юридически логичная (антифрод), но коммерчески
   токсичная формулировка для питча ТСП («вы платите нам за то, что дарите скидку
   своим клиентам»). На старте кэшбэк-конструктор лучше не продавать вообще —
   сначала транзакции, потом лояльность.
7. **Юрструктура (АО «Точка» + АО «Платформа» + ПК «Академия» + 3 ООО)** спроектирована
   для стадии федеральной сети, а не для пилота с 20 точками. Каждое юрлицо — это
   бухгалтерия, отчётность, издержки. Мультирасчеты позволяют стартовать **одним
   юрлицом-оператором** с договором с Т-Банком.

## 2. Ключевой стратегический тезис

**Мультирасчеты — это не «ещё одна интеграция», это смена архитектуры запуска.**

Что берёт на себя Т-Банк:

| Функция | Было в плане | Стало с Мультирасчетами |
|---|---|---|
| Приём платежа | Эквайринг + БПА (ИТпэй) | API оплаты Т-Банка |
| Сплит 90/6,5/3,5 | Спецсчёт БПА, ручная маршрутизация | Автоматический сплит на стороне банка |
| Выплаты точкам | Через БПА по 161-ФЗ | API выплат с номинального счёта |
| Онбординг ТСП | Ручная верификация | API регистрации партнёров |
| Комплаенс 161-ФЗ | Ответственность LOVII+БПА | Внутри периметра банка |
| Хранение денег | Риск квалификации как оператора по приёму платежей | Деньги не касаются LOVII — номинальный счёт |

Следствия:
- **Юридически**: не нужен договор с БПА, не нужна структура из 3 юрлиц на старте.
- **Финансово**: себестоимость запуска падает на порядок; смета ~250–500 тыс. ₽ реалистична.
- **Продуктово**: критический путь = один платёжный флоу в уже существующем приложении.

## 3. Вектор: четыре фазы с KPI-воротами

Принцип: **ни одна следующая фаза не начинается, пока не пройдены ворота предыдущей.**
Целевые значения ворот взяты из PARAMS.md §7 (утверждённые показатели).

### Фаза 0 — «Контур» (сейчас, 2–4 недели)

Цель: юридическая и платёжная готовность.

| # | Действие | Результат |
|---|---|---|
| 0.1 | Завершить оформление номинального счёта и договора Мультирасчеты | Доступ к боевому API |
| 0.2 | Зафиксировать юрлицо-оператора (одно) для пилота | Минимальная структура; холдинг — отложен до Фазы 3 |
| 0.3 | Обновить FINANCIAL_MODEL.md и юрструктуру под Мультирасчеты (убрать БПА из базовой схемы) | Единый непротиворечивый контур |
| 0.4 | Синхронизировать PARAMS: комиссия 10%, 2 990 ₽, лестница ролей — поправить старые MD | Канон без дрейфа |
| 0.5 | Песочница Мультирасчетов: тестовая регистрация ТСП, тестовый платёж со сплитом, тестовая выплата | Доказанный сквозной денежный поток |

**Ворота Фазы 0:** тестовый платёж 100 ₽ прошёл сплит 90/6,5/3,5 и выплату — в песочнице, потом на бою.

### Фаза 1 — «Первый рубль» (1–2 месяца)

Цель: реальные транзакции реальных точек одной локации.

| # | Действие | Результат |
|---|---|---|
| 1.1 | Платёжный шаг в checkout PWA (оплата картой/СБП через Мультирасчеты) | Клиент может заплатить |
| 1.2 | Онбординг ТСП через API регистрации (цель — «5 минут по QR» из PDF) | Точка подключается без ручной работы |
| 1.3 | Минимальный кабинет партнёра: каталог (форма/CSV), заказы (push/SMS), выплаты | Точка обслуживает себя сама |
| 1.4 | Подключить 10–20 реальных точек пилотной локации (Василеостровский рынок / выбранный район СПб) — лично, без представителей | Живой каталог вместо тестового сида |
| 1.5 | Тарифы старта: СТАРТ 0%/0 ₽ (до 30 000 ₽/мес оборота) и БАЗОВЫЙ 10% без абонентки. PRO и кэшбэк — не продаём | Простой питч: «платите только когда продаёте» |
| 1.6 | Убрать/заменить цифровой тестовый сид в проде | Витрина = локальный бизнес |

**Ворота Фазы 1:** ≥ 10 активных точек, ≥ 100 заказов/мес суммарно, 100% выплат в срок,
время оформления заказа < 3 мин (PARAMS §7).

### Фаза 2 — «Лояльность и удержание» (2–4 месяца после Фазы 1)

Цель: включить ядро позиционирования — баллы, когда есть кому их начислять.

| # | Действие | Результат |
|---|---|---|
| 2.1 | Баллы клиента на номинальном счёте (1 балл = 1 ₽, не сгорают) + UI баланса/истории в PWA | Лояльность видима клиенту |
| 2.2 | Конструктор кэшбэка для точки (упрощённый: % на всё / % на категорию / акция выходного дня) | Точка управляет лояльностью |
| 2.3 | Комиссия 25% с кэшбэка — включается здесь, с прозрачным калькулятором для точки | Монетизация лояльности без сюрпризов |
| 2.4 | Вывод баллов через СБП (от 3 000 ₽ для самозанятых, ИП/ООО — по push-графику) | Обещание «100% ликвидности» выполнено |
| 2.5 | Тариф PRO (2 990 ₽/мес, комиссия 4–7%) — продаём лидерам оборота | Вторая линия выручки |
| 2.6 | Flash Deals / акции на главной (паттерн Glovo из конкурентного анализа) | Инструмент трафика для точек |

**Ворота Фазы 2:** 30-дневный Retention > 40%, ≥ 30 точек, GMV локации растёт месяц к месяцу,
доля точек с включённым кэшбэком ≥ 30%.

### Фаза 3 — «Сеть распространения» (после ворот Фазы 2)

Цель: масштабирование людьми — только теперь, когда экономика точки доказана.

| # | Действие | Результат |
|---|---|---|
| 3.1 | Роль «Представитель» (40% с точек) + кабинет: мои точки, доход, выплаты через Мультирасчеты | Первые 3–5 представителей на соседние районы/города |
| 3.2 | Лестница статусов (Представитель→Мэр→Губернатор) — включается как геймификация поверх работающей экономики | Мотивация ростом, не обещаниями |
| 3.3 | Роль «Амбассадор» (20%) — когда представителей > 10 | Второй уровень сети |
| 3.4 | Юрструктура холдинга (АО «Точка»/«Платформа»/ПК «Академия») — проектируется под инвестраунд | Структура следует за масштабом, не наоборот |
| 3.5 | Федеральные партнёрства (Билайн HR, Магнит/Лента DBS, Чибис) — переговоры с позиции работающих цифр | Партнёрства усиливают, а не заменяют продукт |

**Ворота Фазы 3 (= порог масштабирования из PARAMS §7):** GMV > 5 млн ₽/мес,
поставщиков > 50, Retention > 40%.

### Фаза 4 — «Франшиза / федеральная сеть» (горизонт 2027+)

City Franchise, роялти = пул LOVII минус 60% (20% Амбассадор, 40% Представитель), зрелые локации (>200 точек, EBITDA > 0, платные тарифы > 30%),
целевая капитализация 3 млрд ₽ (EBITDA ×10–12). Детализация — после ворот Фазы 3.

## 4. Чего НЕ делать (анти-скоуп на 6 месяцев)

1. **Не строить холдинг из 3+ юрлиц** до инвестраунда/масштабирования.
2. **Не продавать кэшбэк-конструктор** до работающих транзакций (Фаза 2, не раньше).
3. **Не рекрутировать представителей/амбассадоров** до доказанной экономики точки —
   первые точки подключает команда.
4. **Не вести переговоры о DBS с Магнитом/Лентой** как приоритет — федеральные каталоги
   размывают позиционирование «локальный бизнес» и не дают комиссии на старте.
5. **Не переписывать приложение** (React Native, микросервисы, Kafka из чата 18) —
   Vue 3 PWA достаточна до порога масштабирования.
6. **Не делать нативные приложения** — PWA до Фазы 3 минимум.
7. **Не расширять географию** за пределы одной локации до ворот Фазы 1.

## 5. Риски и контрмеры

| Риск | Вероятность | Контрмера |
|---|---|---|
| Затяжка оформления номсчёта/договора Т-Банк | Средняя | Параллельно вести CloudPayments/Точку как план Б (список из юрструктуры §6.3) |
| Точки не хотят онбордиться (холодный старт) | Высокая | Тариф СТАРТ 0%/0 ₽; личное подключение основателем; выбрать локацию с управляющим рынка как союзником |
| Клиентов нет — точки уходят | Высокая | Запуск с точками, у которых УЖЕ есть поток (рынок), LOVII оцифровывает существующий спрос, а не создаёт новый |
| Комиссия 10% воспринимается как дорого | Средняя | Питч через сравнение: агрегаторы берут 15–35% (COMPETITOR_ANALYSIS §4); у нас 0% до 30 тыс. оборота |
| Ресурс основателя разрывается (проект + найм) | Средняя | Вектор построен на минимальной смете и внешней инфраструктуре банка; критический путь — одна интеграция |
| Регуляторный (115-ФЗ, блокировки) | Низкая | Деньги в периметре Т-Банка; LOVII не касается средств |

## 6. Ближайшие 5 шагов (конкретика недели)

1. **Дочитать и замапить API Мультирасчетов** (4 PDF в `references/tbank/`) на текущий
   бэкенд `api.lovii.ru`: где встаёт регистрация ТСП, где платёж, где выплаты.
2. **Дожать номинальный счёт** — это блокер всего вектора.
3. **Решить противоречие бюджета** (60 млн против 264 тыс.) — вектор предполагает экономный путь.
4. **Спроектировать платёжный флоу checkout** в PWA (экран оплаты → Мультирасчеты → статус заказа).
5. **Выбрать и зафиксировать пилотную локацию** и список первых 20 точек-кандидатов.
