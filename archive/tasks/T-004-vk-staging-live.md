# T-004 — Staging: env, коннективити-чеки и live-включение VK-канала

> Статус: Закрыта — живой тест пройден владельцем 2026-09-09 (привязка, доставка кода, произвольная доставка — всё подтверждено; приёмка Super Z — при возвращении парного режима)

> Исполнитель: zcode (env/SSH/чеки) + владелец (кнопки VK UI, шаги 4–6) · Постановил: Super Z · Приёмка: Super Z — §3.1
> Репо: сервер staging (SSH), без коммитов · Дата постановки: 2026-09-09

## Цель

Канал VK реально доставляет коды на staging: от подтверждения Callback до
сквозного входа по коду из ВКонтакте.

## Шаги (порядок соблюдать строго)

1. **Проверить деплой T-002** на staging (CI 🟢, контейнер обновлён).
2. **Env через SSH** в `.env` контейнера core-staging (секреты владелец передаёт
   zcode напрямую из локального дока `OTP codes VK .md`; в чаты/репо НЕ пересылать):
   `VK_COMMUNITY_TOKEN` (токен сообщества), `VK_GROUP_ID`, `VK_CALLBACK_CONFIRMATION`
   (строка подтверждения из дока), `VK_CALLBACK_SECRET` (сгенерировать, например
   `openssl rand -hex 32`, и сообщить владельцу для вставки в настройки VK),
   `VK_API_VERSION=5.199`, `VK_SCREEN_NAME=loviiru`. После — перезапуск php-fpm/queue.
3. **Коннективити-чеки:**
   - outbound из контейнера: `curl -sS "https://api.vk.com/method/users.get?v=5.199"`
     → в ответе `"response"`. Если соединение не проходит — **СТОП**, вернуть задачу
     с выводом curl (сетевой класс риска F-030; прокси самовольно не ставить);
   - inbound (снаружи): `curl -sS -X POST https://api-staging.lovii.ru/api/v1/vk/callback
     -H "Content-Type: application/json" -d '{"type":"confirmation","group_id":<ID>}'`
     → в ответе сырая строка подтверждения (не JSON, не "ok").
4. **Владелец, VK UI** (запускается ПОСЛЕ шага 3): Управление сообществом → Работа
   с API → Callback API → URL = `https://api-staging.lovii.ru/api/v1/vk/callback`
   (прежний `app-staging.lovii.ru/vk/callback` заменить), Secret = тот же
   `VK_CALLBACK_SECRET` → «Подтвердить» (VK пришлёт confirmation — сервер ответит
   строкой, VK покажет успех). Затем: Управление → Сообщения → включить
   «Сообщения сообщества».
5. **Live-тест (сквозной):** в приложении staging выбрать «ВКонтакте» → кнопка
   «Открыть ВКонтакте» → написать сообществу любое сообщение → код приходит
   сообщением от сообщества (первая строка — код) → ввести код → вход выполнен.
6. **Негативные тесты:** (а) отозвать разрешение сообществу в настройках VK →
   повторный send-code → `vk_link_required` (VK ретранслирует 901); (б) написать
   сообществу с ref-ссылкой, у которой истёк `binding_token` → в чат приходит
   инструкция, ошибки 5xx нет.
7. **Фиксация:** результат live-тестов — в отчёт исполнителя; session-док
   (lovii-core `docs/sessions/021-vk-staging-live.md`) + lovii-docs/status.md;
   канонический след — Super Z зафиксирует в FINDINGS/STATUS при приёмке.

## Что НЕ делать (стоп-лист)

- Секреты — только в `.env` стейджинга и локальном доке владельца; НЕ в чаты,
  НЕ в репо, НЕ в канон.
- НЕ включать канал в prod (прод — отдельное решение владельца после приёмки).
- При недоступности api.vk.com / отказе inbound — НЕ ставить прокси и НЕ менять
  nginx: вернуть задачу с диагностикой (вывод curl, логи nginx).

## Критерии приёмки

- Оба curl-чека шага 3 зелёные (выводы в отчёте).
- Live-сквозной вход по коду из VK выполнен; негативные тесты (6а, 6б) —
  ожидаемое поведение.
- VK_CALLBACK_SECRET совпадает в .env и настройках VK; confirmation подтверждён.
