## Факт (воспроизведено живым проходом на staging)

1. Новый профиль, карточка товара (`/stores/1/product/1`): первое «+» добавляет
   (0→1), последующие клики по «+» (координаты подтверждены по DOM,
   `elementFromPoint` = иконка плюса) **не меняют счётчик**.
2. Профиль владельца, корзина: после серии быстрых кликов «+» (1→60) кнопка
   «−» перестаёт срабатывать (клики в точный центр кнопки по DOM-геометрии,
   состояние `disabled=false`), после `reload` счётчик остаётся 60.
3. Сервер при этом в актуальном состоянии: расхождение — клиентский store
   (bumpProduct: оптимистичный сдвиг + debounce 350 мс + абсолютный POST
   `api/v1/cart/items`). Гипотезы: зависший таймер/промис sync, гонка
   ответов, потеря фокуса/событий после SW-обновления.

## Что должно получиться

1. Любая серия «+»/«−» (быстрая и медленная) корректно меняет счётчик и
   синхронизируется с ядром; после `reload` счётчик = серверному.
2. Нагрузочный unit/фейк-тест: 60 быстрых кликов → конечное состояние = 60
   и один-два синк-запроса, без «залипания».
3. Проверено на реальном касании (телефон + десктоп), не только в автомате.

## Критерий приёмки

- Сценарий прохода (добавить 60, уменьшить до 0) выполняется только кликами
  по UI без перезагрузок; гейты app зелёные.
- Отдельно сверить сценарий «товар закончился на сервере, пока пользователь
  кликает» (unavailable_reason) — счётчик не должен молчать.
