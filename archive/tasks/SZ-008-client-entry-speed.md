## 1. P-1 (P1) Magic link / безкодовый вход

- Клиент запрашивает вход → бот в Telegram присылает **кнопку «Это я»**
  (глубокая ссылка) вместо ручного ввода кода. Тап — сессия подтверждена,
  приложение входит само.
- Заготовка уже есть: бот шлёт кнопку подтверждения сессии — развить до полного
  magic link (токен одноразовый, короткий TTL, привязка к устройству/сессии).
- Проверить сценарии: приложение активно / свёрнуто / PWA не открыта; повторная
  отправка; истёкшая ссылка (fallback на код).
- Не ломать существующий OTP-ввод (код остаётся fallback-каналом).

## 2. P-3 (P2) Нижнее модальное меню «открывается очень медленно» (жалоба владельца)

## 6. Отчёт исполнителя (Super Z, 2026-09-10)

### 6.1 P-1 Magic link — core (`3972878`, CI 🟢 run 97)

- `config/otp.php` → `frontend_url` (env `FRONTEND_URL`, дефолт
  `https://app-staging.lovii.ru`; в .env.example добавлен). **Прод:** при
  выкатке задать `FRONTEND_URL=https://app.lovii.ru` — иначе ссылка ведёт на
  staging.
- Новый `Domain/Auth/Services/MagicLoginLink` — сборка
  `{frontend_url}/auth/by-binding?token=<binding_token>`.
- `TelegramBotApiClient::sendOtpCodeMessage(..., ?string $loginUrl)` — при
  переданном URL добавляет inline-кнопку **«Войти в приложение»** (Bot API
  url-button) НАД существующей «Скопировать код». Кнопка добавляется в ОБА
  пути доставки кода: прямая отправка (`TelegramSender::send`) и
  `/start <binding_token>` (`TelegramOtpBotHandler::bindAndDeliverCode`).
- `OtpSenderContract::send(?string $bindingToken = null)` — все 6 сендеров
  принимают токен; каналы без чата его игнорируют. `SendOtpAction` теперь
  выдаёт `binding_token` каждой доставляемой сессии (раньше — только
  запаркованным).
- **Семантика `POST /auth/confirm-by-binding` расширена** (это ключевой
  дизайнерский шаг): обмен токена принимается и для **pending**-сессии —
  обладание binding-токеном внутри собственного чата пользователя = тот же
  уровень доверия, что обладание кодом (токен доставляется только туда же,
  куда код; одноразовость и TTL сохранены; вход по коду, как и раньше, гасит
  токен — `ConfirmOtpAction`). MAX-флоу не изменился (frontend обменивает
  только после подтверждения webhook'ом — подтверждённая ветка проверяется
  первой).
- Тесты `TelegramOtpAuthTest`: URL-кнопка в обоих путях доставки (с тем же
  токеном), обмен pending-сессии (200 + single-use 422), reject истёкшей
  ссылки.
