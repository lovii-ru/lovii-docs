## 1. Контекст и слова владельца

Функциональная фаза завершена (карта, адреса, заказы, оплата, VK-вход) —
экраны тестировались на работоспособность. Владелец: визуал профиля, страницы
заказов и оформления заказа «корявенько»: «всё слиплось», «без учёта отступов»,
«элементы не переиспользуются для одинакового содержания»; пример — строка
адреса на чекауте «не тапается и не выделена… надо догадаться нажать на
карандашик». Направление: близко к дизайн-системе, современно, «ближе к
классике, но не черезчур ярко».

## 2. Направление (продуктовое решение Super Z, владелец сохраняет вето)

- **Классика без яркости**: новая палитра НЕ вводится — только существующие
  токены (DESIGN.md §4); акцент — brand на одном CTA и статусах, всё остальное —
  спокойные surface (правило 60-30-10).
- **Карточная система**: страница = фон, действие = карточка. Радиус 16,
  внутренний отступ 16, разделитель 1px `--border-normal-subtle`, вертикальный
  ритм 16px между карточками (внутри карточек: 8/12/16).
- **Аффорданс**: любая строка-цель — вся тапается (мин. высота 44px), справа
  chevron, active-состояние (лёгкое затемнение surface). Никаких «догадайся про
  карандашик»: иконка-редактирование допустима только как дополнение к
  тапабельной строке.
- **Иерархия**: один акцентный блок на экран (сумма + CTA); заголовки секций —
  единый паттерн (тот, что уже в CreateOrderDeliveryType: h5 + разделитель).
- **Переиспользование**: одинаковое содержание = один компонент (бейджи —
  AppBadge; сводка заказа — один OrderSummery; строка адреса — один
  AddressRow-паттерн).

## 4. Что НЕ делать (стоп-лист всех фаз)

- НЕ менять флоу, API, stores, роутинг — только шаблоны/стили/порядок компонентов.
- НЕ трогать `data-testid` (e2e: `checkout-address-edit`, `place-order`, `order-comment`, `order-card` и пр.).
- НЕ вводить новые цвета/шрифты/компоненты вне DESIGN.md; новые UI-компоненты — только если дубликация реальна (AddressRow, OrderSummery — да).
- НЕ переписывать анти-FOUC логику (сессия 018), поллинги, error-handler.
- Dark/light проверять оба (токены; скриншоты обоих режимов в отчёт).
