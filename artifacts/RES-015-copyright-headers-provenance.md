## Резюме (TL;DR)

1. **Как делают профессионалы.** Единый машиночитаемый стандарт — SPDX/REUSE
   (`SPDX-FileCopyrightText` + `SPDX-License-Identifier` в шапке каждого файла).
   Крупные компании (Google, Amazon, Meta, Microsoft) используют одну строку
   `Copyright <год> <Компания>` в шапке; **сам хедер никого не защищает —
   защищает падающий CI-гейт**, который валит сборку при пропаже шапки
   (`addlicense -check`, `hawkeye check`, `reuse lint`, `license-eye`).
2. **Против «снесли одним прогоном».** Три линии: (а) гейт в CI + pre-commit —
   любая правка, снёсшая шапки, не мержится; (б) «луковица» дублей: шапка +
   SPDX-строка + корневой LICENSE/NOTICE + метаданные пакета — стрип одного
   слоя не убивает остальные; (в) право: **по ст. 1300 ГК РФ удаление информации
   об авторском праве — самостоятельное нарушение** (компенсация 1 000–100 000 ₽,
   а использование «зачищенного» экземпляра — до 11 млн ₽ / 220% по ст. 1301).
3. **Точный маркер принадлежности.** Каноническое имя задачи — **traitor
   tracing** (фингерпринтинг выданной копии). Работает для маленькой команды:
   уникальный ID в шапке каждого файла + приватный реестр («код → файл, репо,
   дата») + CI-гейт сверки. Ст. 1300 ГК РФ прямо включает в «информацию об
   авторском праве» «любые цифры и коды» — ©-код попадает под защиту закона.
   Опционально: honeytoken (canarytokens) как активный tripwire для выдаваемых
   наружу копий.
4. **Чего не делать:** не изобретать «шифр» (открытый код не взламывают — ключ
   держат отдельно, в реестре); не надеяться на `git blame`/CODEOWNERS (умирают
   при копировании файла); не ставить маркеры в невидимые символы как единственную
   защиту (умирают при форматировании); не путать со SLSA/in-toto (это
   целостность сборки, не авторство).

## 1. Как делают крупные компании и опенсорс-проекты

### 1.1 SPDX / REUSE — машиночитаемый эталон [S1, S2]

Единственный зрелый стандарт атрибуции **на уровне файла**, парсится инструментом
`reuse lint`, переживает копирование файла (в отличие от git-истории).

```text
# SPDX-FileCopyrightText: 2026 ООО «Аксиома»
# SPDX-License-Identifier: LicenseRef-Proprietary
```

- Для закрытого кода — `LicenseRef-Proprietary` (проприетарная лицензия,
  свой ID в SPDX-реестре).
- Бинарники/картинки без комментариев — sidecar-файлы `photo.jpg.license`.
- Bulk-разметка без правки файлов — `REUSE.toml` (но: она **не переживает
  копирование одного файла** — только инлайн-шапка).
- Проверка: `reuse lint` (exit ≠ 0 при пропусках), простановка: `reuse annotate`.

### 1.2 Практика гигантов [S3]

| Компания | Реальная шапка (verbatim из кода) |
|---|---|
| Google | `// Copyright 2024 Google LLC.` |
| Amazon | `// Copyright Amazon.com, Inc. or its affiliates. All Rights Reserved.` |
| Meta | `// Copyright (c) Meta Platforms, Inc. and affiliates.` |
| Microsoft | `// Copyright (c) Microsoft Corporation. Licensed under the MIT License.` |
| Linux kernel | `// SPDX-License-Identifier: GPL-2.0-only` в первой строке + `Copyright (C) 1991 Linus Torvalds` |
| Apache | шапка-лицензия в файле + копирайты централизованно в `NOTICE` |
| GNU/FSF | `Copyright (C) год правообладатель` + «This file is part of …» |

Общие черты: одна строка владельца, год не обновляют массово, наличие шапки
**проверяется автоматически**, а не надеждой.

### 1.3 Русская практика в доках UI [S7]

Канон «Лови» уже имеет юр-блок: `© «Лови», 2026` + Оферта/Приватность/Реквизиты
(`lovii-design/docs/11-brand-voice.md` §6). Ресёрч подтверждает: для файлов-исходников
форма `© ООО «Аксиома», 2026` — валидный знак охраны по ст. 1271 ГК РФ
(буква C в окружности + наименование + год первого опубликования).

## 2. Защита от массового удаления

### 2.1 Правовая линия (первичка) [S4, S5, S6]

- **Ст. 1300 ГК РФ** — удаление/изменение информации об авторском праве без
  разрешения = самостоятельное нарушение; компенсация **1 000–100 000 ₽**
  (п. 3, ред. ФЗ №214-ФЗ от 07.07.2025). Использование экземпляров, из которых
  стёрта информация, — второй состав (пп. 2 п. 2).
- **Ст. 1301 ГК РФ п. 2** — при сопряжении с удалением информации повышенная
  шкала: **11 000–11 000 000 ₽ или 220%** стоимости.
- **Ст. 1257 ГК РФ абз. 2** — презумпция авторства: кто указан в ©, тот и автор,
  пока не доказано иное (бремя — на нарушителе).
- **Ст. 7.12 КоАП** — при цели извлечения дохода (юрлицо 30–40 тыс ₽ +
  конфискация); **ст. 146 УК** — крупный размер (500 тыс ₽+).
- **Определение ст. 1300 включает «любые цифры и коды»** — ©-код прямо
  квалифицируется как защищаемая информация об авторском праве.
- В США — 17 U.S.C. §1202 (CMI): удаление само по себе нарушение, $2 500–25 000
  (нужен умысел). Лицензии Apache §4(c)/MIT/MPL §3.4/GPL §§4-5 — условие
  «сохранять уведомления», его снос = потеря лицензии.
- **Важно:** против *собственного* будущего стрип-скрипта работает не закон, а
  внутреннее правило: договор/политика репо + CI-гейт.

### 2.2 Техническая линия — «падающие гейты» [S8]

Ни одна крупная компания не надеется, что хедер уцелеет сама. Де-факто стандарт:

| Инструмент | Как валит | Кто использует (живые CI) |
|---|---|---|
| `google/addlicense -check` | exit ≠ 0 при пропуске | docker/compose, vitess, k8s-sigs |
| `fast/hawkeye` (check/format) | exit ≠ 0 | apache/datafusion, apple/container |
| `apache/skywalking-eyes` | error при missing header | GitHub Action `header@main` |
| FSFE `reuse lint` | non-compliant | GNOME/glib, nixpkgs, authelia |
| `mycila license:check` (Maven) | валит сборку | Java-проекты |

Рецепт для LOVII (минимум):
1. CI-джоба: `grep -rL '© ООО «Аксиома»'` по tracked-файлам → список пропусков → `exit 1`.
2. Прескомуот-хук той же проверки (ловит локально, CI — на пуше).
3. CODEOWNERS: любой PR, трогающий >N шапок или реестр кодов, требует аппрува владельца.

### 2.3 «Луковица» дублей [S8]

Один стрип-скрипт сносит слой шапок, но не все слои:

1. видимая шапка в файле (человек);
2. SPDX-строка рядом (машина/сканеры);
3. корневые `LICENSE`/`NOTICE` + `REUSE.toml` (реестр);
4. метаданные пакетов (`package.json` author/license, composer.json).

Восстановление после любого стрипа — одним прогоном `addlicense`/`hawkeye format`.

**Отвергнуто:** xattr/EXIF (слетают при копировании, git их не хранит),
zero-width как единственная защита (умирает при форматировании), блокчейн-штампы
(не проверяют наличие шапок), FOSSA/Black Duck (SCA по зависимостям, не по нашим
шапкам).

## 3. Copyright-код: точный маркер принадлежности [S9]

Каноническое имя — **traitor tracing / fingerprinting**: установить, какая из
выданная копий утекла.

### 3.1 Что реально работает (вердикт)

- **Пассивный слой (основа):** уникальный на файл/батч код в шапке:
  `Код: LOVII-CR-26-XXXXXX` + приватный реестр `код → файл, репо, автор, дата`.
  Grep утёкшего файла → реестр → точная принадлежность. Академическая база:
  Chor–Fiat–Naor–Pinkas, «Tracing Traitors», CRYPTO'94 — при малом числе
  получателей тривиального уникального ID достаточно; тяжёлая математика
  (коды Тардоса) нужна только против сговора тысяч получателей.
- **Реальные кейсы canary trap:** Apple 2023 (Analyst941 — уникальные комбинации
  ложных дат релизов), Tesla 2008 (разные версии NDA-письма), forensic-точки
  лазерных принтеров (EFF; дело Reality Winner), Coded Anti-Piracy в кино
  (каждая кинокопия — свой паттерн).
- **Активный слой (опционально, для выдачи наружу):** honeytoken/canarytokens —
  уникальное DNS-имя в строке кода (в имя токена вмещается до ~125 байт данных —
  можно закодировать ID получателя); обращение = алерт. Работает, только если
  утёкший код исполняется; для статически лежащего на GitHub — молчит, остаётся
  пассивный слой.
- **Устойчивость:** текстовый маркер умирает при minify/AST-нормализации/ручной
  перепечатке — ловит ленивого сливщика (копия целиком, архив). Против
  мотивированного чистильщика: tripwire + юридический след (реестр выдачи + NDA),
  а не стойкость чернил. Семантические вотермарки (CodeMark 2023) — перспектива,
  не практика.

### 3.2 Машинная проверка и «агенты знают автора» [S10]

- `reuse lint`/кастомный grep как required check в CI — машина **гарантирует
  наличие** шапки в каждом файле.
- Реестр кодов в приватном репо + скрипт `--origin LOVII-CR-26-XXXXXX → строка
  реестра` — обратимость «код → автор» для агентов.
- CODEOWNERS/git blame/GPG — **не авторство** (blame умирает при копировании,
  Author подделывается конфигом); SBOM/SLSA/in-toto — уровень артефакта сборки,
  не файла.
- Маркировка AI-кода: готового стандарта нет (OSSF codetag — не существует,
  проверено); EU AI Act ст. 50 требует машинночитаемой маркировки сгенерированного
  контента (в силе с 02.08.2026) — «текст» под неё попадает, дух нормы можно
  использовать как ориентир для строки `Agent: …` в шапке.

## 4. Что берём в COPYRIGHT_STANDARD LOVII (рекомендации)

| # | Рекомендация | Основание |
|---|---|---|
| R1 | Шапка+подвал комментарием в каждом файле; форма `© ООО «Аксиома», 2026` + бренд LOVII | ст. 1271 ГК; практика гигантов (§1.2) |
| R2 | Вторая строка — `SPDX-FileCopyrightText` + `SPDX-License-Identifier: LicenseRef-Proprietary` | REUSE (§1.1) — машина парсит |
| R3 | Уникальный `Код: LOVII-CR-26-XXXXXX` в шапке+подвале важных файлов; приватный `COPYRIGHT_REGISTRY.md` — ключ | traitor tracing (§3.1); ст. 1300 «цифры и коды» |
| R4 | CI-гейт: grep по tracked-файлам → exit 1; pre-commit хук; CODEOWNERS на реестр | §2.2 — единственная реальная защита от стрипа |
| R5 | «Луковица»: шапка + SPDX + LICENSE/NOTICE + метаданные пакетов | §2.3 |
| R6 | Внешним контрагентам — отдельный батч-код + запись в реестре «код → получатель» | §3.1 canary trap |
| R7 | Не делать: невидимые символы как основа, блокчейн, self-rolled «шифр» внутри кода | §2.3, §3.1 |

## 6. Методология и ограничения

- 5 librarian-агентов, 1 волна, ~40+ запросов; веб-поиск частично отдавал 403 —
  обход: прямое чтение первичных страниц + `gh search code` + OpenAlex/Crossref.
- Не подтверждено первично (помечено, не использовать как факт): текст §1202 —
  пересказ (сверить по Cornell), персональные страницы VDR-вендоров (бот-защита),
  практика инвестбанков по маркировке кода вендоров (закрытая).
- Академические лиды (Tardos codes, CodeMark robustness, Shu 2015) — не
  изменяют рекомендации R1–R7; при необходимости — волна 2.
