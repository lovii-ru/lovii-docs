## 1. Как устроена навигация

- **Оболочка клиента** (`App.vue` + `MainLayout`): шапка (лого → Главная, пилюля адреса → гео-оверлей, иконка корзины) + нижний навбар из 4 табов (Главная / Поиск / Корзина с бейджем / Профиль) + баннеры офлайна и обновления. На широких экранах навбар — плавающая капсула (канон демо).
- **Кабинеты ролей** живут в отдельной оболочке `CabinetLayout` (без навбара): свой хедер + таб-бар вкладок + кнопка «Клиент» (демо-канон выхода в покупательский режим).
- **Гарды**: защищённые роуты (кошелёк, баллы, заказы, адреса, бизнес, оплата) отправляют гостя в Профиль — вход живёт там как оверлей. Кабинеты дополнительно проверяют флаг роли из GET /profile: «роли выдаёт платформа, UI не подбирает».
- **Оверлеи (не роуты)**: вход по телефону (4 шага), выбор адреса на карте, «Все настройки», Face ID/ПИН + экран блокировки AppLock, выбор адреса в чекауте.
- **Роли совмещаются** (BRD §2.4): один профиль — МСП + Представитель + Амбассадор; входы в кабинеты — из профиля, по флагам.

Итого: **35 именованных роутов + 2 роута-заглушки чатов + 6 оверлеев**. Ниже — все экраны по зонам карты.

## 3. Состояния экранов (чек-лист PRODUCT_QUALITY_BAR §1)

- **Скелетоны** — есть почти везде (главная, каталог, витрина, товар, корзина, профиль, кошелёк, адреса, бизнес-статус).
- **Пустые состояния** — образцовые в корзине, заказах, адресах, баллах; отсутствуют на главной и в популярных (пустые секции без текста).
- **Ошибки с retry** — точечно: каналы входа (429/сеть), чекаут, бизнес-статус, карты профиля, баллы.
- **Сквозная дыра**: у главных витринных экранов (главная, популярные, каталог, витрина, товар, корзина, заказы, адреса) **ошибка API = вечный скелетон без текста и повтора**; глобальный errorHandler пишет только в консоль. Это главный системный риск прода: любая деградация API выглядит как «приложение сломалось».

## 4. Приоритеты перед продом

**P0 — без этого на прод нельзя (4 позиции)**
1. Кабинеты ролей: передать пропсы таб-бара в роутере (или собрать табы внутри CabinetLayout по роли) + починить «Клиент» переходом в профиль. Пользователь с ролью сейчас «запирается» в кабинете без навигации.
2. Сквозные error-состояния с повтором для витринных экранов (см. §3) — единый паттерн «не удалось загрузить → Повторить».
3. Снять с прод-роутера заглушку банка `/payment/fake` (env-гейт на фронте) и добавить подтверждение на «Открыть счёт» у представителя.
4. Убрать/перенаправить orphan `/business/result`; починить обманывающие ошибки МСП («нет точки» при сбое сети).

**P1 — заметные шероховатости (первая неделя после релиза)**
- Мёртвые фильтры поиска (тип доставки/сортировка) — либо скрыть, либо отправлять в API; отделять ошибку поиска от «не найдено».
- Хардкоды: баннеры главной (статичные картинки), «₽ за 1 шт.», «Итого» без доставки в корзине, «Доставка — по тарифам заведения», получатель «Пользователь», дом «-» при сохранении адреса.
- «Отправить код повторно» в AuthCode не отправляет код; промокод-шаг входа — фейк (скрыть до готовности).
- МСП: реквизиты счёта верификации в env прода + автообновление статуса оплаты; поллинг бизнес-статуса с потолком.
- Кошелёк: пагинация истории (сейчас 48 записей и месячная статистика только по первой странице); не глотать ошибку истории; тир-бейдж карты — реальный статус из SZ-042.

**P2 — не спешить (бэклог)**
- Отмена/повтор заказа, повторная оплата из истории; типы адресов и тумблер «по умолчанию»; вертикальные `City/StreetSearchInput` дубль в create/update адреса.
- Легаси-чистка: ProfileCard/ProfileBanner/ProfileQr (не используются), CALL_CODERS, `geolocation-access.ts` (дубль композабла), мёртвые константы BUSINESS_POLL_*.
- СБП (иконки уже в ассетах), фискальный чек (сейчас честный дисклеймер), синхронизация счётчика товара в карточке.

**Где усилия НЕ нужны сейчас (осознанные фазы — не трогать):** чаты кабинетов, обучение амбассадора, «Моя точка» (управление), доходные экраны кабинетов (ждут финконтура), «Отзывы»/«Пригласить друга», VK-автологин. Все они честно подписаны в UI как «Скоро» — это соответствует стратегиям фаз и не является долгом перед продом.
