## Диагноз: почему «ужас» (корень, не косметика)

1. **Цвет роли как основной тон.** Карточки залиты rgba роли (tiffany 0.08 / gold 0.10), промокод и кнопки выкрашены в роль — против docs/05 ДС: «один акцент — pink», роль-цвет живёт только в роль-пилюле и мягких тинтах.
2. **Нет продуктового каркаса.** Экраны — «KPI + пара текстовых ссылок» без иерархии: нет главного следующего шага, нет связки обзор↔списки, пустые состояния без CTA, «Загружаем…» вместо скелетонов.
3. **Обещания без механизмов.** Апрув заявки одним тапом без подтверждения (необратимо), ошибка API рендерится как «нет точки», кнопка «управление каталогом» ведёт на маркетинг-лендинг.
4. **Дрейф от канона.** Коды `REP-Город-042` вместо промокода `PPXXXX` (BRD §3.1), статус-чипы вне канон-пар, нули-хардкоды там, где API уже отдаёт данные.
5. **Мульти-юрлица не предусмотрены** (msp-ds-multibranch): нет переключателя юрлицо/филиал, весь МСП-контур считается «одна точка = один экран».

## Что показывают прототипы в lovii-demo

Демо-сборка: экраны `#/dash` (представитель, амбассадор) и `#/msp` (ЛОВИ Бизнес) пересобраны в новом каркасе.

**Как смотреть:**
- Профиль → секция «Роли / кабинеты» → «Войти как Представитель» / «Войти как Амбассадор»; «ЛОВИ Бизнес» — демо-ряд «Открыть».
- Переключатель темы в шапке — проверять обе темы.
- Ширины: 390 (мобильный) и ≥640 (двухколоночный адаптив там, где он есть).

**Ключевые продуктовые решения (на согласование):**

| # | Решение | Где |
|---|---------|-----|
| 1 | Единый каркас всех кабинетов: аватар + название + роль-пилюля, табы-капсула `.seg`, акцент роли — только в пилюле/ранге | все три |
| 2 | Статусы — канон-пары: розовый «новое», золото «в работе», тиффани «готово/активно», серый «отменено» | все три |
| 3 | Карточка подписки представителя (гейт SZ-042: доля 40% действует, пока активна подписка 599/199 ₽) | rep/обзор |
| 4 | Апрув заявки — через bottom-sheet с подтверждением; возврат на правку — с причиной. Фикс P0 RES-004 | rep/подключение |
| 5 | Промокод `PPXXXX` + ссылка `/business/apply?promo=` (канон BRD §3.1); коды REP-*/AMB-* выведены | rep |
| 6 | Структура амбассадора read-only: закрепление платформой, никаких «кодов амбассадора» | amb |
| 7 | Контекст-свитчер юрлица/филиала (`.pill-btn` → sheet → строки филиалов) — кандидат в канон ДС | msp |
| 8 | Заказы МСП с реальной статус-машиной Task 20 (самовывоз / доставка, отмена с причиной, честные тексты переходов) | msp |
| 9 | МСП-кабинет — два режима: онбординг (заявка→платёж→инструкция) и операционный (обзор/заказы/товары/ещё) | msp |
| 10 | Деньги — tabular-nums, честные нули с объяснением, модель-ноут (пул 10% − эквайринг, сплит 40/40/20) | все |

## Открытые вопросы владельцу (чек-лист согласования)

1. **Ранги представителя** «Цифровой Представитель → Мэр → Губернатор» (пороги 30/90 точек) — оставляем как мотивационный слой?
2. **Карточка подписки** (SZ-042) на обзоре представителя — копирайт и место (сейчас: отдельная карточка над KPI)?
3. **Чаты**: в демо оставлены рабочими (были до решения 2026-09-11), в app — отложены. Убрать из прототипов или оставить как целевое состояние?
4. **Контекст-свитчер** юрлиц/филиалов — согласовать паттерн (пилюля в шапке кабинета → bottom-sheet со строками филиалов) как расширение канона ДС (правило AGENTS.md: новый паттерн — сначала коммит в lovii-design).
5. **QR-код** в демо — стилизованная заглушка; в app нужен настоящий QR без внешних библиотек (бэклог) — приоритизировать?
6. **Табы МСП** операционного режима: «Обзор · Заказы · Товары · Ещё» — ок? В «Ещё» — счёт, инструкция, b2b, карточка точки.
