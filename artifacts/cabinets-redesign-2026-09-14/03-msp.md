## 2. Целевая модель: два режима + контекст

### Режимы кабинета

- **Онбординг** (заявка не верифицирована): табы `Заявка · Платёж · Инструкция`. Путь SZ-007: карточка → апрув представителя → счёт VER → платеж с р/с → витрина teaser → активна.
- **Операционный** (после верификации; в демо — сразу доступен как основной сценарий): табы `Обзор · Заказы · Товары · Ещё`.

### Контекст-свитчер юрлица/филиала (новый канон-паттерн)

- В шапке кабинета — пилюля (`.pill-btn`): «ИП Смирнова · Кофейня У дома ▾».
- Тап → **bottom-sheet** со строками филиалов (`.district-row`), сгруппированными по юрлицам: юрлицо = заголовок группы, филиалы = строки с пиктограммой, адресом и активной точкой.
- Выбор филиала меняет контекст всего кабинета: обзор, заказы, товары. Контекст живёт в localStorage.
- Правила (msp-ds-multibranch §B): 1 юрлицо + 1 филиал → свитчер скрыт; 0 юрлиц → empty-state с CTA на заявку; «во всех филиалах» — бейдж позиции.
- В app реализуется после Ф1 core (memberships + `/msp/partners/{partnerId}/*`); паттерн сначала коммитится в lovii-design (правило AGENTS.md).

### Обзор (операционный)

1. KPI: Заказы сегодня (accent) · Выручка · месяц · Товары на витрине · Средний чек.
2. Пилюля витрины: «Витрина активна» (tifфани) / «Карточка видна, товары — после каталога» (gold, teaser SZ-035).
3. Next-step: новые заказы → «Принять заказы сейчас»; каталог пуст → «Заполнить каталог».
4. Последние заказы (5 строк с канон-пилюлями статусов, тап → карточка заказа).
5. Quick actions: Заказы · Товары · Счёт · Инструкция.

### Заказы — статус-машина Task 20 (реальные переходы)

- Сегменты: Новые (badge) · В работе · Готовы к выдаче · Все.
- Строка: номер, время, клиент, состав (кратко), сумма (tabular), пилюля статуса, иконка исполнения (самовывоз/доставка).
- Тап → **bottom-sheet карточки заказа**: позиции, сумма, тип исполнения, комментарий клиента, таймлайн статусов, кнопки-переходы:
  - Самовывоз: Принять → Начать готовить → Готов к выдаче → **Выдан клиенту**.
  - Доставка: Принять → Начать готовить → Передан курьеру → Курьер в пути → **Доставлен**.
  - «Отменить заказ» — доступен до готовки, sheet с полем причины (обязательно).
- Честные тексты ошибок (канон хотфикса `421fd0e`): «Такой статус сейчас недоступен для этого заказа» при гонке.
- Уведомления: WebPush + бот, звук-луп до принятия, потолок 60 мин — dash-note в демо, реализовано в app.

### Товары

- Строки: эмодзи, название, цена/ед., остаток, бейдж принадлежности: «Все филиалы» (SZ-013) или имя филиала.
- Read-only: «Управление каталогом — в кабинете b2b» + кнопка «Открыть кабинет b2b» (внешний URL из env, новое окно; в демо — честная note).
- Пустой каталог: empty-state + CTA на инструкцию.

### Ещё

- Счёт верификации: статус «оплачен, возвращён» (после верификации) или pay-card до него.
- Карточка точки/филиала: адрес, часы, фото (сводка).
- Инструкция b2b (mentor-card + 3 шага: ссылка → каталог → публикация).

### Онбординг (до верификации)

- Stepper 5 шагов реальной машины (`draft → submitted → awaiting_rep_approval → invoice_issued/awaiting_payment → verifying → verified | failed`).
- Заявка: форма SZ-007 (ИНН с контрольной цифрой, деятельность, адрес с геоподсказками, согласия).
- Платёж: pay-card 1 ₽, назначение **VER-<partner_id>-<суффикс>** (паттерн `.promo-code`), «платёж строго с р/с компании», «вернём на реквизиты после проверки» (без обещания «мгновенно»), чек-лист 4 строки.
- Статус оплаты сам не обновляется (P1 RES-006) → в демо: кнопка «Обновить статус» + поллинг-ноут.

## 3. Данные / API (путь к реализации)

- Сейчас: `/api/v1/msp/*` без контекста юрлица (одна точка = один аккаунт).
- Цель (msp-ds-multibranch §B): `GET /business/memberships` → `GET /business/partners/{partnerId}/branches` → параметризованный `GET|PATCH /msp/partners/{partnerId}/orders|offers...`; guard по memberships (`order_not_owned`).
- Порядок выката: core → deploy-staging → app (канонический урок Task 20).
