## Цель

Один проход оформления всех экранов demo + app через канон ДС (lovii-design 1.16.2) с фиксацией решений и скриншот-регрессией. На выходе — синхронный, предсказуемый стиль обеих витрин и закрытый реестр расхождений.

## Шаги сессии

1. **Ресинк токен-снапшотов.** Пересобрать demo `assets/lovii-tokens.css` и app `lovii-tokens.scss` из lovii-design одной датой сборки; бамп версий.
2. **Решение по 3 локальным токенам app** (`--lv-navbar-height/offset`, `--lv-line-strong`): канонизировать в lovii-design (правильный путь) либо вынести из «неправляемого» файла в слой app. Один вариант, зафиксировать в REGISTRY.
3. **Navbar-фикс demo:** определить `--lv-navbar-height: 64px` (RES-008 §5); прогнать экраны с нижними CTA на iPhone-safe-area.
4. **13 разночтений кабинетов** (RES-008 §4): по каждому — «чьё право» (канон ДС / demo / app), правки вносятся одной пачкой после подтверждения владельца.
5. **69 демо-семейств без аналога:** разметить «реализовано иначе / пробел переноса / не нужно» — таблица в артефакты сессии.
6. **Типографика:** решить, нужен ли demo `--font-scale` (настройка «Размер текста» из app) и оверрайды контраста светлой темы (Task 89) — поднять в канон или оставить витринными.
7. **Скриншот-регрессия:** все роуты demo + ключевые экраны app, 390/1280, светлая/тёмная; сравнение до/после; артефакт-отчёт с датами.
8. **Полный аудит демо** (хвост RES-009 §4) на итоговой голове.

## Критерии приёмки владельца

- Токен-слои demo/app собраны из одного коммита lovii-design; никаких значений вне канона без регистрации.
- Каждое из 13 разночтений закрыто (сведено или помечено «осознанное отличие» с причиной).
- На iPhone таббар 64px и отступы считаются от него; ничего не встаёт вплотную.
- Скриншот-регрессия без новых визуальных диффов вне согласованных правок.
- Стрелки профиля на телефоне владельца — подтверждено исправно.

- Всегда свежие клоны с GitHub перед началом; локальное состояние не считается истиной.
- Код-пуши — только по явной команде владельца, по согласованному списку.
- Каждый шаг сессии фиксируется в worklog и артефактах с датами загрузки/проверок.
