# RES-014 — Аудит OTP-входа на проде: MAX / Telegram / VK (03.10.2026)

Контекст: владелец прошёл авторизацию на проде; Telegram — «код есть, но флоу
неоднозначный», VK — «открыл диалог и ничего не произошло», MAX — застревал на
инструкции (починено в тот же день). Запрошена аналитика для решений.

## 1. Как флоу устроен в коде (единый паттерн на все каналы)

Экран канала (AuthMaxLink / AuthTelegramLink / AuthVKLink):
1. Инструкция + кнопка-дииплинк «Открыть MAX/Telegram/ВК».
2. Пользователь в диалоге бота нажимает «Начать» (deeplink несёт binding_token).
3. Бот присылает 4-значный код + кнопку «Поделиться контактом».
4. Два пути подтверждения:
   - **бескодовый**: «Поделиться контактом» → сессия confirmed → приложение
     само входит (поллинг `/auth/{max|telegram}/status`);
   - **ручной**: пользователь вводит код на экране — форма спрятана за
     фолбэк-ссылкой «Ввести код из бота вручную».

## 2. Что сломано/неоднозначно (факты из логов прода, 03.10)

| # | Канал | Симптом | Причина | Статус |
|---|---|---|---|---|
| 1 | MAX | «замер на инструкции», формы нет | (а) env прода был без токенов; (б) вебхук зарегистрирован на чужой роут; (в) форма = фолбэк, сама не открывалась | (а)(б) починено 03.10; (в) починено: `status=delivered` → форма открывается сама (в проде с вечера 03.10) |

## 3. Как это сделано у других (ресёрч, 03.10)

- **Без ввода кода вообще — мейнстрим 2024+**: Telegram Login Widget /
  `request_contact` (один тап), VK ID (one-click OAuth + push-подтверждение +
  passkeys/OnePass), WhatsApp-OTP у зарубежных. Ручной ввод кода — фолбэк, а
  не основной путь ([vk.ru](https://vk.ru), [vc.ru](https://vc.ru),
  [Authsignal](https://www.authsignal.com)).
- **Код, если вводится**: TTL 30 сек–5 мин, автопрочтение/автопереход
  (SMS Retriever, deep-link возврат в приложение), один явный следующий шаг
  на экране ([Dexatel](https://dexatel.com), [Prelude](https://prelude.so)).
- **Мультиканальность как надёжность**: WhatsApp ~99,7% доставки против
  «бесплатных» ботов; fallback SMS→мессенджер — стандарт
  ([8x8](https://cpaas.8x8.com), [Hey Pingr](https://heypingr.com)).
- **VK ID для бизнеса** — готовая федерация «войти через VK» одним кликом;
  наш сценарий «код в диалог сообщества» — самодельный и слабее VK ID.

## 4. Выводы и варианты (для решений владельца)

**Корень неоднозначности — не «сценарий сломан», а два инфра-разрыва (VK
callback → staging; TG-статус → MAX-таблица) плюс UX-паттерн, где главный
путь (ручной ввод кода) спрятан, а главный сценарий рынка (поделиться
контактом / one-click) не подсвечен.**

Варианты:
- **А (минимальный, ~1 день)**: перевести `/auth/telegram/status` на общую
  логику delivered (по аналогии с MAX — таблица связи TG chat↔телефон) +
  авто-раскрытие формы в AuthTelegramLink + подсветить «Поделиться контактом»
  как главный путь на всех трёх экранах. VK: инструкция владельцу для
  перерегистрации callback на api.lovii.ru (5 минут в настройках сообщества).
- **Б (стратегический)**: подключить VK ID OAuth как основной VK-способ
  (one-click, без ботов), бот-диалог оставить фолбэком. Telegram — оставить
  код-флоу, но с автопереходом; MAX — как есть.
- **В (дальняя)**: push-подтверждение входа вместо кодов (после подключения
  пушей SZ-069), passkeys — как VK ID.

## 6. Решение владельца (04.10) — дорожная карта A→B→C

- **A — первый старт**: работа в одном устройстве после подключения канала.
  Починить TG-статус (delivered), авто-формы, «Поделиться контактом» как
  главный путь; владелец меняет VK-callback на api.lovii.ru.
- **Б (VK ID) — принят с условием, условие ВЫПОЛНЕНО**: VK ID отдаёт номер
  телефона — `POST https://id.vk.com/oauth2/user_info` возвращает `user.phone`
  при скоупе `phone` (старый users.get телефон не отдаёт). Нюансы: приложение
  VK нужно зарегистрировать на dev.vk.com и запросить скоуп `phone`
  (возможна модерация), согласие пользователя на передачу телефона.
  Телефон — наш единственный базовый ключ, поэтому Б имеет смысл.
- **В (push-вход с другого устройства) — обязателен**, появляется как вариант
  только когда: (1) у номера есть профиль, (2) на устройстве пользователя
  установлено приложение и включён приём пушей. Проверять это можно точно:
  SZ-069 хранит per-device push-токены — наличие активного (живого) токена
  на устройстве пользователя = надёжный признак; «выключены пуши в ОС»
  узнаётся только по факту отправки, живость токена — по ответам провайдера.
- Порядок: A → (параллельно заявка на VK ID app + скоуп phone) → Б → В.
