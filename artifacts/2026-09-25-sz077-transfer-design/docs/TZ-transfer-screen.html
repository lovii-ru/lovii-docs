Экран «Перевод» + единый узел переводов (обход невозможен)

Задача на два слоя: привести экран перевода в приложении к эталону витрины и закрыть систему так, чтобы перевод существовал ровно в одной точке — с тремя обязательными проверками, инвариантом транзитного счёта и детектором обхода.

Дата: 25.09.2026 Репозитории: lovii-app · lovii-core · lovii-admin Эталон: витрина #/transfer (сборка 126) Исполнитель: zcode (зона кошелька/балансов)

01 · Суть задачи

СлойЧто делаем
Приложение lovii-appЭкран перевода по витрине: одно поле адресата, сумма, точный авто-расчёт, выпадающий выбор источника, экран успеха
Бэкенд lovii-coreЕдиный узел TransferService: три проверки, идемпотентность, инвариант транзита, одна точка подписи
Админка lovii-adminЗакрыть обходной путь правки баланса; расширить настройку комиссий по типам переводов
Ограничение зоны. Кошелёк и балансы — зона zcode (канон WORK_PROTOCOL.md §1.2): правки по своей карточке с приёмкой владельца. Другому агенту эту задачу отдавать нельзя.

03 · Три проверки в момент перевода

Всё — в одной DB::transaction, до записи. Нарушение любой → 422 и ни одной записи.

  1. Балансы. Источник под lockForUpdate. PAY: сумма + комиссия ≤ баланс − 100 ₽. Счёт компании: сумма ≤ баланс. Проверка под блокировкой, а не до неё — защита от гонки.
  2. Дубли (идемпотентность). Поле idempotency_key + unique-индекс. Повторный запрос с тем же ключом возвращает тот же перевод и не создаёт второй транзакции. Плюс запрет перевода самому себе.
  3. Правила. 100 ₽ ≤ сумма ≤ 3 000 ₽; тариф по ступеням; направление из белого списка; получатель найден и не является отправителем.

04 · Инвариант транзитного счёта

Любой перевод идёт через platform_nominal; по каждой транзакции номинал — в ноль:

с комиссией: +(сумма + комиссия) − сумма − комиссия = 0 без комиссии: +сумма − сумма = 0 ← сколько пришло, столько ушло
  • Проверка-тест: сумма проводок platform_nominal по transfer_id = 0.
  • Расхождение → инцидент P1, алерт админу (канон FINANCIAL_CONTOUR.md §5.4, допуск 0).

05 · Одна точка подписи и детектор обхода

  • Все записи одного перевода — AccountTransfer + WalletTransaction + проводки ledger — в одной транзакции и в одном месте, с transfer_id и split_role у каждой ноги.
  • Перевод, созданный не через узел (остаточный интерфейс, консоль, админка), должен не создавать транзакцию, а возвращать пользователя с ошибкой transfer_unknown_origin.
  • Страж-тест: скан кода падает, если AccountTransfer::query()->create или WalletTransaction::query()->create с типом transfer/fee встречается вне TransferService.
