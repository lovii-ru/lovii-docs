LOVII · SZ-076 · шкурка демо на приложение

Как ставить задачи кодеру, чтобы экран принимался с первого раза

Регламент постановки задач для кодинг-агента + рабочий шаблон ТЗ + заполненный пример. Цель одна: убрать из задачи все решения, которые агент иначе примет сам — а владелец потом будет разгребать руками.

Составлено: 25.09.2026 Репозиторий: lovii-app Ветка: feat/sz-076-demo-skin Стенд: localhost:5173 · API staging

01 · Почему задача «не доделывается»

Три причины, все видны в истории SZ-076. Каждая лечится одним и тем же — предзаполненным ТЗ.

1
Агент решает за владельца — и решает «как быстрее»
Когда в задаче не сказано из чего и чем, агент берёт привычное: свой радиус, свой цвет, свой текст, свою иконку. Отсюда «выпадающий список» на 2 часа: агент собрал контрол по-своему, а не по канону.
2
Не зафиксирована граница «что НЕ входит»
Срез «Главной» был сделан и откачен: владелец про Главную не просил, а структура в приложении другая — переносить 1:1 было нельзя. Это не ошибка кода — это пропущенный блок «объём и решение».
3
Нет гейта и нет приёмки — «готово» на глаз
Экран считается сделанным только когда: yarn test зелёный, DS-guard не вырос, есть скрин-пара 390/1280, и владелец сказал «принято». Без этого «сделано» возвращается трижды.

02 · Роли и цикл

Разделение: постановщик (я) превращает указание владельца в точное ТЗ с путями, классами и гейтами; кодер реализует ровно это и отчитывается артефактами; владелец принимает один раз.

  1. Владелец называет экран и порядок. Без явного указания экран не берём — это уже стоило откатом Главной.
  2. Постановщик пишет ТЗ по шаблону: паспорт, решение, эталон демо, точные файлы, токены, состояния, гейты.
  3. Кодер кодит в worktree локально (yarn dev, API staging), ничего не мержит.
  4. Гейты: yarn test + DS-guard + скрин-пара приложение↔демо на 390 и 1280.
  5. Владелец смотрит локально и либо принимает, либо даёт правки — правки сразу на hot-reload.
  6. После «принято» — мерж в staging → CI → деплой. Раньше — нельзя.

03 · Анатомия ТЗ — 10 обязательных блоков

Пустой блок = агент поставит туда своё допущение. Это и есть источник переделок.

0. Паспортчто/где/как
ID и номер экрана, репозиторий, ветка, worktree, база (origin/staging @ хеш), команда запуска стенда, и чьё это указание с датой.
1. Решениеin / out of scope
Цель одним абзацем, что входит, что НЕ входит (явно), запретные зоны платформы (кошелёк/биллинг/чарджбэк — только zcode).
2. Эталонисточник истины
Файл и функция демо (js/<файл>.js → <render…>), список классов к переносу, кадры-эталоны. Таблица соответствия «демо → приложение».
3. Целевые файлыточные пути
Таблица: путь в src/ → что именно делаем. Не «экран заказов», а profile-orders/components/OrderPreview.vue.
4. Переиспользоватьне изобретать
Конкретные компоненты кита (Ui/AppBadge, AppPagination…), примитивы шкуры (scss/demo-skin/*), иконки LvIcon. Правило: перед новым контролом — grep по src/components/Ui/.
5. Токены и запретыDS-guard
Только токены; в новом коде нет #hex, box-shadow:…, border-radius:Npx. Акцент выбора — --lv-accent*. Ритм: --lv-block-gap (16) / --lv-section-gap (24).
6. Состояния + адаптив3 состояния, 2 ширины
loading / empty / error — что видит юзер в каждом. Ширины 390 и 1280; где демо даёт 2 колонки — воспроизводим. Тап-таргет ≥44, обе темы.
7. Гейтыобязательны
yarn test (format→lint→unit→type-check→build + DS-guard), скрин-пара, тесты при изменении контрактов/тестидат.
8. Приёмкапроцесс владельца
Локально → владелец смотрит → «принято» → мерж. В staging раньше нельзя.
9. Отчётв том же цикле
Session-док docs/sessions/NNN-…, отчёт в карточке SZ-076, коммит-нейминг, строка в трекере. Что прислать на проверку: diff --stat, скрины, хвост yarn test.

05 · Пример — №8 «Заказы / карточка заказа»

Как выглядит точное ТЗ в объёме. Полная версия — deliverables/sz076-task-spec/example-orders.md.

БлокСодержимое примера
Эталонjs/orders.js → renderOrdersMirror(), oOrderCard(), renderOrderDetailMirror(); классы orders__list, order-preview__footer, cart-info__products, row-item, cart-summary, sum-total
Файлыprofile-orders/OrdersModule.vue, components/OrderPreview.vue, components/OrdersEmpty.vue, profile-order/ProfileOrder.vue, components/OrderInfo.vue, OrderProducts.vue

Открытый вопрос
владельцу		Текст пустого состояния: сейчас «Пока ничего нет» + кнопка; в демо — «Заказов пока нет / Оформите первый заказ — история появится здесь». Предложение: текст по демо (закон демо), кнопку оставить. Это единственное решение — и оно вынесено явно, а не оставлено агенту.

06 · Красные флаги из истории

откат

Главная: сделали — откатили

Причина: экран не был назван владельцем, а структура в приложении отличается от демо. Лечение: блок 1 «откуда указание» + явный out-of-scope. Экран без указания не берём.
2 часа

«Выпадающий список»

Каскад юрлицо→мерчант→точка: агент собрал контрол без эталона (чип + шит-список), владелец доделывал вручную. Лечение: блок 2 «эталон + классы» + блок 4 «переиспользовать AppBottomSheet/примитивы». Такой контрол специфицируется один раз как шаблон-паттерн и переиспользуется.
текущий долг

Словарь классов

Демо и приложение называют одно и то же по-разному (row-item ↔ .row). Лечение: в блоке 2 всегда указывать, какой словарь целевой (для SZ-076 — классы демо, порт в scss/demo-skin/), чтобы агент не плодил третий.
