## 6. Три обязательные проверки в момент перевода (в одной `DB::transaction`, до записи)

1. **Балансы.** Источник под `lockForUpdate`. Для PAY: `сумма + комиссия ≤ баланс − резерв(100 ₽)`.
   Для счёта компании: `сумма ≤ баланс`. Проверка — **под блокировкой**, а не до неё (защита от гонки).
2. **Дубли (идемпотентность).** Новое поле `idempotency_key` + unique-индекс. Повторный запрос с тем же
   ключом возвращает **тот же** перевод, второй транзакции не создаёт. Плюс запрет перевода самому себе.
3. **Правила.** `min ≤ сумма ≤ max` (100…3 000 ₽), резерв, тариф по ступеням, направление из белого списка,
   получатель найден и не является отправителем. Любое нарушение → `422` и **ни одной** записи.

## 7. Инвариант транзитного номинала (обязателен)

Любой перевод идёт через `platform_nominal`; по каждой транзакции номинал **в ноль**:

```
с комиссией:   + (сумма + комиссия) − сумма − комиссия = 0
без комиссии:  + сумма − сумма = 0            ← «сколько пришло, столько ушло»
```

- Добавить проверку-тест: сумма проводок `platform_nominal` по `transfer_id` = 0.
- Расхождение → инцидент P1 (канон `FINANCIAL_CONTOUR.md §5.4`, допуск 0), алерт админу.

## 8. Единственная точка подписи перевода

- Все записи одного перевода — `AccountTransfer` + `WalletTransaction` (transfer/fee) + проводки ledger —
  в **одной** транзакции, в **одном** месте (`TransferService`), с `transfer_id` и `split_role` у каждой ноги.
- **Детектор обхода:** перевод, созданный не через узел (остаточный интерфейс, консоль, админка),
  должен **не создавать транзакцию**, а возвращать пользователя с ошибкой `transfer_unknown_origin`.
- Закрепить стражем-тестом: скан `lovii-core/app` и `lovii-admin/app` падает, если `AccountTransfer::query()->create`
  или `WalletTransaction::query()->create` со типом transfer/fee встречается вне `TransferService`.
