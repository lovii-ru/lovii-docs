## Analysis

1. **C1 подтверждён на всех доступных осях.** Проверено 6 независимых поверхностей: (i) индекс/дерево HEAD, (ii) все локальные refs (только `main`), (iii) все теги, (iv) тексты всех blob-объектов, включая недостижимые (1342 blob'а, 0 совпадений), (v) каталоги `canon/TASKS/` и `archive/tasks/`, (vi) живой `git ls-remote` зеркала (только `main` + `refs/pull/1/head`). Максимум T-ID корпуса — **T-013**. Дополнительный сильный сигнал: даже как **текст** (inline-код, ссылки, упоминания в BACKLOG/FINDINGS/STATUS) строки `T-014`/`T-015`/`T-016` в каноне отсутствуют — при том что T-001…T-013 встречаются 7–44 раза. Это не «карточку забыли положить», а «волны T-014+ в каноне docs ещё нет вовсе» — при том что **в коде** core/app коммиты с «T-014» уже существуют.

2. **C5 против C1 — ключевое расхождение, которое надо удержать.** «T-014» живёт как идентификатор коммитов в `lovii-core`/`lovii-app` (6+6 коммитов, включая «T-014 приёмка» и «решение владельца 22.09»), но карточки/канон-записи под ним в docs нет. По §2 протокола работа, ссылающаяся на несуществующий в каноне путь/карточку, **не должна импровизироваться**: исполнитель обязан зафиксировать находку в `canon/FINDINGS.md` с конкретным пунктом и вернуть задачу на уточнение. Наличие коммитов-«T-014» в коде при отсутствии карточки в каноне — типовой кандидат в FINDINGS (ещё не зафиксировано: максимум FINDINGS = F-054).

3. **C2 подтверждён численно.** Диапазон FINDINGS непрерывен F-001…F-054 (54 уникальных номера); F-055…F-069 отсутствуют. Значит F-058/F-059 — не «потерянный номер», а номера, которых в каноне просто нет.

4. **C3/C4 подтверждены по живому remote, а не по устаревшему tracking-ref.** Это важно: локальный `mirror/main` мог быть стейлом. `git ls-remote` (сеть) показал совпадение. Аналогично для core/app `origin/staging`. Никаких ahead/behind и грязных файлов у HEAD нет. Единственная «грязь» во всей картине — untracked `PHOTOS.md` в docs (вне git, на канон не влияет).

5. **Формулировка протокола про «только вердикт владельца закрывает карточку» мягче, чем в mainline-claim.** Протокол требует: (1) отчёт исполнителя; (2) Приёмка-1 **независимой** стороны с вердиктом `Достаточно`/`Доработка: …`; (3) Приёмка-2 **второй обязательной** стороны — «обычно владелец или партнёр по парному режиму». То есть владелец — обязательная сторона **по договорённости задачи**, но текст не говорит «только владелец». Закрытие = наличие обоих обязательных вердиктов `Достаточно` + записанные результаты/даты. Статус `Закрыта` без этого недопустим (§3.2), а `STATUS` не заменяет секции приёмки (§3.3).

6. **Гейты §8 материальны.** Все четыре скрипта физически есть в репо, `git diff --check` зелёный, CI-workflow `fact-guard.yml` на месте. Значит проверка «существуют ли скрипты» — да. Отдельно: §9.4 опирается на `tools/lovii-backup.sh` / `tools/lovii-cloud-backup.sh`, которых **внутри docs-репо нет** — они в workspace-слое `/Users/best/LOVII/tools/`. Это согласуется с §6 (workspace-слой = оперативные файлы), но как путь «из корня lovii_docs» он не разрешается — потенциальная ловушка для агента, буквально исполняющего протокол.

## Gaps and risks

1. **Partial clone (blob:none).** `git config remote.mirror.partialclonefilter` = `blob:none`; при переборе объектов git предупреждал: «This repository uses promisor remotes. Some objects may not be loaded.» Поэтому формулировку «во всех git objects» корректнее читать как «во всех **доступных локально** объектах» (1342 blob'а) + полный перебор имён по всем refs + живой `ls-remote`. Для refs, которые remote вообще не объявляет (а он объявляет только `main` и `refs/pull/1/head`), объекты существовать не могут — так что практический вывод C1 устойчив. Теоретическая дыра: blob, недостижимый ни из одного ref (для обычного репо невозможен).
2. **Локальные теги docs не запушены.** `git ls-remote mirror` не отдаёт ни одного `refs/tags/*`, при этом локально есть `v0.9.0`, `v1.0.0`, `v2.0.0`, `v2.0.3`. Если кто-то ожидает увидеть T-карточки в тегах на remote — их там нет; локальные теги тоже без T-014/15/16.
3. **T-номер в коммитах ≠ карточка в каноне.** Расхождение core/app («T-014» есть) ↔ docs (карточки нет) — реальный разрыв цепочки «постановка → исполнение → канон», и он пока **не** отражён ни в FINDINGS (потолок F-054), ни в карточках. Риск: следующая сессия примет коммиты-«T-014» за каноничную задачу и начнёт импровизировать, что §2 прямо запрещает.
4. **`PHOTOS.md` untracked в docs.** Не влияет на канон, но при `git push`/`git add .` может «уехать» в хаб посторонним файлом; по §9.2/§9.3 это нежелательный шум. Стоит держать вне индекса.
5. **Не проверял (вне scope C1–C5):** содержимое чужих рабочих копий-спутников (`lovii-core-sz063`, `lovii-core-queue`, `lovii-app-queue`, `lovii-app-sz063/066`, `lovii-core-sz038/045`, `lovii-core-referral`, `lovii-docs-local-archive-20260917`). Если требуется инвентарь «всех» карточек T-014/15/16 на машине, эти каталоги надо проверить отдельно — по mainline-claim они не входят в «canon», но физически это возможные источники карточек.
6. **Текущее состояние гейтов не прогонялось** (только проверено наличие файлов + `git diff --check`). Запуск `task_guard.py` / `doc-canon-check.py --strict` / `fact-guard.sh` не выполнялся, чтобы не создавать side-effects при read-only задаче; если нужен фактический цвет гейтов — отдельный проход (`sync-public.sh` намеренно не запускался ни в каком виде).

## Suggested placement

- **Основной вывод (C1+C5):** в отчёт главной линии как отдельный пункт «разрыв цепочки постановки T-014: коммиты в core/app есть, карточки и канон-записи в docs отсутствуют; максимум T-ID канона = T-013, максимум FINDINGS = F-054». Кандидат на запись в `canon/FINDINGS.md` как новый F-055 по §2 («задача/работа ссылается на путь/карточку, которых нет в каноне»).
- **Подтверждение C2/C3/C4:** в сводную таблицу факт-чека как «verified by raw artifact» — с указанием, что C3/C4 сняты по живому `git ls-remote`, а не по tracking-ref.
- **Карта правил (WORK_PROTOCOL §1/§2/§3.3/§8/§9.2/§9.3):** в раздел «governance constraints» сводки — с дословной цитатой §2 (действие при ссылке на несуществующий путь) и уточнением, что закрытие карточки требует **двух** обязательных вердиктов `Достаточно`, а не только владельческого.
- **Мелкие находки для отдельного места:** (i) `tools/lovii-*.sh` отсутствуют в docs-репо и живут в workspace `/Users/best/LOVII/tools/`, хотя §9.4 пишет их как путь из репо — уточнить формулировку протокола; (ii) локальные теги docs (`v0.9.0..v2.0.3`) не запушены в зеркало; (iii) untracked `PHOTOS.md` в docs — держать вне индекса.
