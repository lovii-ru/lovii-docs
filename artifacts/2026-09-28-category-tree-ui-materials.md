## Где живёт в UI

Экран «Товары» кабинета МСП (`MspProducts.vue`, вкладка «Добавить / Категория»): блок
«Категории товаров», создание категории, скрытие категории на точке, выбор категории у товара.
Разбор экрана (вёрстка, табы, тап-зоны): `artifacts/2026-09-27-msp-design-pass-deliverables/`
(пакет `reports/lovii-products-audit`).

## Бэкенд — готов в ядре (staging, T-025 срез 2)

| Метод | Путь | Тело/ответ |
|---|---|---|
| GET | `/api/v1/msp/categories?branch_id={id}` | `{data:[{id, name, is_active, hidden_on_branch, offers_count}]}` |
| POST | `/api/v1/msp/categories` | `{name, branch_id?}` → 201 `{data:{id,name}}` |
| DELETE | `/api/v1/msp/categories/{id}` | — |
| POST | `/api/v1/msp/categories/{id}/branch-visibility` | `{branch_id, hidden}` → `{data:{id, hidden_on_branch}}` («точка сильнее», канон 27.09) |

Права — `MspAccess` (точка из запроса → мерчант). Плоский список, `sort_order` по порядку создания.

## Что осталось для вёрстки/приёмки

1. **Живые данные:** нужен мерчант с точкой (на стартере — нет; сид см. пакет
   `2026-09-27-msp-cabinet-deliverables`, `sql/seed-msp.sql`).
2. **Состояния экрана:** пусто («Категорий пока нет»), загрузка (скелетоны), ошибка, длинный список,
   «скрыта на точке» (визуальная пометка), удаление.
3. **Иерархия:** модель поддерживает `parent_id`, но API отдаёт **плоский** список.
   Если нужен именно «дерево» (вложенность/сворачивание) — расширение API отдельным срезом;
   решение владельца.
4. **Связка с товаром:** категория выбирается у товара (id), пилюля области действия — как в текущем
   макете (T-025 Фаза Б).
5. **Канон-дизайн:** строки списка и тап-зоны ≥44, только токены; скрин-пара 390/1280, обе темы.
