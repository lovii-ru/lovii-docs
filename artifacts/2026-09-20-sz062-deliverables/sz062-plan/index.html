Куда идут правки и как устроен канон

Вы подтвердили разбивку по репозиториям. Объём расширен: иконки выносим в канон, дизайн-система получает источник истины в lovii-design и каталог в витрине. Ниже — зафиксированные решения, обновлённый объём и оставшиеся контентные решения Гейта №1.

01Подтверждено вами

1Правки CSS и иконок — только в lovii-demo★ да
2Канон стилей — в lovii-design (новые токены через Гейт №2)★ да
3Канон иконок — вариант A: выносим в lovii-design★ A
4ДС: источник истины в lovii-design, каталог — в lovii-demo/design/ds/★ да
5lovii-app — только сверка, правок нет★ да

02Обновлённый объём по репозиториям

lovii-design расширено — канон
  • icons/ новое — полный каталог иконок: реестр SVG + манифест (имя → смысл) + шкала размеров + превью-витрина для подбора. Иконки не удаляем — расширяем.
  • tokens/ — добавить шкалу размеров иконок (и navbar-токен) — через Гейт №2.
  • docs/ — раздел про иконки; при необходимости — уточнения примитивов.
  • tools/ — разнос иконок в витрину по образцу токенов (генерация снапшота); механизм зафиксирую в фазе 3–4.
lovii-demo правим здесь — реализация + каталог
  • css/lovii.css — оптимизация анатомии витрины (мёртвый CSS, дубли, токенизация, слои).
  • js/icons.js — становится потребителем канона: явные размеры + шкала из lovii-design.
  • design/ds/ — каталог-витрина (README, tokens, primitives, components, icons, catalog.html), ссылается на канон.
  • index.html — бамп ?v= при правках.
lovii-app только сверка · lovii_docs только артефакты
  • Приложение — сравнение токенов и кабинетов, без правок.
  • Артефакты фаз 0–6 и строки реестра — в lovii_docs.
Важное уточнение по пункту 4. «Источник истины» относится к уровню канона — токены, шкала размеров, иконки, компоненты слоя B. Но анатомия именно витрины (её 919 классов вида .store-card, .cabinet__*) физически живёт в lovii-demo и в каноне её нет. Поэтому каталог компонентов в витрине документирует классы витрины и ссылается на канон — а не наоборот. Если хотите иначе — скажите.

03Гейт №1 — итог

Архитектура и пять из шести решений закрыты. Ниже статус каждого пункта.

1Удаление мёртвого CSS — 38 классов★ да
2Слияние 103 дублей + 9 дублей @media 640px, слои tokens→base→primitives→components→utilities★ да
4Иконки — не удалять, а расширять; полный каталог иконок и их стилей в lovii-design★ да
5Шкала иконок 16/20/24/32 + явный размер всем 195 вызовам★ да
6Navbar-фикс --lv-navbar-height: 64px★ да
3Токенизация хардкода: 52 hex + частотные размеры → var(--lv-*)⏳ жду
Открыт один пункт — №3. Менять ли 52 hex и повторяющиеся размеры на токены var(--lv-*)? Чего нет в каноне — предложу новыми токенами на Гейте №2. Если «нет» — хардкод остаётся как есть, и ДС получит пометку «вне токенов».
Следствие по иконкам (пункт 4). Раз иконки не удаляем, «оптимизация» иконок = привести все вызовы к явному размеру, свести дубли SVG, упорядочить реестр и вынести канон в lovii-design/icons/ с превью-каталогом. Удаления не будет ни одной иконки из 13 «неиспользуемых».

04Порядок дальше

Фаза 3 (оптимизация CSS) → Гейт №2 (токены, шкала иконок, таблица правок) → модуль иконок в каноне + Фаза 4 (ДС) → Фаза 5 (валидация на локальном стенде, скриншот-регрессия «до/после») → Гейт №3 (приёмка и команда на пуш).
