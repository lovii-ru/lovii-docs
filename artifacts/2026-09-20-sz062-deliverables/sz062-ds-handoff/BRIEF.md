# LOVII · бриф для аудита дизайн-системы (handoff большой модели)

> Готово к передаче вместе с `lovii.css`, `lovii-tokens.css`, `lovii-design-components.css`.

## 1. Что это

**LOVII** — клиентский продукт (витрина локальных торговых точек + роли: клиент, торговая точка, представитель, амбассадор, инвестор). Фронт витрины — **static HTML/CSS/JS** (без фреймворка), PWA. Есть отдельное Vue-приложение (`lovii-app`) и канон-фреймворк дизайн-системы (`lovii-design`).

## 2. Текущая архитектура стилей

| Слой | Файл | Строк | Правил | Роль |
|---|---|---|---|---|
| Токены канона | `lovii-design/tokens/tokens.css` | 253 | 23 | значения `--lv-*` (light/dark) |
| Компоненты канона | `lovii-design/css/lovii-components.css` | 593 | 461 | слой B: `.btn .chip .card` и т.п. |
| Снапшот токенов (в витрину) | `lovii-demo/assets/lovii-tokens.css` | 362 | 25 | то же + compat-алиасы |
| **Продуктовый CSS витрины** | `lovii-demo/css/lovii.css` | **3804** | **1701** | анатомия экранов витрины |

Витрина подключает: `lovii-tokens.css` (токены) + `lovii.css` (своя анатомия).

## 3. Проблема (глазами владельца)

- `lovii.css` = 3804 строки / 1701 правило / ~205 КБ — «страшно, тяжело поддерживать».
- Карточки и блоки выглядят почти одинаково, но описаны разными правилами.
- Желание: **свернуть всё в минимум (~500 строк)**, всё остальное **комбинировать/настраивать по месту**, масштабироваться **без роста числа правил**.

## 4. Что уже известно/зафиксировано (не ломать)

- Токены `--lv-*` в `lovii-tokens.css` — источник значений; темы light/dark через `[data-theme]`.
- «Рецепт карточки»: фон `--lv-card` + рамка `1px --lv-line` + радиус `--lv-r-lg`(16) + тень `--lv-shadow-soft`; hover → `--lv-shadow-lift` + `--lv-pink`.
- Обводки: канон `--lv-line` (light `#ece5da` / dark `#372d3e`); разделители `--lv-line-2`; контролы `--lv-line-strong`.
- Витринные фото — **1:1** (full-bleed внутри карточки).
- Иконки — inline SVG из канона `lovii-design/icons` (lucide), размер по шкале 12/16/20/24/32.
- Визуальный результат менять нельзя — только структуру/переиспользование.

## 5. Задача для модели

Дать рекомендации по **архитектуре дизайн-системы**, чтобы:
1. Продуктовый CSS свернулся максимально (цель владельца — **≤~500 строк** для ДС-ядра).
2. Новые экраны **комбинировались из существующего**, не добавляя правил.
3. Оставалось динамичным (темы, варианты) и масштабируемым.
4. Не ломая текущий визуал и токены.

Ответьте по пунктам:
- Реалистично ли ≤500 строк на ВСЮ витрину? Если нет — почему и что именно укладывается в 500 (ДС-ядро vs продуктовые экраны)?
- Предложите структуру: токены → примитивы → компоненты с вариантами → утилиты. Что и чем управляется.
- Как масштабироваться без роста правил (комбинирование, варианты через атрибуты/модификаторы, CSS custom properties, `@layer`).
- Что конкретно из `lovii.css` можно объединить (кандидаты на слияние), а что принципиально не сворачивается.
- Риски и что потеряем.

## 6. Ограничения

- Без сборщика/препроцессора (статика + классические `<script>`).
- Нельзя менять визуальный результат.
- Нельзя плодить новые правила ради «красоты» — цель обратная.

## 7. Приложения

- `lovii.css` — продуктовый CSS витрины (главный объект аудита).
- `lovii-tokens.css` — токены (light/dark).
- `lovii-design-components.css` — компонентный слой канона (сравнить с продуктовым CSS).
