# Ресёрч: PWA-инцидент прода «не загрузить / войдите заново» — причины и лечение

Дата: 2026-10-07. Статус: на внешнем аудите. Составил: агент ZCode (3 ресёрч-потока: код lovii-app, история задач/сессий, живой прод app.lovii.ru — только чтение).

## 0. Симптом (владелец, прод, мобильные устройства)

«Не получилось загрузить приложение, войдите заново» — обновление страницы/закрытие не помогает;
застревают ВСЕ, кто когда-либо заходил на app.lovii.ru. Маркер из поля: тост
**«Не удалось открыть раздел. Полностью закройте и откройте приложение»** — это
`src/router/chunk-recovery.ts:76`, т.е. самолечение перезагрузкой уже отработало
и НЕ вылечило. Пользователь в петле устаревшего шелла.

## 1. Факты (проверено по коду и живому продy 07.10)

Прод (деплой 06.10 21:30, образ lovii-frontend:latest, свежий и корректный):

| Ресурс | Cache-Control | Примечание |
|---|---|---|
| `/` index.html | `public, max-age=60, must-revalidate` | 3 750 B, свежий |
| `/sw.js` | `no-cache` + `Service-Worker-Allowed` | skipWaiting+clientsClaim+cleanupOutdatedCaches есть |
| `/assets/index-*.js|css` | `immutable, max-age=31536000` | precache и html согласованы |
| `/version.json` | `public, max-age=300, must-revalidate` | `production·081496e2…·2026-10-06` |

`baseURL=void 0` в ТЕКУЩЕМ прод-бандле НЕ подтверждён (`baseURL:"https://api.lovii.ru"` на месте).

Механизмы самолечения, которые уже есть:
1. `initPwaShellGuard` (`src/package/global-helpers/pwa-update.ts`) — controllerchange→reload + ранний `registration.update()`. Ставится в `main.ts:25`.
2. `chunk-recovery.ts` — router.onError → полный переход, гард 10 с (sessionStorage), потом тост.
3. `ReloadPrompt.vue` — баннер «Доступна новая версия» (нужен КЛИК).
4. `ensureFreshVersion` (`src/modules/profile-settings/ProfileSettings.vue:124-136`) — сверка `/version.json` no-store vs `__APP_VERSION__` → `clearAppCaches()` + reload. **Вызывается ТОЛЬКО на onMounted экрана «Настройки».**
5. Ручная «Очистить кэш» (SZ-032) — там же в настройках.

## 2. Корневые причины (ранжировано)

**К1 — главный структурный дефект: сверка версии живёт внутри приложения и на глубоком экране.**
`ensureFreshVersion` выполняется только если приложение УЖЕ загрузилось и пользователь открыл «Настройки». Все механизмы самолечения (1–4) — это JS внутри бандла. Если бандл мёртв (baseURL=void 0, битый чанк) или пользователь не доходит до настроек — механизмов не существует. Серверного рычага нет.

**К2 — NavigationRoute отдаёт index.html из ПРЕКЭША, а не из сети.**
`navigateFallback: "/index.html"` + `createHandlerBoundToURL` — пока старый SW активен, каждая перезагрузка получает СТАРЫЙ index.html из precache. Если обновление SW не состоялось (мобильная сеть, троттлинг iOS standalone, сбой инсталла нового SW — любой фейл фетча precache-манифеста ставит инсталл на паузу), перезагрузка чинит ровно ничего → петля → тост chunk-recovery. «Полностью закройте и откройте» помогает только когда таки произойдёт навигационная проверка SW.

**К3 — [СНЯТА АУДИТОМ для прода] когорта с отравленным бандлом — только staging.**
Сессия 149 (`lovii-app/docs/sessions/149-staging-baseurl-deploy.md`): CI-сборка потеряла
`VITE_BACKEND_URL` → `baseURL=void 0`. По документам инцидент касался **staging**; прод был
исправен (аудит арены 07.10, живой бандл `baseURL:"https://api.lovii.ru"` подтверждён).
Механизм симптома остаётся релевантным для любых будущих ошибочных сборок: запросы на
собственный origin → SPA-fallback HTML → «generic» на экране входа (AuthCallCoders.vue:85).
Продовое поле объясняется К2+К1.

**К4 — вторичные дыры:**
- `version.json` кэшируется nginx 300 с — задержка обнаружения до 5 мин;
- версия НЕ запечена в бандл (в `__APP_VERSION__` она есть, но сравнения при буте нет);
- chunk-маркеры — строковые эвристики; при 2-м подряд фейле тост просит пользователя «закройте и откройте» вместо автоматической чистки кэша;
- runtimeCaching `api.lovii.ru` захардкожен в vite.config (staging-домен вне стратегии);
- legacy CacheFirst kuper-CDN (импорт выключен);
- `pwa-update.ts` не покрыт тестами.

## 4. Целевая механика (контракт версий, скорректирован по вердикту арены 07.10)

Принцип: решение о свежести принимает **index.html + сервер**, а не живой бандл.

⚠️ Поправка арены: inline-гейт — НЕ мгновенная разблокировка. Застрявшие клиенты получают
новый index.html только после обновления их SW (sw.js no-cache → обновление на следующем
заходе с сетью; skipWaiting+clientsClaim уже на проде). Подмножество со систематически
срывающейся установкой нового SW сервером недостижимо в принципе — класс закрывается
превентивно, не ретроспективно. Полный разбор — AUDIT-RESULT.md.

1. **Сервер-инициированно**: `/version.json` — единственный источник истины версии; nginx: `no-store` (вместо 300 с).
2. **Бут-гейт вне бандла**: инлайн-скрипт в `index.html` (исполняется до загрузки модулей, работает даже на мёртвом бандле): `fetch('/version.json?ts=…')` → сравнить с `localStorage.loviVersion` (запоминается при успешном буте) → расхождение → `unregister` всех SW + delete всех caches → reload (однократно, sessionStorage-гард). Нулевая сеть/offline — пропустить.
3. **В приложении**: `ensureFreshVersion` поднять в `main.ts` (бут + visibilitychange + интервал), убрать зависимость от экрана настроек.
4. **Навигация network-first**: NavigationRoute → network-first c фолбэком на precache index.html (offline остаётся). Убирает класс «старый шелл навсегда» (К2).
5. **chunk-recovery усиление**: 2-й подряд фейл → `clearAppCaches()` + reload автоматически, тост — только после 3-го.
6. **Наблюдаемость**: версия запекается в бандл (уже есть `__APP_VERSION__`) + лог бут-гейта в RUM-канал; при расхождении — счётчик «форс-обновлений».
7. **Приёмочный сценарий арены**: e2e «старый SW + намеренно сорванная установка нового SW» —
   проверить, что петля не вечна (гард) и что после восстановления сети самолечение доходит.

## 5. Критерии приёмки

- e2e-сценарий: устройство со старым SW+precache после деплоя новой сборки самолечится за ≤2 загрузки без действий пользователя (автотест через Playwright + отдельный SW-контекст).
- Симуляция К3 (сборка с baseURL=void 0): бут-гейт вычищает кэш и поднимает свежий бандл.
- Повторные загрузки не циклятся (гарды), offline-старт работает (precache-фолбэк).
