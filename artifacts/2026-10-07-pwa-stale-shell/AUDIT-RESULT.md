хаба не найден (проверены все remotes и 62 arena-ветки — ветки с этим пакетом не содержат).
Зафиксировано агентом ZCode по тексту вердикта для трассируемости.

## Выводы арены

1. **К2 подтверждена на живом проде**: sw.js обслуживает навигации через precache `/index.html`,
   ленивые чанки экранов в precache не входят → старый shell запрашивает удалённый hashed-чанк
   → 404 → повтор ошибки после перезагрузки. Для подтверждения конкретного полевого случая
   нужен trace с устройства.
2. **К1 подтверждена production-бандлом**: сверка `/version.json` живёт в модуле «Настройки»
   и запускается при открытии экрана. Текущая версия бандла совпадает с `/version.json`.
3. **К3 НЕ подтверждена**: документация относит сбой `baseURL=void 0` (session 149) к staging,
   прод был исправен. Приписывание этого случая продy в RESEARCH — ошибка; нужны доказательства
   именно ошибочной production-сборки (наличие таковой не установлено).
4. **Ф0 не доказана как разблокировка текущих клиентов**: новый inline-гейт не исполнится у клиента,
   пока старый активный SW продолжает отдавать старый index.html без гейта. Требуется сценарий
   «старый SW + намеренно сорванная установка нового».
5. Аудит исходников не завершён: у арены не было доступа к приватному `lovii-tech/lovii-app`
   (403) — владельцу проверить подключение GitHub в Arena. Токены не нужны.

## Решения агента по вердикту

- К3 снята с прод-объяснения: поле объясняется К2 (петля устаревшего шелла после серии деплоев)
  и К1. К3 остаётся историческим инцидентом staging (session 149).
- Ф0 переформулирована: inline-гейт — это НЕ «мгновенная разблокировка», это ворот после
  обновления SW; разблокировка застрявших идёт через штатное обновление SW (sw.js no-cache,
  skipWaiting+clientsClaim уже на проде) на следующем заходе с сетью. Подмножество, у которого
  установка нового SW систематически срывается, недостижимо сервером в принципе — класс
  закрывается превентивно (гейт) + e2e-сценарием арены (п.4) в приёмку.
