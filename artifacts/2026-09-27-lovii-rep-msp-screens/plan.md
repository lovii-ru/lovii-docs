## Состояния, которые обязан увидеть каждый воркер

- загрузка (скелет), пусто, ошибка, нет данных, отказ/отклонение — у каждого своя подача и тон;
- обе темы: светлая и тёмная;
- ширина 390 px (мобильный) — базовый сценарий; 768 px — как ведёт себя сетка.

## Метрики (замер в браузере, не «на глаз»)

1. Заголовок экрана — в шапке страницы, шапка вне `<main>`; в контенте `<h1>` быть не должно.
2. Вертикальный ритм: отступы/паддинги/гэпы — только токенами, литералы px запрещены.
3. Тап-зоны — ≥ 44 px, с учётом расширения через `::after` (иначе ложное срабатывание).
4. Контраст текст/фон — ≥ 4.5 (AA) в обеих темах, включая нажатое, выключенное и состояние загрузки.
5. Границы полей ввода — видимые, нейтральные, из канонных токенов.
6. Фактические данные: заполнены ли реальные поля (а не заглушки).

## Ход магистрали (со стороны API, не пересекается с воркерами)

**Находка 1 — очередь апрувов на стенде пустая не по вине экрана.**
`GET /api/v1/representative/approvals` отдаёт только заявки в статусе `awaiting_rep_approval`
(подтверждено чтением контроллера `ListApprovalsController`). В базе стенда таких не было
вовсе: сид создал `submitted` / `invoice_issued` / `verified` / `failed` — то есть очередь
представителя нельзя было увидеть ни разу. Данные восстановлены: 3 заявки переведены
в `awaiting_rep_approval` (Grand, ПАФФО, Пекарня «Заветный хлеб»), промокод приведён к AA2BTK.

**Проверено — поля для карточки апрува приходят в полном составе:**
`id, status, status_label, name, inn, activity_type, activity_type_label, address_line,
city_name, phone, promo_code, legal_name, legal_name_full, ogrn, created_at,
rep_approved_at, rep_rejected_at`. Юридические поля (юрлицо, полное юрлицо, ОГРН) на месте.

**Находка 2 — в заявке на выплату МСП реквизиты получателя пустые.**
`GET /api/v1/msp/payment` → `status: "failed"`, `status_label: "Заявку отклонили"`, при этом
`payee: { name: null, inn: null, account: null, bank: null }`. Экран не может показать,
куда уходят деньги. Требует проверки на экране: это заглушка, или данные действительно не
заполняются.

**Наблюдение 3 — `city_name` может быть `null` при заполненном `address_line`**
(заявка Grand). Если карточка где-то показывает город без запасного варианта, будет пустая
строка. Проверяется воркерами на экране.

**Проверено магистралью — экран «Заявки» представителя в состоянии списка (обе темы, 390px).**
Очередь отрисовалась: заголовок раздела «Представитель», подзаголовок «Очередь на модерации»,
счётчик «3 заявки», карточки с полями «ИНН 970512345688», «ОГРН», «адрес торговой точки».
Формулировка «торговая точка» — в каноне.
Тап-зон меньше 44px не найдено: единственные «мелкие» боксы — кнопки шапки, у обеих
расширение зоны нажатия через псевдоэлемент (117×44 и 44×44) — ложные находки.
Не проверено магистралью: состояния загрузки и ошибки (их закрывают воркеры),
полнота визуальных замеров (отступы, контраст) — за воркерами.
