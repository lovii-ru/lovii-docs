# Требования задачи (constraints.md)

Запрос владельца (дословно): «подготовь в документ текущий статус чтобы другой агент мог продолжить твою работу»

## Требования
1. Результат — ДОКУМЕНТ (готовый файл, не только ответ в чате). [явное]
2. Содержание — ТЕКУЩИЙ СТАТУС работы по переносу профиля LOVII из демо в клиент: что сделано, в каком состоянии код, что проверено, что не сделано, где открытые места.
3. Адресат — ДРУГОЙ АГЕНТ (или разработчик), который продолжит работу без доступа к этому диалогу: значит нужны точные пути, команды запуска, точки входа в код, критерии готовности, порядок следующих шагов, риски. [явное]
4. Язык документа — русский (язык последнего сообщения владельца). [явное]
5. Опираться на фактическое состояние рабочей копии, а не на память: пути файлов, git-состояние, результаты проверок. [inferred]
6. Формат: Markdown как основной агентский формат + HTML-версия для чтения глазами. [inferred]
7. Изменения не коммитить. [inferred: соответствует конвенции проекта, HANDOFF §1/§3]

## Ограничения
- Не раскрывать во внешнем виде документа внутренние рабочие детали (служебные имена процессов, стенограммы, внутренние id).
- Не выдумывать данные: неизвестное помечать как открытый вопрос.
- Файлы вне workspace читаются через exec (доступ к файловой системе у инструментов ограничен рабочей папкой).
