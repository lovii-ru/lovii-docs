# 2026-09-27-msp-cabinet-deliverables — кабинет МСП: разбор, сценарий, сид

Пакет по кабинету МСП (самый критичный экран). Собрано в сессии, где роль агента — помогать владельцу
проходить сценарий подключения точки и приводить экраны в порядок.

## Что в пакете

| Файл | Что это |
|---|---|
| `docs/cabinet-review/index.html` + `assets/` | Разбор кабинета МСП: демо против стенда, построчное сравнение, диагноз (дробление карточек, теснота, обрезка, конкурирующие CTA), план |
| `docs/scenario-map/index.html` | Карта сценария подключения точки: что создаёт одна заявка, порядок шагов, шпаргалка статусов |
| `docs/seed/index.html` + `assets/` | Сид МСП и путь верификации: что заведено, причина путаницы (`partner_memberships` пустая), где нажимать «Я оплатил» |
| `docs/system-status/index.html` | Сводка состояния системы: стенды, коммиты исполнителя, блок CI/раннера, план до прода |
| `sql/seed-msp.sql` | Скрипт сида: клонирование строк-образцов с подменой колонок (3 юрлица, мерчант, 2 точки, членство, заявка на стадии счёта) |
| `screens/` | Кадры: демо/стенд кабинета МСП, сравнение, шаги сценария нового пользователя (дом, профиль, ЛОВИ Бизнес, заявка, кабинет МСП), счёт верификации |

## Как снято

Локальный стенд приложения (`:5173` / актуальный `:5175`), демо-витрина (`:8090`), Chrome/Playwright
390px, светлая тема. Данные — локальный core. Вход тестовый: `+7 000 000-00-01`, код `1234`.

## Факты, важные для продолжения

- Кабинет МСП ищет юрлица через `partner_memberships`; таблица была **пустой** → кабинет выглядел пустым.
  Сид её заполняет (членство владельца).
- Одна заявка создаёт юрлицо + членство + бренд (`pending_moderation`) + точку (только при наличии
  координат адреса) + саму заявку.
- Тестовая маска `+7 000…` требует `OTP_TEST_REDIRECT_ENABLED=true` (включено локально в `lovii-core/.env`).
- Профильный промокод резолвится мягко: неактивный код даёт путь `submitted` без счёта. У тестового
  пользователя промокод переведён на активный `AA2BTK`.
