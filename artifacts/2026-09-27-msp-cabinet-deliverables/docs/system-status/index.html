CI и деплой — что мешает

Джобы обоих репозиториев (lovii-app, lovii-core) всё ещё идут на GitHub-хостовом раннере (runs-on: ubuntu-latest) и падают за 5 секунд — это блок биллинга организации. Self-hosted раннер заведён, но только на core (gostiny-ci-core, online); у app раннеров 0, а workflow на него не переключён.

План, чтобы «продолжить деплоить в прод»

  1. Разбудить CI: добавить self-hosted раннер для lovii-app (+ b2b/admin) и переключить runs-on на свои метки — тогда checks и деплой пойдут без GitHub-хоста. Это задача zcode; я готов собрать точную постановку и критерии.
  2. Стартовый деплой на staging из ветки staging с проверкой health — там вы принимаете работу.
  3. Дизайн новых экранов — на демо (:8090): следующий экран по списку; собранное переносим на стенд и в постановку zcode.
  4. Прод — только когда staging-приёмка пройдена (ручной запуск по канону).
