# СЦЕНАРИЙ СЕССИИ: полный проход через app — «приглашение МСП → выдан покупателю»

> Подготовлено 09.10 по запросу владельца. Сессия следующего запуска.
> Стенд: **staging** (app-staging.lovii.ru / api-staging.lovii.ru / b2b-staging).
> Прод не трогаем. Обязательно к прочтению перед стартом:
> `canon/TEST_PROFILES.md` (картотека+правила), `tools/stage-actor.py` (раннер),
> `lovii-app/e2e/README.md` (авторизация/сеть), `canon/PRODUCT_QUALITY_BAR.md`.

## 1. Цель

Полный продуктовый проход через клиентское приложение по цепочке:

```
приглашение по промокоду владельца → регистрация нового МСП → заявка МСП
(ИНН, компания) → подтверждение торговой точки через мок → каталог (тестовые
товары) → точка на карте (СПб, ул. Белы Куна, 3) → заказ с доставкой с профиля
владельца → оплата (мок) → статусы до «Доставлен» (= выдан покупателю) → чек.
```

Побочная цель: проверить, что после вчерашних фиксов b2b (redis, security,
чеки, статусы) весь контур живёт в связке app ↔ core ↔ b2b.

## 2. Актёры

| Роль | Кто | Данные |
|---|---|---|
| **Владелец** (покупатель+промо-источник) | Основатель, user 1 | +79119287478, код представителя **AA4A4E** (representative_promo_codes user 1; амбассадорский AAAAAA — НЕ его, для ветки «приглашение представителя» нужен именно AA4A4E) |
| **Новый МСП** (наш персонаж) | одноразовый актёр | **+79009990006** (свободный; 004/005 заняты NEW-1/NEW-2). Имя в e2e: «Пекарь Белы Куна» |
| Точка персонажа | мерчант+точка актёра | СПб, **ул. Белы Куна, 3**; каналы: самовывоз ВКЛ + **доставка ВКЛ** |
| Каталог персонажа | 2–3 позиции | например «Пирог с картошкой» 180₽, «Кулебяка» 320₽, «Расстегай» 150₽; остатки по 20 шт |

ИНН персонажа: сгенерировать `stage-actor.py` (валидная контрольная сумма),
НЕ дублировать существующие (T-027: уникальность ИНН).

## 3. Пошаговый сценарий

### Этап A — персонаж: регистрация по промокоду владельца
1. Апп-стейджинг, гостевой вход: номер +79009990006, канал sms/Telegram,
   код `1234` (или `GET /api/v1/dev/otp/last-code?phone=…`).
2. Привязать промокод представителя владельца: **AA4A4E** (bind-promo / поле при заявке —
   как в реальном онбординге; привязка представителя фиксируется в момент
   создания заявки).

### Этап B — заявка МСП
3. Создать заявку МСП: название «Пекарь Белы Куна», ИНН из генератора,
   `promo=AA4A4E`. Проверить в ответе/профиле: привязка к Основателю
   (приглашение от владельца работает).
4. Статус заявки: submitted → **счёт верификации VER-\*** (1₽).

### Этап C — подтверждение через мок
5. Оплатить счёт верификации **через мок-банк** staging
   (mock-pay-staging.lovii.ru, успешный сценарий). Если вебхук подтверждения
   не настроен — подтвердить штатным manual-путём (как раньше), но отметить
   в отчёте, что в staging мок-контур включён и должен срабатывать сам.
6. Заявка → verified: у актёра появляются мерчант + точка. Партнёр-доступ
   актёра в b2b-staging (вход по его номеру, OTP 1234).

### Этап D — точка и каталог (b2b-кабинет актёра)
7. Точка: адрес **СПб, ул. Белы Куна, 3** (геокодер Yandex на staging
   работает — проверить пин на карте), расписание, каналы: самовывоз вкл,
   **доставка вкл** (радиус/fee — дефолт).
8. Товары: 3 позиции из таблицы выше (категория, цена, остаток, фото
   опционально). Проверить позицию на витрине app рядом с точкой.

### Этап E — заказ с профиля владельца
9. Выйти/перелогиниться в app как **Основатель** (+79119287478).
10. Витрина: найти точку «Пекарь Белы Куна» (поиск/рядом), **доставка**
    на адрес владельца (близкий к Белы Куна, 3 — чтобы зона доставки
    покрыла), корзина 2 позиции, чекаут: промо/балансы не трогаем
    (чистый кейс), оплата картой через **мок-банк**.
11. Оплата confirmed → заказ оплачен, чек prepayment/full по канону 54-ФЗ.

### Этап F — статусы до «выдан покупателю»
12. Актёр (второй профиль/вкладка) в b2b-кабинете проводит заказ по доске:
    **Принят → Готовится → Готов → Передан курьеру → (В пути) → Доставлен**.
    После каждого шага — в app владельца статус обновляется; push
    (если подписан).
13. Финал: статус «Доставлен» (= выдан покупателю) в app и в b2b; чек
    full_payment confirmed; в app доступна квитанция + «Поделиться» чеком.

## 4. Проверки приёмки (что считается успехом)

- [ ] Привязка промокода AA4A4E к заявке персонажа (владелец = представитель; сеть владельца).
- [ ] Заявка → verified через мок без ручного вмешательства.
- [ ] Точка на карте по адресу Белы Куна, 3; доставка доступна владельцу.
- [ ] Заказ оплачен моком; оба чека confirmed (54-ФЗ); «Поделиться» работает.
- [ ] Все статусы проведены из b2b-кабинета актёра без ошибок в логах
      (проверить laravel.log b2b/core: нет 409 sz037 — после вчерашнего
      dead-letter должен быть skip+warning в худшем случае).
- [ ] Сессии/балансы: леджер заказов сведён (Σ=0) — опционально.

## 5. Грабли и правила

- OTP: 2/мин на телефон; бипас 1234 только staging; прод-номера не трогать.
- Актёров картотеки (ACT-*, NEW-*) не использовать для грязных сценариев —
  наш персонаж одноразовый (+79009990006), данные чистить в конце (§4
  TEST_PROFILES), номер можно оставить под повтор сценария.
- e2e на staging гонять как есть (network-грабли учтены в helpers).
- Не путать: деньги реальные не ходят — мок-банк staging.
- Все находки/баги — в session-док lovii-app + BACKLOG по правилам §0.2.
- Прогон НЕ через e2e-спеки, а руками в UI (это продуктовая приёмка, не
  регресс) — e2e-спеки можно гонять отдельно как дым.
