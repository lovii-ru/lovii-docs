# screens/ — скриншоты экранов: версии и визуальный контроль

**Что это.** Живой каталог кадров приложения LOVII по каждому экрану (ID карточек
`../canon/APP_PAGES/` — `APP-P-001…APP-P-060`). Назначение — визуальный контроль интерфейсов:
сверка с дизайн-системой, поиск отклонений и проблем, фиксация «до/после» каждой правки.

**Главное правило — append-only.** Каталог только растёт: новая версия = новая папка
`vN-YYYY-MM-DD/` внутри папки экрана + новая строка в `_VERSIONS.md`.
**Старые версии никогда не удаляются и не перезаписываются.**

## Структура

```text
screens/
├── README.md               ← этот документ (инструкция)
├── _VERSIONS.md            ← журнал версий (append-only)
├── _tools/
│   └── screens-publish.mjs ← публикация новой версии из каталога съёмки
└── APP-P-001-home/         ← папка на каждый экран (имя = ключ карточки канона)
    └── v1-2026-10-02/
        ├── default.png     ← основной кадр версии
        ├── guest.png       ← дополнительные состояния (по имени состояния)
        └── meta.json       ← метаданные среза
```

## Как добавить новую версию (пошагово)

1. **Сними кадры.** Инструмент — Playwright-каркас приложения; спеки и скрипты лежат в пакете
   [`../artifacts/2026-10-02-t032-app-pages-screens-deliverables/capture-toolkit/`](../artifacts/2026-10-02-t032-app-pages-screens-deliverables/README.md).
   Полный прогон — команды из README пакета; **точечно один экран** — добавь к запуску
   `PAGES_SHOTS_ONLY=APP-P-046-msp-orders` (можно несколько через запятую) и секцию `-g`.
   Кадры подмножества складывай в **отдельный** каталог (например `.cluster/app-pages-shots/snapshots/<дата>/`),
   не смешивая с baseline.
2. **Опубликуй версию:**
   ```bash
   node screens/_tools/screens-publish.mjs \
     --from  <каталог со снятыми кадрами> \
     --to    lovii_docs/screens \
     --version auto --only APP-P-046-msp-orders \
     --note  "правка T-0XX: <что изменилось>"
   ```
   Скрипт создаст `v{N+1}-<дата>/`, разложит кадры (`default.png` + состояния), запишет
   `meta.json` и допишет строку в `_VERSIONS.md`. Существующие версии не трогаются.
   Явная версия: `--version v2-2026-10-05`; если папка уже существует — предупреждение и пропуск.
3. **Проверь публикацию (чек-лист):**
   - в папке версии — все ожидаемые состояния, размеры вменяемые;
   - `meta.json` заполнен (стенд, срез, дата, маршрут, состояния);
   - строка в `_VERSIONS.md` добавлена, предыдущие строки на месте;
   - `git status` в `lovii_docs` показывает только **добавления** — ничего не удалено и не перезаписано.

## Именование состояний

- `default.png` — основной кадр (обязателен);
- согласованные состояния: `guest.png`, `as-is.png`, `history.png`;
- свободные имена (`empty.png`, `error.png`, …) допустимы — опиши их в `meta.json` → `states`.

## _VERSIONS.md

Одна строка на версию экрана: `| Дата | Экран | Версия | Каталог | Комментарий |`.
Строки не удаляются; ошибку правим новой строкой. Новые строки — в конец файла.

## Визуальный контроль (сценарий использования)

- **Эталоны для сверки:** `../canon/DESIGN.md`, дизайн-система `lovii-design` / витрина `lovii-demo`,
  стандарт [`../canon/PRODUCT_QUALITY_BAR.md`](../canon/PRODUCT_QUALITY_BAR.md)
  (скрин-тест «премиальный банк», три состояния экрана, адаптив, честные цифры).
- **Правка экрана:** снять новую версию затронутого экрана (и зависимых) → сравнить `v(N−1)` ↔ `vN`
  → отклонения оформить задачей в каноне со ссылкой на `APP-P-NNN` и на обе версии кадров.
- **Порядок разбора:** сначала отклонения интерфейса от дизайн-системы, затем функциональные проблемы;
  найденное — в `FINDINGS` пакета baseline (см. ниже) и/или отдельными задачами.

## Ограничения и правила честности

- Кадры содержат данные тест-профиля стенда: **не публиковать вне контура проекта** (лендинг/публичные каналы).
- По умолчанию снимается светлая тема; тёмная тема и edge-состояния — отдельной версией при необходимости.
- Full-page артефакт: фиксированный нижний таб-бар рендерится один раз в середине длинного кадра —
  это поведение инструмента, не дефект UI (описано в README пакета).
- Кадры «протухают» при дрейфе данных стенда; каждый срез фиксируется датой в `meta.json` и `_VERSIONS.md`.
