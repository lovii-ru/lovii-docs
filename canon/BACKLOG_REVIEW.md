**★ Подсказка для zcoder'а (A2):**
- Это БОЛЬШАЯ задача. Скорее всего, разобьётся на 2–3 карточки:
  - `SZ-NNN-sub-domain` — модель подписки + миграции (active/expired/grace/suspended)
  - `SZ-NNN-sub-billing` — cascade + retry policy + grace period
  - `SZ-NNN-sub-price-lock` — отдельная логика цены 199₽ для текущего владельца
- Логика каскада — это **state machine** на подписке. Используй enum
  `SubscriptionStatus` (вероятно уже есть) с состояниями
  `Active → GracePeriod → Suspended → Cancelled`.
- Каскад «LOVII Business → LOVII PAY → внешняя карта»:
  - Business = `accounts` где `owner_type=partner` + `kind=business`
  - PAY = `accounts` где `owner_type=user` + `kind=personal` (или новый `kind=pay`)
  - Внешняя карта = нужно завести таблицу `external_payment_methods`
- Grace period 48ч: `expires_at + 48h` = конец grace. Если оплата пришла в окне —
  восстановить, иначе → Suspended. Возможно, через `Carbon::now()->lt($grace_end)`.
- Retry каждые 6ч, первая 09:00 МСК: cron-задача, лучше через Laravel Scheduler
  (есть `app/Console/Kernel.php`). Регистрируется в существующем `routes/console.php`
  или kernel — выбери место по конвенции репо.
- Учти: реализация цены 199₽ vs 599₽ уже частично обсуждалась (см. SZ-038 в

### A5. Push / Pull каналы выплат

| Параметр | Решение | Канон (PARAMS §1.6) | Согласовано? |
|---|---|---|---|
| Push (ИП/ООО): авто-суточный | **Каждый день** по итогу финансового дня | «Push-вывод: ежедневно, по завершении финансового дня» | ✅ |
| Комиссия push | **0.5%** покрывает ОПЕРАТОР | «0,5% — Компания» | ✅ |
| Мин. порог push | **Нет** (батчинг) | «без порога» | ✅ |
| Pull (НПД): ≥ 3 000 ₽ | **1% покрывает ОПЕРАТОР** со своего счёта, **получатель = 100%** | «1% (min 100 ₽) — Компания» | ⚠️ см. §C #1 (разъяснено 2026-09-17) |
| Pull (НПД): < 3 000 ₽ | **30 ₽ фикс** удерживается из суммы | «30 ₽ — Получатель» | ✅ |
| Pull (НПД): мин. сумма вывода | **100 ₽** | Не зафиксировано | ✅ решено 2026-09-17 |

**Разъяснение владельца (2026-09-17, ~22:10):**
- Комиссия банка для ОПЕРАТОРа **всегда 1%** на вывод физлицам-самозанятым.
- Мин. сумма вывода: **100 ₽**. Если сумма < 3 000 ₽ — комиссия **30 ₽ фикс** из суммы.
- Если сумма **≥ 3 000 ₽** — комиссия ОПЕРАТОРа **1% от суммы вывода** со своего счёта,
  **пользователь получает без комиссии всю сумму**.
- Примеры: вывод 100 ₽ → -30 ₽ комиссия, получатель 70 ₽. Вывод 2 900 ₽ →
  -30 ₽ комиссия, получатель 2 870 ₽. Вывод 3 000 ₽ → ОПЕРАТОР платит 30 ₽
  (= 1% от 3 000), получатель 3 000 ₽. Вывод 100 000 ₽ → ОПЕРАТОР платит 1 000 ₽,
  получатель 100 000 ₽.

**Расхождение с каноном (требует правки владельца в `canon/PARAMS.md §1.6`):**
- Канон: «1% (min 100 ₽) — Компания». В новом решении владельца «min 100 ₽»
  отсутствует. По разъяснению — ОПЕРАТОР платит ровно 1% (например, на 3 000 ₽ —
  30 ₽, не 100 ₽). Это меняет канон.
- Задача zcoder'а: реализовать **по разъяснению** (1% точно, без min floor).
- Параллельно: владелец правит канон `canon/PARAMS.md §1.6` — убирает «(min 100 ₽)».

**★ Подсказка для zcoder'а (A5):**
- Это ГЛАВНЫЙ блокер пилота — без авто-выплат деньги копятся у платформы,
  партнёры их не получают.
- Каркас `LedgerEntryType::Payout` уже объявлен, но использований 0 (FINDINGS F-049).
  Это и есть точка входа.
- План реализации:
  1. **Модель/миграция:** `payout_schedules` (для push: partner_id, scheduled_for,
     amount, status) и `payout_requests` (для pull: user_id, amount, commission,

  2. **Cron `payouts:process-push`** — Laravel Scheduler, ежедневно 09:00 МСК:
     собрать всех ИП/ООО с `accounts.kind='business'` и `balance > 0`,

(`'timezone' => 'Europe/Moscow'`) и тогда `dailyAt('09:00')` будет МСК.
