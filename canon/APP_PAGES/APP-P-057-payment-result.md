# APP-P-057 — Результат оплаты заказа
- Статус: живая
- Маршрут: `/payment/result?order={id}` · name `PaymentResultView` (src/router/index.ts:941)
- Тип: обычная (в MainLayout, группа /payment)
- Доступ: авторизован — beforeEnter без loviAccessToken → APP-P-008 (index.ts:946–953); order в query обязателен, иначе replace в APP-P-015
- Назначение: финал цепочки оплаты заказа покупателем: ждём подтверждение банка (авто-опрос), оплачено (квитанция) или не прошло (заказ сохранён).
- Функциональные блоки:
  - #pending — «Оплачиваем заказ»: спиннер + «Форма оплаты открыта…» (в т.ч. после «двух тапов» на чекауте, когда банк открылся на новой вкладке); кнопка «Я оплатил — проверить» (refresh: сброс лимита + запрос) и «Оплатить позже» → APP-P-015; авто-опрос статуса каждые 2 с, до 15 попыток (PaymentResultView.vue:39–69)
  - #paid — «Заказ оплачен» (payment.status ∈ authorized|confirmed): квитанция OrderReceipt + «К заказам» (PaymentResultView.vue:94–105)
  - #failed — «Оплата не прошла» (status ∈ rejected|expired|canceled|reversed|refunded|failed): «Заказ сохранён — оплатить можно позже в истории заказов» (PaymentResultView.vue:107–112)
  - #fetch — `GET api/v1/profile-orders/{id}` (apiGetProfileOrder), ошибка загрузки — текст в pending-состоянии (PaymentResultView.vue:42–57)
- Состояния: pending (спиннер, авто-опрос) / paid / failed; битый/чужой order — редирект в историю заказов
- Зависимости: API profile-order/api/profile-order-api.ts (apiGetProfileOrder); компоненты OrderReceipt.vue, AppPageHeader (back → OrdersView); стор payment.store.ts (запуск оплаты — на чекауте)
- Переходы: → APP-P-015 (история заказов, все кнопки); ← APP-P-058 (после «оплаты» в заглушке — replace с query order), чекаут APP-P-007 (redirect банка)
- Дизайн/канон — проверить визуально: 3 состояния, честные цифры (сумма в квитанции), токены ДС (плитка 80×80 с глифом набора — без эмодзи/«✓»), a11y; нейтральные токены клиента (не ролевые акценты)
