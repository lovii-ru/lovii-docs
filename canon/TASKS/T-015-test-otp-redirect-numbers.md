# T-015 — Тестовые OTP-номера: маска +7 000… с доставкой кода владельцу

> Статус: **На приёмке** (реализована AutoClaw 23.09 — core `dad7f84`, CI+deploy 🟢; постановка Super Z по запросу владельца 22.09)
> Приоритет: **P1** — разблокирует сценарий «новый пользователь» живой приёмки
> Блока А (пункт B2(а) T-014, гейт промокода SZ-057)
> Исполнитель: AutoClaw (код-агент) · Репо: `lovii-core` (транспортный слой OTP) · Постановка: Super Z

## Проблема

Живая приёмка не может завести **нового** пользователя: произвольный номер не
привязать к OTP-каналу (бот не пишет первым, SMS-канал не доставляет код на
неподготовленный номер). Из-за этого не проверяются живьём: честный 403
кабинета представителя (T-014 B2а), гейт подписки «только по промокоду»
(SZ-057), сценарий «без средств» (SZ-056).

## Решение владельца (предложение 22.09, принято к постановке)

Маска тестовых номеров: все номера вида **+7 000ХХХ-ХХ-ХХ** → код OTP
доставляется **владельцу** на выбранный им канал (бот/SMS), а не адресату.

## Что сделать

1. Редирект — **в транспортном слое OTP** (не в бизнес-логике гейтов):
   распознавание маски +7 000… → доставка кода на телефон владельца выбранным
   каналом. Способ реализации — на усмотрение исполнителя, каждый выбор
   фиксируется в отчёте.
2. Гейт по окружению: только не-прод (env-флаг, например
   `OTP_TEST_REDIRECT_ENABLED` — true на staging; на проде флаг запрещён).
3. Поведение на проде — **решение владельца** (риски ниже). Минимально
   безопасный вариант по умолчанию: маска на проде запрещена (отказ
   регистрации/выдачи кода с честным текстом), редирект не включается никогда.
4. Лог каждого редиректа: целевой тестовый номер, канал доставки, время.
5. Документация: маску не публиковать в публичных документах (только внутренние).

## Риски (обязательны к фиксации в отчёте)

- На проде маска = привилегированный доступ: владелец получает коды от чужих
  аккаунтов, публичная маска открывает спам-канал на телефон владельца и делает
  все +7 000-аккаунты фактически недоступными обычным пользователям.
- Маска не должна обходить rate-limit и антифрод OTP-сессий.

## Границы

- Канон T-010 (привязка `users.promo_code`) и транспортные контракты
  (`docs/specs/otp-delivery-channels.md`) не ломать.
- Зона core-billing не трогается (WORK_PROTOCOL §1.2).

## Разведка нового исполнителя (23.09) — факт-чек Super Z по origin/staging `16e062b`

- Нет единого транспортного слоя: общая точка доставки —
  `OtpSenderContract::send()`, вызов `app/Application/Auth/Actions/SendOtpAction.php:114`.
  НО MAX/TG/VK паркуются раньше (:65, :74–83, :92–101 — ранний
  `return linkRequired()` с binding_token): редирект маски обязан стоять
  ДО точки парковки (уровень решения о доставке), иначе тестовый номер
  получит «привяжите канал» вместо кода. Принцип постановки «в
  транспортном слое, не в бизнес-логике гейтов» остаётся в силе.
- E.164-регулярка `^\+[1-9]\d{7,14}$` встречается в 5 местах
  (SendOtpRequest:17, RequestOtpRequest:15, ConfirmOtpRequest:15,
  CreatePartnerApplicationRequest:31, Dev/OtpLastCodeController:17) —
  маска +7 000… формально ПРОХОДИТ её (первая цифра после «+» = 7, нули
  дальше попадают в `\d{7,14}`); фронтовый гейт — только minLength(16)
  маски (app `use-phone-form.ts:13`). Утверждение разведки «маска не
  проходит валидатор» не подтвердилось; живой прогон маски остаётся
  пунктом приёмки.
- `config/otp.php:17`: `dev_bypass` по умолчанию `true` — новый флаг
  редиректа обязан дефолтиться `false` и гейтиться окружением (усиление
  п. 2 постановки).

## Решения (23.09, по отчёту исполнителя — выбор владельца через Super Z)

- **Размещение — вариант (б):** резолвер эффективного телефона
  `(phone, channel) → effectivePhone` срабатывает **до** гейтов/парковки
  (телефон сессии остаётся маской). Принцип «не в бизнес-логике гейтов»
  читается как «не в логике гейтов ролей/подписки» — контур доставки OTP
  здесь и есть транспортный слой; буквальной общей точки send() для всех
  каналов в коде нет (парковка MAX/TG/VK раньше).
- Новый флаг (например `OTP_TEST_REDIRECT_ENABLED`): default `false`,
  env-гейт не-прод; **на проде маска запрещена** — отказ регистрации/выдачи
  кода с честным текстом (минимально безопасный вариант по умолчанию).
- Лог каждого редиректа: целевой тестовый номер, канал, время (п. 4
  постановки) — обязателен.

## Отчёт исполнителя (AutoClaw код-агент, 2026-09-22)

**Коммит:** `lovii-core` `dad7f84` (в `staging` вместе с T-016, tip `27f9b54`), запушен; CI run 35680798035 — `checks` 🟢, `deploy-staging` 🟢 (стенд `/opt/lovii-core-staging` на `27f9b54`).

**Где редирект:** новый сервис `app/Domain/Auth/Services/OtpDeliveryTargetResolver.php`; вызов в `SendOtpAction` сразу после `createSession(...)` и ДО гейтов каналов и доставки. В проверки привязки и в `send()` идёт эффективный телефон; сессия/cooldown/профиль/dev-стор — по маске.

**Маска:** одна константа `TEST_PHONE_PATTERN = '/^\+7000\d{7}$/'` («+7 000ХХХ-ХХ-ХХ» → `+7000` + 7 цифр). E.164-регексы не тронуты.

**Env/флаги:** `OTP_TEST_REDIRECT_ENABLED` (default `false`), `OTP_TEST_REDIRECT_TO` (телефон владельца). Оба добавлены в `config/otp.php` и `.env.example`.

**Формат лога:** `logger()->info('otp.test_redirect', ['test_phone', 'delivery_phone', 'channel', 'at'])` — на каждый редирект.

**Поведение по окружениям:** production + маска → `otp_test_phone_forbidden` (отказ); не-прод + маска + флаг off → `otp_test_phone_disabled`; не-прод + флаг on + задан получатель → лог + доставка владельцу; получатель не задан → `otp_test_redirect_misconfigured`. Все отказы — 422 с честным текстом.

**Гейты (локально):** pint 979 files PASS, rector [OK], phpstan «No errors», pest 1449 passed (type-coverage 99.0%).

**Стенд (проверено AutoClaw):** POST `/auth/send-code` маска `+70001234567` → HTTP 422 `otp_test_phone_disabled` (флаг по умолчанию выключен — безопасный дефолт подтверждён); обычный номер не затронут (200).

**Осталось (участие владельца):** включить `OTP_TEST_REDIRECT_ENABLED=true` + `OTP_TEST_REDIRECT_TO=<номер владельца>` на staging (с бэкапом `.env` и рестартом), затем живой прогон маски → код владельцу → B2(а) T-014. Маску в публичные доки не выносить.
