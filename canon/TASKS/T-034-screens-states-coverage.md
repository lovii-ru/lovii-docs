## Контекст

Скрин-пакет T-032 ([`artifacts/2026-10-02-t032-app-pages-screens-deliverables/`](../../artifacts/2026-10-02-t032-app-pages-screens-deliverables/README.md),
галерея `screens-gallery/`, манифест 57 карточек APP-P-001…060) покрывает
только **верхний уровень страниц**: списки и хабы. Пользовательские формы,
мастера, модалки и состояния экранов не отсняты и визуально никогда не
контролировались. Подтверждение по коду `lovii-app`:

- **Добавление товара / создание-переименование категории** — состояния одного
  экрана `src/modules/roles-module/msp/MspProducts.vue` (переключатель
  «Товар | Категория», режим правки) — в галерее только список;
- **5 типов акций** — визард `msp/loyalty/LoyaltyRuleWizard.vue` с
  `MechanicPicker.vue`; механики в `mechanicOptions()` (`msp/loyalty.ts`):
  `threshold` «Сумма чека», `combo` «Комбо», `stamps` «Штампы — N-й в подарок»,
  `hours` «Счастливые часы», `cashback` «Группа товаров»; спутники:
  `LoyaltyGroupEditor`, `StampCard`, `BudgetMeter`, `BuyerPreview`, `DayChips`.

Источник пропусков — состояния живут в компонентах **без собственного роута**,
поэтому инвентаризация по роутеру (`src/router/index.ts`) недостаточна: нужен
обход компонентов.

## Что сделать

1. **Инвентаризация (read-only).** Пройти `src/router/index.ts` + компоненты
   `src/modules/` (прежде всего `roles-module/msp/`, `roles-module/team/`,
   `business-module/`, `profile-*`, `payment/`, `loyalty/`); сверить каждый
   роут с манифестом галереи. Составить реестр трёх категорий:
   1. отдельные страницы без скрина;
   2. **состояния существующих страниц**: формы, визарды, модалки,
      confirm-диалоги, empty/error/loading по `PRODUCT_QUALITY_BAR`;
   3. ветвления по данным (механики акций, настройки точки с доставкой/без,
      приглашение в команду SZ-047, каскад юрлицо→мерчант→точка SZ-076).
   Реестр — `artifacts/2026-10-03-t034-screens-states-inventory/INVENTORY.md`:
   ID, где в коде (file:line), приоритет (P0 = коммерческий путь МСП).
2. **Съёмка.** Локальный стенд :5174 (тест-данные по канону T-025 — Ромашка,
   точки 670/671; не засорять staging). Каждое состояние — в
   `screens/<slug>/v1-2026-10-03/` (правила версионирования — `screens/README.md`);
   состояния существующих страниц — как `extras` в манифесте, не новые карточки.
   Для 5 механик — по кадру шага визарда с выбранной механикой + шаг
   предпросмотра/подтверждения, если есть.
3. **Галерея и ревью-страница.** Обновить `screens-gallery/manifest.json` и
   `gallery.html` (новые карточки в существующих группах; состояния — миниатюры
   в карточке страницы). Собрать `screens-gallery/review-2.html`: только новые
   и изменённые экраны, чек-лист ревью из `PRODUCT_QUALITY_BAR` (канон ДС,
   три состояния, адаптив, честные цифры, a11y), поле вердикта по каждому
   экрану (ok / правка + комментарий) — для прохода владельца по образцу T-033.
4. **Фиксация.** Регистрация пакета в `artifacts/REGISTRY.md`, ссылка из этой
   карточки (Отчёт), session-дока, обновление `canon/STATUS.md`.
