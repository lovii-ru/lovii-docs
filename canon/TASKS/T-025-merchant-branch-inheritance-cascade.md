# T-025 — Каскад каталога и лояльности: наследование «мерчант → точки» с переопределением на точке

> Статус: **Открыта** (канон утверждён владельцем 27.09 в чате)
> Приоритет: **P1** (разблокирует решения владельца по настройкам МСП при нескольких мерчантах/точках)
> Исполнитель: **zcode** · Репо: `lovii-core` (модель, если нужен док-тип) + `lovii-app` (UI выбора области применения) + `lovii_docs` (session-доки)
> Зависимости: каскад «юрлицо → мерчант → точка» (восстановлен, ветка `sz076-merchant-cascade-restore`); каталог типов T-023 Фаза A

## Канон (утверждено владельцем, 27.09)

Принцип «**мерчант = дефолт для всех точек; точка = точечное переопределение; точка всегда сильнее**»:

1. **Область применения** при создании сущности (товар/позиция каталога, группа или
   акция лояльности) — явный выбор:
   - «**Всему мерчанту**» → действует во всех существующих и будущих точках мерчанта;
   - «**Конкретной точке**» → выбор точки из каскада, действует только на неё.
2. **Модель данных** (уже существует в ядре): `merchant_offers.branch_id` —
   `NULL` = уровень мерчанта (все точки), значение = только эта точка.
   Для лояльности — тот же паттерн (привязка к мерчанту vs к точке).
3. **Переопределение без конфликта**: точечная правка создаёт точке собственную
   запись (override-строку), шаблон мерчанта не трогается.
4. **Правило разрешения**: точечная запись всегда перекрывает мерчант-шаблон;
   удалил точечную — снова действует шаблон мерчанта.
5. **Наглядность**: в списках позиций/акций — метка области действия
   (пилюля «Весь мерчант» / «Точка: <название>»).
6. Тот же принцип — для будущих сущностей кабинета МСП (настройки точки,
   расписания и пр.), не только каталог/лояльность.

## Дополнение 27.09 (вопрос владельца «как задать категорию?»)

Выяснено: в кабинете МСП (app) категории **не реализованы** — товар из формы
создаётся с `category_id = null` (витрина показывает его без группировки).
Категории платформы привязаны к мерчанту (`catalog_categories.merchant_id`) и
создаются через b2b-панель (Filament CategoryResource).

**Добавляется в скоуп T-025 (Фаза Б-кат):**
- UI «Категории» в кабинете МСП: создание/список категорий мерчанта
  (core API: CRUD `catalog_categories` scoped по merchant_id);
- выбор категории в форме товара (+ опция «без категории»);
- витрина: группировка по категориям уже работает (GetStorefrontCatalogQuery).

До реализации — заводить категории Ромашке через b2b-панель (вручную).

## Фазы (набросок, детализирует исполнитель)

- **Фаза А** — сверка модели: `merchant_offers.branch_id` (NULL-семантика), лояльность
  (привязка групп/акций), кейс «точка переопределяет товар мерчанта».
- **Фаза Б** — UI: переключатель области применения в формах создания
  (товар/группа/акция), метки области действия в списках, фильтр по каскаду
  (выбранный мерчант → его шаблон + точки).
- **Фаза В** — переопределения: точка правит «свой» товар → override-строка;
  правило разрешения в выдаче витрины/поиска.
- **Фаза Г** — приёмка: сценарий владельца «добавил каталог всем точкам → добавил
  конкретный товар конкретной точке → другой мерчант не задет».
