# SZ-017 — Квитанция заказа (I-2): информационное подтверждение до фискального чека

> Статус: **На приёмке** (2026-09-11, app `4dbe3d9` staging — приёмка zcode/владельца запрашивается). Постановка (2026-09-10, из BACKLOG Трек I-2)
> Приоритет: **P1** — «старт продаж»: клиент после оформления должен получить
> подтверждение (не кассовый документ!)
> Исполнитель: Super Z · Репо: `lovii-core` + `lovii-app` · Гейт: composer + yarn
> Источники: `money_flow_public.md` §2.2, Оферта присоединения §12.2.3
> (в квитанции НЕ называть её «чеком» — это не фискальный документ)

## 1. Что

Экран/уведомление «Ваш заказ принят» после успешного оформления:

- номер заказа (внутренний), дата/время;
- точка (название, адрес), самовывоз/доставка + адрес доставки;
- состав: позиции, количество, цены (копейки → рубли);
- итог: сумма, доставка, скидка/баллы (если применялись);
- статус заказа и ссылка на отслеживание (внутри app);
- текст-дисклеймер: «Квитанция не является фискальным документом. Чек будет
  доступен после оплаты/подтверждения расчёта» (формулировка 🔶 согласовать с
  юристом — база money_flow §2.2).

## 2. Где живёт

1. **Экран успеха** в app сразу после оформления (сейчас — что показывается?
   сверить с текущим UX, не ломать);
2. **Повторный просмотр**: из карточки заказа в «Моих заказах» — кнопка
   «Квитанция»;
3. **Каналы**: push/уведомление о принятии заказа (связка SZ-010) — в тексте
   номер заказа.

## 3. Не входит

- Фискальный чек (I-1), PDF-выгрузка/email-вложение (позже, с E-2).

## 4. Приёмка

- Владелец: оформляет заказ → видит квитанцию со всеми полями; из «Моих
  заказов» открывает её повторно; текст дисклеймера корректен.
- zcode: приёмка кода; тест на формирование квитанции (суммы, состав).

## 5. Отчёт исполнителя (Super Z, 2026-09-11, app `4dbe3d9`)

### 5.1. Экран успеха (§2.1)
- `CreateOrderSuccess.vue`: квитанция встроена сразу после заголовка «Заказ создан успешно»
  (компонент `OrderReceipt`, order уже приходит пропсом). Платёжный флоу не сломан:
  квитанция над кнопками оплаты, блоки «Оплатить/Проверить/Позже» — как были.

### 5.2. Повторный просмотр (§2.2)
- `ProfileOrder.vue`: кнопка **«Квитанция»** (toggle «Скрыть квитанцию») под сводкой —
  открывает ту же квитанцию в карточке заказа из «Моих заказов».

### 5.3. Состав квитанции (§1)
Номер (`order_number`), дата/время приёма (ru-RU формат), точка (`merchant.name`,
лейбл «Магазин/Точка выдачи» по delivery_type), получение + адрес, скидки и баллы
(`discount_amount + bonus_spent`, строка скрывается при нуле), итог (`total`).
Позиции и суммы показывают уже существующие секции (`OrderProducts`, `OrderSummery`)
— дублирование убрано. Дисклеймер по money_flow §2.2: «Квитанция не является фискальным
документом и подтверждает только приём заказа. Чек будет доступен после оплаты и
подтверждения расчёта.» (🔶 финальная формулировка — юрист).

### 5.4. Каналы (§2.3)
Пуши SZ-010 уже содержат номер в title: «Заказ #N — {статус}» (PushPayload::forOrderStatusChanged)
и «Новый заказ #N» (продавец) — дополнительная работа не потребовалась.

### 5.5. Тесты и гейты
vitest ×3 (`OrderReceipt.test.ts`: номер/дата/точка; скидки при наличии/отсутствии; итог +
дисклеймер). Гейты: prettier ✓, vue-tsc 0, oxlint 0, eslint 0, **vitest 309/309**.
Гейт core не требовался — API OrderDetail уже отдавал все поля (order_number, subtotal,
delivery_fee, discount_amount, bonus_spent).
