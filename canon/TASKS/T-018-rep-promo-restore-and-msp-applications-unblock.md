## Контекст

Владелец (user 51, `+79119287478`, Основатель/амбасадор, префикс `AA`) сообщает:
подписка PASS активна, но **представительский промокод не виден в профиле**, ввести

промокода MVP-сценарий «МСП регистрируется по QR-коду представителя → заявка уходит
в кабинет → аппрув» не работает — живые staging-тесты владельца заблокированы.

### Система промокодов — три разных кода, не путать

1. **Амбасадорский код** (для user 51 — **`AA2222`**) — полный 6-символьный код:
   prefix(2) `AA` + suffix(4) `2222`. Хранится и в `ambassadors` (строка с `prefix=AA`,
   `is_active`), и в `representative_promo_codes` (активная запись с кодом `AA2222`).
   Назначает только Основатель вручную: `roles:assign-ambassador {phone} {prefix}`
   (`AssignAmbassadorCommand.php:12–14`). Иерархия rep→amb — **только по префиксу**,
   дерева нет (`ListAmbassadorRepsController.php:18–19`).
   - ⚠️ **Префикс `AA` — это наследуемый тег ветки, а НЕ отдельный код в профиле.**
     Соль префикса: все, кто регистрируется по амбасадорскому коду `AA2222`,
     получают личный промокод представителя с тем же префиксом `AA` (напр. `AA3K7M`).
     В профиле у амбасадора стоит **полный код `AA2222`**, а не «`AA`».
2. **Инвайт-промокод (`users.promo_code`)** — полный код пригласившего (напр. `AA2222`
   для тех, кого пригласил user 51), nullable, добавлен 2026-09-14 (миграция
   `2026_09_14_120001`). **Гейт подписки** (SZ-057): без него → 403
   `subscription_requires_promo`, кнопки подписки нет, в профиле строка «Подписка —
   по приглашению». Перепривязок в MVP нет.
3. **Личный промокод представителя** — `representative_promo_codes`, code(6) =
   prefix(2, ветка амба) + suffix(4, случайный, алфавит без `0/1/I/O`). Один активный
   на юзера. Выдаётся: (а) `RepresentativePromoService::issue()` при успешной
   активации подписки (SZ-057, commit `e9453bd`); (б) довыдача при успешном продлении
   в кроне (для подписавшихся до SZ-057); (в) вручную artisan-командой
   `roles:issue-promo {phone} {--prefix=AA}`.
   - ⚠️ **Для user 51 (амбасадор + представитель) личный промокод, скорее всего,
     и есть `AA2222`** (одна активная запись на юзера — `один активный на юзера`).
     zcode должен **верифицировать по БД**, какой код реально активен у user 51:
     `AA2222` или другой; если `AA2222` деактивирован — перевыпуск выдаст новый
     код с префиксом `AA` и **случайным** суффиксом (не `2222`).
   Флаг `representative` = есть активный код (`User.php:119–122`); флаг `ambassador` =
   есть строка в `ambassadors` с `is_active` (`User.php:124–127`).

### ⚠️ Канонический `AAAAAA` — открытая проблема (НЕ чинить в T-018)

По канону должен существовать промокод **`AAAAAA`** — инвайт-код «само-приглашения»
Основателя: user 51 (Основатель) не имеет человеческого пригласившего, но гейт
подписки (SZ-057) требует `users.promo_code` ≠ null. Каноническое решение —
`AAAAAA` как корневой инвайт для Основателя. **Владелец пока не выставил `AAAAAA`
правильно, чтобы не запутать систему** (должен быть привязан к «какому-то профилю»,
но корректный способ без поломки логики не определён). T-018 **не выставляет
`AAAAAA` и не ставит `users.promo_code = AAAAAA`** — только фиксирует, что это
контекст гипотезы Б4 и открытая проблема для отдельной задачи.
