## Контекст: что сейчас доступно и где (проверено 2026-09-21)

Кабинет МСП в приложении (`lovii-app`, `/cabinet/msp`, экраны в
`src/modules/roles-module/msp/`): разделы Обзор / Заказы / Товары / Настройки / Команда / Чек-лист
запуска. Экран «Настройки» (`MspBranchSettings.vue`) сегодня правит:

- название точки, адрес (с геокодированием на стороне ядра, при смене адреса координаты
  пересчитываются, при неудаче — честное предупреждение), график работы (дни/интервалы +
  «Круглосуточно»), минимальная сумма заказа точки;
- карточку магазина-базы: название, описание, логотип (`PATCH /api/v1/msp/merchant`).

Правки точки в ядре (`UpdateMspBranchSettingsController`) принимают только
`name` / `address_line` / `working_hours` / `min_order_amount_rubles`.

**Что сегодня доступно только в b2b** (`lovii-b2b`, Filament): статус точки
(`active|inactive|closed`), тумблеры канала (`pickup_available`, `delivery_available`),
`min_delivery_minutes` / `max_delivery_minutes`, зоны доставки (радиус/полигон, fee, free_from,
ETA), полный каталог (категории, товары, привязка позиции к точке), управление брендами
и юрлицами целиком, команда точки в деталях.

Поля точки в БД (`merchant_branches`): `merchant_id`, `city_id`, `name`, `status`,
`address_line`, `pickup_available`, `delivery_available`, `min_delivery_minutes`,
`max_delivery_minutes`, `min_order_amount`, `working_hours` (jsonb), `timezone` (nullable!),
`location` (geography), `partner_id`, `deleted_at`.

Наблюдение со стенда 21.09 (следствие, а не полнота): у точек, заведённых через приложение,
`timezone` пустой (время считается в UTC), а `delivery_available`/`pickup_available` выключены —
то есть точка, созданная «с телефона», не может принимать заказы, пока её не доведут в b2b.
Это ровно тот разрыв, который закрывает требование владельца.

В приложении есть чек-лист запуска (`msp/readiness.ts`, экран `MspStarter.vue`) — он уже
формулирует «что мешает точке начать работать»; его стоит использовать как основу для
определения «базового набора» и не расходиться с ним.

## Что сделать (решения принимает исполнитель, обоснование — в отчёте)

1. **Зафиксировать «базовый набор» — чек-лист «точка запускается с телефона»** и обосновать
   его: что минимально нужно, чтобы точка приняла первый заказ (адрес с координатами, график,
   канал продаж: самовывоз/доставка + радиус, минимальная сумма заказа, карточка магазина
   (название/лого/описание), товары, контакт для заказов и т.п.). Поле радиуса доставки
   в этом наборе подчиняется канону `SZ-070` (простой радиус от адреса точки; за радиусом
   доставка недоступна, самовывоз остаётся; границы значения — дом `PARAMS.md`). Набор должен
   быть непротиворечив с `readiness.ts` и с `PRODUCT_QUALITY_BAR.md`.
2. **Реализовать недостающие базовые настройки в приложении** так, чтобы точка прошла путь
   «создал → настроил → начал принимать заказы» целиком с телефона, без обязательного похода
   в b2b. Чем именно дополнить экран/контракт — решаешь ты (в объёме набора из п.1).
3. **Явно провести границу «базовое в app / детальное в b2b»** и отразить её в отчёте таблицей
   «поле → где правится → почему». Граница не должна оставлять состояние, в котором настройка
   из приложения молча затирает точную настройку из b2b (в особенности зоны доставки).
4. **Согласовать с соседними задачами** (зависимости, не дублируя их): `SZ-063` (вкл/выкл и
   временное закрытие), `SZ-064` (точки/товары бренда), `SZ-065` (каналы продаж),
   `SZ-066` (радиус доставки), `SZ-067` (круглосуточность + `timezone`/данные).
   Если что-то из этого уже сделано к моменту работы — переиспользуй, а не переделывай.
5. **Приёмка живьём**: с чистого профиля МСП пройти путь запуска точки из приложения
   и показать, что заказ на этой точке после него проходит (оба канала по канону).

## Что не делать

- Не переносить в приложение детальные настройки b2b (полный каталог, полигоны зон, ETA,
  управление юрлицами) — владелец прямо определил app как упрощённую базовую версию.
- Не ломать существующий путь b2b и не менять семантику полей точки молча.
- Не менять канон формата расписания (`lovii-core/docs/specs/working-hours-specification.md`).
- Не пушить в `staging`/`master` без «го» владельца, не трогать прод-данные.

## Приёмка

- С телефона: новая точка доводится до состояния «принимает заказы» без обязательных действий
  в b2b; чек-лист запуска (`readiness`) при этом не противоречит реальности.
- Таблица «поле → где правится» из отчёта соответствует фактическому поведению (проверено живьём).
- Точная настройка, сделанная в b2b, не теряется при сохранении из приложения.
- Тесты: core (`bash ~/LOVII/tools/core-tests.sh <путь>` на локальном стенде) и app (`yarn test`)
  зелёные; e2e/ручной сценарий на стенде пройден; горячие пути — стресс-страж на локальном стенде.
