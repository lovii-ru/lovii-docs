## Контекст — текущее состояние (проверено zcode на staging 2026-09-10)

- Все **31 позиция** мерчанта 280 «Пышки & Пончики», созданные через экраны b2b
  в ходе SZ-006 §2, лежат в `merchant_offers` с **`branch_id = NULL`**.
- Витрина `/v1/storefront?branch_id=1024` их показывает: `loadOffers`
  фильтрует по `merchant_id` (GetStorefrontCatalogQuery::loadOffers:204) —
  поэтому на витрине дефект не виден.
- **Поиск по филиалу `/v1/search/offers?branch_id=1024` → 0 позиций**:
  Meilisearch-фильтр `branch_id` не совпадает с документами, где branch_id
  null. Индекс уже актуален (zcode выполнил `scout:import MerchantOffer`) —
  это данные, а не индекс.
- В core `CheckoutBuilder` при заказе филиал требуется (фолбэк на первый
  активный) — заказ пройдёт, но привязка оффера к точке на стороне данных
  отсутствует, что бьёт по будущим зонам/остаткам/отчётности филиалов.

## Отчёт исполнителя (Super Z, 2026-09-10)

### 1. Ресёрч формы (п.1)
`PositionResource` (Filament) создаёт `MerchantOffer` через `CreatePosition::handleRecordCreation`:
`branch_id` приходил из формы только когда в свёрнутой секции «Дополнительные настройки»
партнёр снимал тоггл «Доступна во всех филиалах» (`all_branches`, dehydrated(false),
ДЕФОЛТ = true) и выбирал филиал в Select. При наполнении SZ-006 §2 тоггл никто не
трогал → все позиции ушли с `branch_id = NULL`. То есть поле не отсутствовало —
его молча обнулял дефолт.

### 2. Решение по форме (п.2) — коммит b2b `2e25744`
- **Однофилиальный мерчант**: авто-привязка — на create тоггл выключается и
  `branch_id` предзаполняется ЕДИНСТВЕННЫМ АКТИВНЫМ филиалом
  (`singleBranchIdFor()`: статус = Active; inactive/closed не считаются).
  Тихий NULL больше невозможен для доминирующего МСП-кейса.
- **Многофилиальный мерчант**: осознанный nullable — тоггл «все филиалы» остаётся
  дефолтом ON. Обоснование: сети (Дикси — 275 точек) легитимно продают сетевые
  позиции «везде»; обязательный выбор вынудил бы создавать позицию 275 раз.
  Выбор филиала при снятом тоггле — обязателен (requiredIf, был и остался).
- Смена мерчанта в форме переоценивает привязку (single → проставить, multi →
  сброс в «все филиалы», чужой филиал не остаётся в стейте).
- Clone: прefdilled branch (от исходной позиции) сохраняется и переключает тоггл.
- ⚠️ ВАЖНОЕ СЛЕДСТВИЕ для core (вне стоп-листа этой задачи, zcode): позиции
  «все филиалы» (`branch_id = NULL`) по-прежнему НЕ находятся поиском по филиалу.
  Core-side решение (индексировать such-офферы под каждый филиал ИЛИ фильтр
  `branch_id = X OR branch_id IS NULL` в SearchOffersQuery) — в бэклог core;
  на витрине они видны (loadOffers по merchant_id — статус-кво не тронут).

### 3. Данные «Пышек» (п.3) — только через экраны b2b
- 29 позиций (id 4850983–4851012, лакуна 4850986) перепривязаны к филиалу 1024

  Сохранить; драйвер agent-browser по реальным формам (scripts/rebind_positions.sh),
  идемпотентно, каждое сохранение проверено перезагрузкой формы («SKIP: already
  bound» на контрольном прогоне 6 позиций).

### 6. ДОПОЛНЕНИЕ (2026-09-10, вечер): hydration-баг найден ЖИВОЙ верификацией и исправлен (`f2af5b3`, `cf98901`)

Первый вариант авто-бинда прошёл style-шаги CI, но ЖИВАЯ проверка формы на
staging показала `branch_id: null` при выключенном тоггле. Причина (журнал SZ-011 → F-15):
`$set('branch_id', …)` из afterStateHydrated тоггла перетирался собственной
последующей гидратацией поля branch_id (порядок схемы = порядок гидрации).
Пест-набор это ловил СРАЗУ (шаг Pest в CI — не блокирующий, потому три раза был
незамечен — см. SZ-011 §8.5.1) — теперь ловит и блокирует смысл:

- branch_id теперь СТОИТ ПЕРЕД тогглом и авто-биндит в СВОЁМ afterStateHydrated;
  тоггл читает уже разрешённое состояние (filled → bound);
- заодно исправлен краш рендера селекта на безымянных филиалах
  (name nullable → isOptionDisabled(string|null) → ViewException):
  label-фолбэк «Филиал #:id» (ru/en) — найдка из ResolvesTenantMerchantTest;
- Pest: 552 passed / 7 failed — все 7 = pre-existing базовая линия
  (MediaStorageIntegrationTest ×6, BranchResourceWorkingHoursTest ×1 — были
  красными до моих коммитов, см. прогон 779ce13: 7 failed/484 passed);
  мои +68 тестов зелёные;
- ЖИВАЯ верификация на staging: форма создания позиции показывает
  `all_branches=false, branch_id=1024` без единого действия партнёра ✓.

Критерий приёмки «новая позиция однофилиального мерчанта получает branch_id
автоматически» — выполнен и проверен на живом staging (деплой `f2af5b3`+).
