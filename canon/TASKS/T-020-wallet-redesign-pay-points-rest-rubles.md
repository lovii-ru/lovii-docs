## Контекст

Экран кошелька `/profile/wallet` (`ProfileWallet.vue`, 48KB) — единый экран «Счёт и
операции»: карусель карт, сводка выбранного счёта, одна лента операций. **Реликты
двух контуров** (подтверждено кодом + комментом в шапке файла):

- явный `type Contour = "money" | "points"` + `CONTOUR_SEGMENTS = [{Деньги},{Баллы}]` —
  ручной сегмент-контур;
- две истории: `ledgerEntries` (рубли, `/balance/entries`) vs `walletTx` (баллы,
  `/wallet/transactions`);
- два фильтр-хелпера: `helpers/entries.ts` (10KB, money) vs `helpers/wallet-history.ts`
  (4KB, points);
- два компонента-строки: `components/LedgerTxRow.vue` (рубли) vs
  `components/WalletHistoryList.vue` (баллы);
- `pointsAvailable` = только personal-счёт имеет баллы.

**`PayCard.vue` (17KB) УЖЕ правильная** — `balanceUnit` проп: personal→«б.», company/
nominal→«₽». Проблема НЕ в карте, а в ленте/контуре.

### Канон карт (B1, B4 — решение владельца)

- **PAY** — одна на пользователя; **всегда баллы (б.)**, биндится на `wallets.balance`
  (`Core\Wallet`), источник истории — `/api/v1/wallet/transactions`.
- **Business** — открывается на каждое МСП = ИНН (N штук у владельца, в т.ч. ООО Аксиома
  ИНН 7842223709 = оператор платформы, получает комиссии + оплаты подписок); **всегда
  рубли (₽)**, биндится на `accounts` (`owner_type=partner`), источник истории —
  `/api/v1/balance/entries`.
- **Nominal/транзит** — **только на профиле Основателя** (одна карта), видит все
  транзакции (списания + начисления), `owner_type=platform_nominal`; **всегда рубли (₽)**,
  история — `/api/v1/balance/entries` с группировкой по чекам (`groupEntriesByOrder`).
- **Будущее**: когда появится Operator entity с промокодом `AAAAAA` — добавить доступ к
  транзитному счёту и ей (отдельная задача, не T-020). Возможно несколько операторов с
  своими оборотами — требует продумывания (вне T-020).

### Правила (B5, дефолты с пометкой «на визуальной приёмке»)

- **B5**: экран переводов `/profile/wallet/transfer` — **всегда отдельный экран**;
  кнопка на него из профиля (есть) + **добавить кнопку из кошелька** (как в профиле под
  картой — `feat(transfers)` по SZ-077, кнопка «Переводы» под личной картой).
- **B3 (дефолт)**: тап по карте → операции **именно этой карты** (карта = фильтр);
  сегмент-контроль «Деньги/Баллы» убирается — контур НЕявный от kind карты.
- **B6 (дефолт)**: блок подписки PASS остаётся на кошельке как вторичный (статус +
  CTA «Подключить/Возобновить», SZ-056/057) — владелец подтвердит на визуальной приёмке.
- **B8**: НЕ ждать F-059 — унификация UI идёт на текущих двух бэкендах (`Core\Wallet`
  для баллов, `Domain\Billing\Account` леджер для рублей); F-059 — про платёж подписки
  (422 на активации), не про отображение. Если после решения F-059 что-то изменится в
  бэкенде — ревизит.
- **B7**: zcode сам найдёт кандидатов на удаление/слияние — трогает все файлы модуля и
  зависимости.

### Фаза Б — Рефакторинг `ProfileWallet.vue` (после T-019 Фаза Б)

Б.1. **Убрать `Contour` + `CONTOUR_SEGMENTS` + сегмент-контроль** из UI и логики.
Контур становится **неявным** от `selectedAccount.kind`:
- `kind === "personal"` → points: баланс `wallets.balance`, история `/wallet/transactions`,
  unit «б.», label «Доступно баллов · 1 балл = 1 ₽»;
- `kind === "company"` → rubles: баланс `accounts.balance`, история `/balance/entries`,
  unit «₽», label «Доступно на счёте»;
- `kind === "nominal"` → rubles: баланс `accounts.balance` (platform_nominal), история
  `/balance/entries` с `groupEntriesByOrder` (цепочки по чекам), unit «₽».

Б.2. **Унифицировать ленту**: одна `feed`-логика, переключающая источник данных по
`selectedAccount.kind` (вместо двух `moneyRows`/`pointsRows`). Одна пагинация, один
`feedTotal`/`shownCount`/`clientFiltered`.

Б.3. **Сводка месяца**: одна логика (`monthStats` работает для обоих — rubles по ledger,
points по wallet-tx); убрать дублирование `ledgerMonth`/`walletMonth` → единый `monthData`.

Б.4. **Сабхедер/хедер экрана**: `--lv-subheader-h: 48px`, sticky к хедеру (T-019 регламент
