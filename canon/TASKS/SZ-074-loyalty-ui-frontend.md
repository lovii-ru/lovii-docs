## 1. Цель

Базовый конструктор — **в приложении**, в кабинете точки (как в демо); сложные
механики — в `lovii-b2b`. Обе поверхности собираются из **одного UI-набора
лояльности**. Визуальный эталон — демо.

## 2. Шаг 0 — зафиксировать дизайн-канон из демо (обязательный первый шаг)

Качество демо — приёмка. Переносим **компоненты, поведение и визуальный язык**
(каркас в приложении другой, поэтому это не копия HTML, а порт на токены
`lovii-design`).

| Эталон демо | Что переносим |
|---|---|
| <https://lovii.mobiap.com/#/msp> → «Промо» | живое поведение всех механик |
| `lovii-demo/js/loyalty.js` | логика разделов: список, мастер акции, редакторы механик, состояние, предпросмотры |
| `lovii-demo/css/loyalty.css` | визуальные компоненты `lv-*` |
| `lovii-demo/index.html` | подключение раздела в кабинете (вкладка, `cabinet-mode`) |
| `loyalty/prototypes/assets/lv-demo/` (13–16) | кадры-эталон трёх состояний |

Поведение-эталон (сохранить дословно смысл):

- **Раздел точки:** «Акции» — карточка «Кэшбэк по умолчанию», «Группы товаров»,
  список «Акции» с типом и статусом («На витрине», «Стоп по бюджету»), «Итог по точке».
- **Мастер акции:** «Сумма чека», «Комбо», «Штампы · N-й в подарок»,
  «Счастливые часы», «Группа товаров».
- **Редакторы:** шаговый ввод «− / +» (тап-таргет ≥44px), чипы дней недели, поля
  времени `ЧЧ:ММ`, карта штампов, метр бюджета, блок «Как увидит покупатель».
- **Бюджет:** «Авто-стоп по бюджету», демо-действие «Смоделировать исчерпание».
- **Подписи покупателю:** «Кэшбэк N% · +K балл.», «Счастливые часы · +N%»,
  «Штампы 2 из 6», «Подарок … 0 ₽».

## 3. UI-набор лояльности (общий для app и b2b)

| Компонент | Назначение |
|---|---|
| `LoyaltyRuleCard` | карточка правила в списке (имя, мета, тип/статус, тумблер) |
| `MechanicPicker` | выбор механики (5 вариантов из демо) |
| `PercentStepper` | шаговый ввод процента/количества (44px) |
| `DayChips` / `TimeField` | окно «счастливых часов» |
| `StampCard` | карта штампов |
| `BudgetMeter` | бюджет и авто-стоп с прогнозом стоимости |
| `BuyerPreview` | предпросмотр «как увидит покупатель» |
| `PromoBadge` | бейдж на товаре/в корзине |

Все — на токенах `lovii-design`, без локальных цветов.

## 4. Экран «Акции» в кабинете точки (приложение)

- Новый экран `src/modules/roles-module/msp/MspLoyalty.vue` + дочерние представления.
- Маршрут рядом с `MspOverview`; вкладка в `cabinetTabs`
  (`src/router/index.ts:726–756`) с правом (`loyalty.manage` или `merchant.update` —
  по рамочному вопросу SZ-072 §8).
- Каркас — существующий `CabinetLayout` (нижний бар, `cabinetAccent`).
- Три состояния: загрузка (скелетон), пусто (продающее + CTA), ошибка (честный текст).

## 5. b2b — сложные механики

- Расширенный редактор правил и **массовые настройки по сети точек** (одна акция на
  бренд/мерчантов), пресеты и дублирование.
- Использует **тот же** UI-набор и тот же контракт `SZ-073`.

## 6. Визуальная приёмка (гейт)

Для каждого экрана — скриншоты:
- «приложение vs демо» в одинаковой ширине **390px**;
- состояния: заполнено / пусто / загрузка;
- сверка токенов с `lovii-design`.

Расхождение — либо поправить, либо обосновать в отчёте (например, каркас кабинета
в приложении отличается). Кадры приложить к отчёту.

## 7. Критерии приёмки
1. Владелец точки настраивает акции базовых механик из приложения без веб-кабинета.
2. Сложные механики доступны в b2b; источник правил один (сервис).
3. Все 5 механик из демо настраиваются и сохраняются; значения читаются обратно.
4. Визуальная приёмка (§6) пройдена; три состояния есть у каждого экрана; a11y
   (контраст AA, тап ≥44px, подписи) и адаптив 390px+/десктоп.
5. Права: сотрудник без нужного ability не видит раздел.

## 8. Гейты
`yarn test` (format → lint → unit → type-check → build) в `lovii-app`;
`docker exec lovii-b2b-app-1 composer test` в `lovii-b2b`; cross-tenant тест для
b2b-правил; e2e по теме.

## 9. Стоп-лист
Не дублировать правила в кабинете; не рисовать локальные цвета/компоненты вместо
UI-набора; не публиковать в прод-путь без прохождения визуальной приёмки.

## 10. План отчёта
Экраны и компоненты (файлы, коммиты); скриншоты «app vs демо» и трёх состояний;
