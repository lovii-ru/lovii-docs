## Контекст

`lovii-demo` — живая витрина платформы (PWA, lovii.mobiap.com, GitHub Pages, ветка
`master` = прод). Стиль вырос в один глобальный `css/lovii.css` поверх снапшота
токенов `assets/lovii-tokens.css`; иконки — единый реестр `js/icons.js` (контур
lucide 24×24, цвет через `currentColor`, размер — через CSS-класс). Канон токенов —
репозиторий `lovii-design` (v1.16.2, голова 0e93f47 на дату постановки).

Состояние проверено на свежих клонах 2026-09-20 и зафиксировано в RES-008/RES-009.
Ключевое: классов в компонентном слое — сотни, из них часть заведомо мёртвая;
52 уникальных hex-цвета в компонентном CSS вне токен-слоя; в иконках — вызовы без
класса размера (привело к багу стрелок профиля, исправлен в сборке 50, a8a86be);
`--lv-navbar-height` в demo не определён (fallback 56px при реальном таббаре 64px);
13 разночтений кабинетов demo↔app. Полный аудит-конвейер на актуальной голове ни
разу не прогонялся (хвост RES-009 §4).

Задача фиксирует объём, порядок, критерии приёмки и формат результатов так, чтобы
любая чистая сессия дала один и тот же проверяемый результат.

## Железные правила сессии (не менять, повтор канона владельца)

1. **Всегда свежие клоны с GitHub** в чистую рабочую папку; локальные копии прошлых
   сессий не считаются истиной. Головы зафиксировать в артефакте фазы 0.
2. **Пуши — только артефакты** в `lovii_docs`; кодовые репозитории (`lovii-demo`,
   `lovii-app`) и ветки не пушить и не мержить без отдельной явной команды владельца
   на конкретный список.
3. **Токен доступа** в файлах не сохранять; в командах и логах маскировать:
   `sed 's|//[^@]*@|//***@|'`.
4. **Бизнес-логика JS не трогается.** Допустимые правки JS: только связанные с
   размером/классом иконок (`icon(name, cls)`).
5. **Ноль визуальных изменений** вне таблицы правок, согласованной владельцем.
6. `lovii-design` — только чтение; канонизация новых токенов — только через решение
   владельца (гейт №2).
7. Каждый шаг — запись в worklog (append-only) + артефакт с датой загрузки и датой
   проверки. Статусы: 🟩 готово · 🟧 доработать · 🟥 блокер · ⬜ заглушка.

### Фаза 1 — Полный аудит CSS → `ART-1` (только измерения, никаких правок)

1. **Мёртвые классы:** класс определён в CSS, но 0 упоминаний в HTML/JS-строках +
   0 появлений в рантайме на всех роутах. Каждый кандидат — с доказательством
   (grep-вывод + рантайм-проверка). Классы, генерируемые динамически из строк JS
   (шаблоны, конкатенации), помечать отдельно — в удаление только с ручным разбором.
2. **Дубли и коллизии:** повторные определения одного класса, перекрытия селекторов,
   конфликты специфичности — `lv_collisions.py` + ручной разбор.
3. **Статика:** `node --check` всех JS; eslint `lv_eslint.mjs`; HTML-аудит
   (незакрытые/запрещённые теги, дубли id, битые `data-action`/`data-go`).
4. **Хардкод-инвентарь:** все hex/rgb вне токен-слоя; все повторяющиеся значения
   (px-размеры, отступы, радиусы, тени, транзишены) с частотой ≥2 — кандидаты на
   токенизацию.
5. **Специфичность/каскад:** инвентарь `!important`, селекторов глубже 3, вложенных
   каскадов — только карта рисков, без правок.
