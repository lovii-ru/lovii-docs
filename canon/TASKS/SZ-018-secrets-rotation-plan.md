## 1. Что

Инвентаризация и план ротации секретов платформы до включения прода:

| Секрет | Где живёт | Действие |
|:---|:---|:---|
| GitHub PAT (bestdeejay-design) | CI/локальные репо | проверить срок/права; ротация — владелец |
| Токены Telegram-ботов (otp/orders/support) | `.env` серверов | не светились в открытых чатах? аудит + ротация перед продом |
| MAX Bot API токены («Лови») | `.env` staging | NB: в «Боты Макс.txt» подписи перепутаны — инвентаризировать честно |
| VK-ключи (сообщества, callback) | `.env` + OTP codes VK .md | ротация строки подтверждения ротируется VK-ом — учесть |
| Т-Банк ключи терминала (тест/бой) | LOVII/lovii-docs/tbank (нелокально-гит) | проверить, что тест-ключи не в прод-.env |
| VAPID-ключи push (SZ-010) | `.env` | сгенерировать на staging/prod раздельно |
| Пароли БД (staging/prod) | `.env` серверов | минимальные права, разные пароли окружений |
| Доступ к серверу (deploy) | ключи SSH | аудит: кто в authorized_keys |

## 2. Как

1. Инвентаризация (таблица выше → дополнить фактическими местами);
2. Отчёт: что ротируем, кто выполняет (владелец/агент), порядок;
3. Ротацию НЕ выполнять в этой задаче — только план-чеклист на утверждение
   владельца 🔶 (секреты меняет владелец или по его прямому поручению);
4. Инцидент-план (утечка токена: что отключаем, в каком порядке) — черновик в
   отчёте.
