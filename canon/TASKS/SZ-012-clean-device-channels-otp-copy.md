### 1.1 Диагноз и фикс (Super Z, 2026-09-10)

Репро: чистая сессия браузера (localStorage пуст, свежий SW) + эмуляция iPhone —
app-staging, happy path ЧИСТЫЙ (ввод телефона → каналы рендерятся, request-code
200). Триггер пойман live: серия `POST /v1/auth/request-code` с одного IP →
`1..5:200, 6:429, 7:429, 8:429`; тело 429 `{"error":{"code":"too_many_requests"}}`,
заголовка **Retry-After нет**.

Корневая цепочка (совпадает с симптомом владельца «экран вообще не загрузился,
повторно через MAX код пришёл автоматически»):

1. `otp-send` троттлится 6/мин **на IP** + 2/мин на телефон
   (`AppServiceProvider::configureRateLimiters`).
2. На первом визите кэша `loviOtpChannels` нет → каждый ремаунт экрана каналов
   бьёт в API. Механика «назад → повторный ввод телефона → ремаунт»
   (AuthModule.backHandle) плюс SW-precache-шторм первого визита (уходит канал)
   быстро набирают 6 запросов с IP → **429** (carrier-NAT усиливает).
3. Фронт глушил ошибку молча (`catch(() => {})`) → вечные скелетоны, без текста
   и ретрая. У axios не было timeout — зависший XHR на слабой сети даёт тот же
   симптом. Через минуту окно лимита истекает → повторная попытка проходит.

Фикс (lovii-app push `14e87a0` + prettier `4a9df44`, staging):

- `AuthCallCoders.vue`: load-error состояние вместо вечных скелетонов —
  `data-testid="auth-channels-error"` + кнопка «Повторить»
  (`auth-channels-retry`); 429 получает отдельный текст («подождите около
  минуты»), прочие сбои — «проверьте связь»; не-массивный ответ трактуется как
  сбой; тесты: 6 новых сценариев чистого состояния.
- `auth-api.ts`: timeout 15с на request-code / send-code / confirm /
  confirm-by-binding (мелкие JSON; uploads не тронуты — глобального таймаута нет).
- Гейты: vitest 230/230, vue-tsc 0, oxlint+eslint 0, prettier ✓.

**На zcode**: деплой app-staging → live-регресс «первый контакт» (чистое
устройство → телефон → каналы → MAX → код). **Примечания (не блокер)**:
per-IP 6/мин жёстко для carrier-NAT — решение за владельцем (безопасность vs
воронка); Retry-After не доходит до клиента; e2e-конфиг блокирует SW
(`serviceWorkers: "block"`) — SW-путь нигде не покрыт.

## 1. Бага: экран выбора канала не загружается на чистом устройстве

Симптом (владелец, чистый телефон, LOVII не открывалась никогда): после ввода
телефона экран выбора способа получения кода **вообще не загрузился**; повторно
через MAX код пришёл автоматически.

Диагностика zcode: backend жив — `POST /v1/auth/request-code` на staging
отвечает **200** и отдаёт каналы (`max`, `telegram`, `vkontakte`, без
coming_soon). Значит проблема на **фронте** (lovii-app) при первом визите.

Проверить и починить:

- воспроизвести на чистом устройстве / инкогнито + свежий SW: открыть
  app-staging → регистрация → ввод телефона → экран каналов;
- снять console/network в этот момент; кандидаты: JS-ошибка при отсутствии
  кэшированного состояния, гонка инициализации auth-store на холодном старте,
  Service Worker первой установки перехватывает запросы, обработка ответа
  `request-code` (формат каналов) падает на пустом стейте;
- фикс + тест (юнит на сторе/компоненте с чистым состоянием);
- регресс: повторить сценарий «первый контакт» целиком (это воронка привлечения!).

## 2.5. Длина кода и авто-подстановка (решение владельца, 2026-09-10)

Факты из кода core:

- длина задаётся в `OtpChannel::codeLength()`: **MAX = 4**, Call = 4,
  **Telegram / VK / SMS / WhatsApp = 6** (хардкод enum);
- `config/otp.php: code_length = 4` существует, но **не читается никем**
  (мёртвая настройка) — источник истины разъехался.

Решение владельца:

1. **Все каналы — 4 цифры.** Единственный источник истины — конфиг
   (`otp.code_length`); enum читает его (или удаляется в пользу конфига).
2. **Текст сообщения: перед цифрами буквально `Код: `** — триггер авто-
   подстановки кода iOS/Android в поле ввода. ✅ Финальная формулировка
   утверждена владельцем 2026-09-10 — §2.3.1 (требование «Код: {код}»
   рядом выполнено).
3. UX app: поле ввода кода под 4 цифры (autofill/one-time-code: autocomplete
   атрибуты, клавиатура numeric) — проверить все экраны ввода.
4. Тесты: длина кода по каждому каналу; формат сообщения; регресс
   dev-bypass `1234` не ломается.
