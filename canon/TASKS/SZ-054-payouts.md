# SZ-054 — Выплаты: push-реестр ИП/ООО + pull-заявки НПД

> Статус: **В работе** (2026-09-18, исполнитель zcode)
> Приоритет: **P1** (главный блокер пилота M1 — без выплат деньги копятся
> у платформы, партнёры их не получают; BACKLOG_REVIEW §A5)
> Репо: `lovii-core`
> Источник: `lovii-docs/BACKLOG_REVIEW.md` §B (`payout-scheduler` +
> `payout-pull-request` — объединены в одну карточку, решение zcoder'а §C2 #8)
> Точка входа: `LedgerEntryType::Payout` объявлен, использований 0 (F-049)

## Решения владельца (§A5 + §C2 #1)

| Параметр | Решение |
|---|---|
| Push (ИП/ООО) | Ежедневно по итогу финансового дня, 09:00 МСК; комиссия банка 0,5% — за счёт ОПЕРАТОРА; без порога |
| Pull (НПД) ≥ 3 000 ₽ | Комиссия 1% платится ОПЕРАТОРОМ со своего счёта; получатель получает 100% |
| Pull (НПД) < 3 000 ₽ | 30 ₽ фикс удерживается из суммы получателя |
| Мин. сумма вывода | 100 ₽ |
| ⚠️ Канон PARAMS §1.6 «1% (min 100 ₽)» УСТАРЕЛ | Реализуем 1% точно, без floor (владелец правит канон отдельно) |
| Гейт | Вывод только при льготной подписке (`grantsBenefits()`, PARAMS §1.6) |
| Банк-API | Ждём тестовый контур (§C2 #6): реестр формируется → ручная отправка через интернет-банк (как верификационные платежи) |

## Что сделать

1. Миграции: `payouts` (тип push/pull, суммы, комиссия + носитель, статус
   реестра, for_date, unique(account,type,for_date) для push-идемпотентности);
   `users.legal_status` (nullable — презумпция НПД §A6: не задан = самозанятый);
   `accounts.payouts_blocked` (минус-баланс блокирует исходящие).
2. `config/payouts.php`: min 100 ₽, порог 3 000 ₽, flat 30 ₽, pull 1%
   (100 bp), push 0,5% (50 bp) — все в копейках/bp, с обоснованием §A5.
3. `PayoutService`:
   - `requestPull(user, amount)`: гейты (подписка `grantsBenefits()`,
     `payouts_blocked`, min 100 ₽, баланс, legal_status ≠ ip/ooo → 422);
     расчёт комиссии; проводки: debit личного счёта на полную сумму +
     (при удержании) credit платформы на комиссию; для bearer=operator
     комиссия фиксируется в строке — проводку оператор платит при исполнении
     банком (реестр может не исполниться).
   - `runPush(now)`: по всем partner-счетам с balance > 0 → payout push
     (amount = баланс, комиссия 0,5% bearer=operator, проводка дебета);
     счёт с балансом < 0 → `payouts_blocked = true` (инвариант «минус
     блокирует исходящие»); без льготной подписки владельца — пропуск
     с причиной (решение канона §1.6; в пилоте — виден в сводке).
4. Cron `payouts:push-daily` — ежедневно 09:00 МСК.
5. API `POST /api/v1/payout/request` (pull) — honest-валидация, payload с
   суммами и комиссией.

## Что НЕ делать

- Реальная отправка в банк (тестовый контур §C2 #6) — статусы
  pending/sent существуют, исполнение добавит paid.
- Экспорт реестра (CSV/выгрузка с реквизитами) — реквизитов в системе нет.
- ПЭП-отчёты (№6, зависит от pull) — следующая карточка.
- Проводки комиссии ОПЕРАТОРА — при исполнении банком (пока только фиксация).
