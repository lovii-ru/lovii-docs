# SZ-043 — Номинальный (транзитный) счёт Основателя: полный учёт каждого чека

> Статус: **На приёмке** (2026-09-12; исходная постановка zcode; владелец по заказу #146: «нужен счёт,
> где видно все операции и их учёт — 100% приходит, минус комиссия банка, 90%
> компании, сплит 40/40/20»)
> Приоритет: **P1** — контрольный прибор владельца для сверки каждого чека
> Исполнитель: **Super Z** · Репо: `lovii-core` (+ UI в `lovii-app` — профиль
> Основателя) · Гейт: `composer test` / `yarn test`
> Источники: SZ-040 (accounts/ledger_entries), BRD §7.2, подтверждённая
> владельцем схема (2026-09-12): 100% → −fee → 90% точке → пул 40/40/20.

## 1. Факт (заказ #146, staging, проверено zcode)

Сейчас ledger пишет только 4 исходящие проводки: 90% точке (partner-счёт) +
pool_share ×3 (company/representative/ambassador). Входящее 100% чека и
комиссия банка НЕ проводятся — «где начало каждой операции» в ledger не видно,
сверять приходится вручную. Счёт АКСИОМЫ используется как «Компания» в сплите —
владелец считает это неправильным местом для контрольных операций.

## 2. Что сделать

1. **Номинальный счёт Основателя** (`accounts.owner_type = platform_nominal`,
   владелец — user 51 / роль founder): транзитный, не «кошелёк» — только учёт.
2. **Полный цикл проводок на каждый CONFIRMED-платёж** (в порядок разбора
   SZ-040, append-only):
   - `+100%` чека → номинальный счёт (инбокс, канал оплаты в payment_channel);
   - `−fee` (эквайринг по каналу: карта 3,16% / T-Pay 2,59% / СБП 0,7%) →
     номинальный счёт (исходящая на счёт банка/платёжного агента);
   - `−90%` чека → счёт компании точки (order_income, как сейчас);
   - `−40/40/20` пула → Компания/Представитель/Амбассадор (как сейчас).
   Инвариант расширяется: сумма проводок номинального счёта за чек = 0.
3. **UI**: в профиле Основателя — «Номинальный счёт» (отдельная карточка в
   списке балансов SZ-041): баланс транзита + выписка с группировкой по
   заказу (цепочка 4-5 строк на чек). Для прочих пользователей счёт невидим.
4. Задним числом пересчитать существующие проводки нельзя (append-only) —
   номинальный цикл включается с даты деплоя; исторические заказы видны
   старым составом (принято владельцем).

## 3. Приёмка

- Свежий заказ: в выписке номинального счёта ровно 5 строк на чек
  (+100%, −fee, −90%, −40, −40, −20), инвариант «номинал = 0 по чеку».
- Существующие балансы (SZ-041) и инвариант SZ-040 не задеты; гейты зелёные.

## 4. 🔶 Открытое

- Юрлицо номинального счёта (АКСИОМА — кандидат спец-счёта) — номинал
  учётный, деньги на него не «оседают»; подпись в UI «технический счёт».


## 5. Отчёт Super Z (2026-09-12, стейджинг)

Реализовано в `lovii-core` (коммит `824c8f4` → staging, CI+deploy 🟢, тесты 1028 passed):

- Типы: `AccountOwnerType::PlatformNominal`, `LedgerEntryType::PaymentIncome`/`AcquiringFee`.
- `DistributeOrderPoolAction`: на номинальном счёте полный цикл каждого
  CONFIRMED-платежа — инбокс (чек целиком), эквайринг по каналу оплаты,
  затем зеркала всех исходящих ног под ролью оригинала. Каждая нога имеет
  непустой `split_role` — уникальный индекс БД защищает идемпотентность
  вебхука по каждой строке выписки.
- Инвариант расширен и покрыт тестами: сумма проводок номинала за чек = 0
  (карта — 6 ног; баллы — 5 ног, эквайринга нет). Повторный вебхук не
  создаёт вторых проводок.
- Видимость: номинал в `GET /api/v1/balance` и гейте выписок — только
  Основателю; Основатель резолвится по фолбэк-промокоду из конфига
  (правило владельца «МСП без промокода не бывает»), без нового env.
  Чужой счёт — 404 (анти-перечисление), не пустая выписка.
- Миграция не требовалась: `accounts.owner_type` — строка.
- UI (`lovii-app` `4cc6a8c` → staging 🟢): карточка LOVII NOMINAL (скин по
  канону ДС v1.14.2 — техническая штриховка) в профиле и кошельке; выписка
  номинала — цепочками по чекам с подписью закрытия транзита при нулевой
  сумме цепочки; расхождение, если появится, показывается честно.

🔸 Открытое (из §4, не менялось): задним числом проводки не пересчитываются
(append-only) — номинальный цикл действует с даты деплоя. Край: чек без
партнёра (Kuper-импорт) — зеркал нет, у точки счёта нет; остаток остаётся
на транзите — семантику ноги подтвердить у владельца при первом таком чеке.
