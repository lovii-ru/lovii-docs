# SZ-061 — Реферальная система по канону владельца: два кода, амб-код как сущность, счёт платформы, ввод промокода при подписке

> Статус: **Открыта**
> Приоритет: P1 (блокер пилота — встанет в очередь ПЕРЕД прод-деплоем Б-2)
> Источник: диктовка владельца 19.09 (ответы на 7 развилок Б-8) + аудит готовности
> (00-док, гэпы G1–G5). Исполнитель: zcode. Репо: `lovii-core` + `lovii-app`.
> ⚠️ Граница: доработку кабинетов ведёт ВЛАДЕЛЕЦ сам (решение 19.09, п.5) —
> эта карточка делает только ядро и минимальные поверхности (перечислены ниже).

## Канон владельца (зафиксирован, не менять без него)

1. **Структура без глубины**: только «представители под амбассадором». Код
   амбассадора — 6 символов; стартовый код **AA2222** — код амбассадора
   Основателя (профиль +79119287478, пользователь 51).
2. **Экономика не меняется**: пул Компания 40 / Реп 40 / Амб 20; гейт EC-11
   (без активной подписки доля репа уходит Компании) — без изменений.
3. **Привязка**: смена промо-родителя — в будущем; сейчас — вставка при
   отсутствии: пользователь **без** привязанного промокода в блоке счёта
   (кнопка «Подписаться») может ввести промокод амбассадора ИЛИ представителя;
   привязка по общим правилам; в момент оплаты подписки платформа генерирует
   ему личный промокод по всем правилам (уже реализовано — SZ-057).
4. **Ранги** (Мэр/Губернатор) НЕ влияют на деньги — только статус и участие
   в мероприятиях компании (совпадает с решением A3 Executive Summary).
5. **Кабинеты** дорабатывает владелец (вне карточки).
6. **P2P** — нужен (см. SZ-062): стартовый баланс на профиле Основателя,
   перечисления Основатель → амбассадоры → представители. Отдельной карточкой,
   не здесь.
7. Термины/публичная подача — отложено владельцем (не блокирует карточку).

## Решения по гэпам аудита 19.09

- **G1 (решение: по рекомендации, отдельная сущность)** — амб-код становится
  отдельной 6-символьной сущностью `ambassadors.code`; реп-коды остаются в
  `representative_promo_codes` (prefix = первые 2 символа амб-кода ветки).
  AA2222 переносится в `ambassadors.code` Основателя; Основателю выпускается
  личный реп-код AA-XXXX. Привязка (`referral_code` при регистрации и при
  подписке) валидируется по ОБОИМ таблицам. «Один активный код на юзера»
  остаётся для реп-кодов; амб-код — отдельное поле (у Основателя два кода
  одновременно — канон).
- **G2** — назначение амбассадора Основателем: API `POST /founder/ambassadors`
  (телефон + генерация амб-кода от его ветки) + минимальный UI в кабинете
  амбассадора Основателя (владелец потом переделает — держим просто).
- **G3** — счёт платформы: счёт `owner_type=platform` + Founder-only API
  `GET /platform/ledger` (операции с распределением каждого платежа: точка
  90%, Компания 40/Реп 40/Амб 20, fee, подписка, выплата) + экран «Платформа»
  (carкас; владелец доработает).
- **G4** — QR амбассадорского кода в кабинете амба (как у репа).
- **G5** — данные staging: верифицировать Grand (268), зачистить дубль
  «Статус-92» (269, ИНН 970512345688) — T-008; выпустить личный реп-код
  Основателю по новым правилам.

## Фазы

- **Ф1 (core)**: миграция `ambassadors.code` (unique, 6 симв., канон-алфавит);
  выдача амб-кода при назначении; привязка по двум таблицам (регистрация T-010
  + активация подписки); `POST /subscription/activate` принимает опциональный
  `promo_code` (вставка при отсутствии привязки, только на пустое); личный код
  Основателю AA-XXXX; тесты на все правила канона.
- **Ф2 (app)**: шит ввода промокода на кнопке «Подписаться» в блоке счёта
  (для непривязанных); QR амба; у Основателя — обе карточки кодов с QR/копированием.
- **Ф3**: G2 UI + G3 API/экран + G5 данные. Гейт каждой фазы: preflight 🟢,
  smoke-страж (горячий путь — подписка/ledger), приёмка владельца на стенде.

## Готово, когда

Регистрация по амб-коду И реп-коду работает; пользователь без промокода
подписывается с вводом кода в блоке счёта и получает личный код; Основатель
видит и шарит два кода (QR); назначает амба из интерфейса; видит счёт платформы
с распределениями; на staging у него активная подписка, два кода, три МСП
(АТМОСФЕРА/АКСИОМА/Grand verified).
