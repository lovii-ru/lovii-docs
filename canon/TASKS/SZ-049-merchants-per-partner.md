# SZ-049 — Мерчанты под юрлицами: создание мерчанта и видимость всех юрлиц

> Статус: **Сформулирована** (2026-09-17, из разбора кабинета команды)
> Приоритет: **P1** (блокирует сценарий «несколько юрлиц у владельца»)
> Исполнитель: **Super Z** (ядро) + `lovii-app` (экраны) · приёмка zcode
> Источник (владелец, 2026-09-17, дословно):
> «в рамках кабинета мсп у нас должны быть все юрлица, чтобы владелец мог добавить
> в любом юрлице в любую точку сотрудника»;
> «надо чтобы любой владелец мсп, после подтверждения своего инн мог добавить мерчантов,
> к каждому мерчанту свои бренды, и у каждого бренда должны быть свои торговые точки»;
> «мой профиль как раз создан таким что у нас несколько юрлиц и все подтверждены».

## 1. Терминология (синхронизация с владельцем)

Уровни владения: **юрлицо** (partner, появляется после подтверждения ИНН) →
**бренд** (= мерчант, витрина с логотипом — это ОДИН уровень, отдельного
«бренда под мерчантом» нет) → **торговые точки** (branches). В карточках и
интерфейсе говорить «юрлицо → бренд → точки».

## 2. Что уже работает (2026-09-17)

- Обзор отдаёт **мерчанты всех юрлиц** владельца (`MspAccess::merchants()` по
  активным membership) + `partner_id`/`partner_name` каждого бренда
  (core `f2a4f06`).
- Экран «Команда» (`cabinet/msp/team`): бренды сгруппированы по юрлицам,
  состав и «Ожидают принятия» следуют за выбранным брендом, приглашение уходит
  в юрлицо бренда — приглашать сотрудника можно в **любое** юрлицо.

## 3. Чего не хватает (суть задачи)

| # | Разрыв | Факт по коду |
|---|---|---|
| 1 | **Создать мерчанта под СУЩЕСТВУЮЩИМ юрлицем нельзя** | Право `merchant.create` в `PartnerRole` есть, но ни один роут его не использует; из приложения новый бренд появляется только через заявку нового юрлица (`POST /business/applications` — ИНН → счёт 1 ₽ → верификация) |
| 2 | **Юрлица без мерчантов не видны в кабинете** | Обзор строится от мерчантов; партнёр без мерчантов (пример: АКСИОМА) в списке брендов не участвует — владелец не видит, что юрлицо «пустое» |
| 3 | **Создание точки под брендом из приложения** | Право `branch.create` есть; роута/экрана в app нет — точки заводятся в b2b |

## 4. Что нужно сделать

1. **API**: `POST /api/v1/msp/merchants` (право `merchant.create`) — создание
   бренда под активным юрлицем владельца (название, логотип — как в карточке
   магазина); при одном юрлице выбор не спрашиваем, при нескольких —
   `partner_id` в теле. Ограничение: `partner_id` только из своих активных
   membership с правом `merchant.create`.
2. **API**: `GET /api/v1/msp/partners` (или расширение обзора) — список юрлиц
   владельца, включая пустые (без мерчантов), для экрана «Бренды».
3. **Экран «Бренды»** в кабинете МСП (или раздел в Обзоре): группы юрлиц →
   бренды → точки; у пустого юрлица CTA «Добавить бренд»; у бренда — CTA
   «Добавить точку» (`branch.create`).
4. Приглашение в команду уже умеет любое юрлицо — после п.1–3 сценарий
   «подтвердил ИНН → создал бренда → точку → пригласил сотрудника» замыкается
   полностью из приложения.
