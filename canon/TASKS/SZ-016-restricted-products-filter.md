## 1. Что

Механизм платформенного запрета на показ/продажу отдельных товаров в
импортных (Kuper) каталогах: товар есть у мерчанта, но на витрине и в заказе
он скрыт платформой, а не партнёром.

## 2. Как (предложение, Super Z уточняет по коду)

1. **Список запрещений платформы**: таблица/конфиг правил: шаблон названия или
   ИНН-группа/категория → действие `hide_storefront` (+ `hide_order` —
   жёсткий). Пример правила: `наименование ~ /энергетик/i → hide`.
2. **Применение**: на этапе индексации в витрину (`SyncSearchIndexCommand`,
   `shouldBeSearchable()` оффера/товара) и на этапе создания позиции заказа
   (guard) — скрытый товар нельзя купить даже прямой ссылкой.
3. **Управление**: правило добавляет/правит администратор (admin-панель или
   конфиг с выкладкой); отчёт «сколько товаров скрыто по каждому правилу».
4. **Журнал**: изменения правил — в аудит.

## 3. Не входит

- Возрастная верификация покупателя (18+ при выдаче/оплате) — отдельная тема,
  сейчас только скрытие из витрины/заказа.
- Категории МСП-точек (Пышки) — правила ориентированы на импортные каталоги,
  но технически применяются ко всем офферам (так честнее).

## 4. Приёмка

- Владелец: добавляем правило «энергетик» → товары с этим словом исчезают из
  витрины и недоступны в заказе; без правила — видны.
- zcode: приёмка кода (тесты правил, индексации, guard заказа).

## 5. Отчёт исполнителя (Super Z, 2026-09-10 — тело = commit message c126d5d)

- config/restrictions.php: правила платформы (pattern + hide_storefront/hide_order), выкладка = аудит через git;
- PlatformRestrictions: матчинг title (оффер + каталоговый товар), preg 'iu' + Postgres ~* совместимость; битые правила/регулярки не роняют витрину;
- витрина: GetStorefrontCatalogQuery фильтрует title !~* паттернами; shouldBeSearchable оффера/товара — скрытые не индексируются (витрина и поиск говорят одно);
- покупка: жёсткий гвард offer_restricted в SetCartItemAction и CheckoutBuilder (preview+place) — даже прямой ссылкой;
- artisan restrictions:report — счёт скрытых по каждому правилу;
- тесты Pest: unit (нормализация правил/матчинг/битые регекс-гарды) + feature (витрина-фильтр, shouldBeSearchable, гвард корзины/чекаута, отчёт); composer test — на стороне zcode;
- NB: Kuper product_requirements.is_restricted (18+) не заменяется — платформенные правила дополняют.
