# T-016 — Инструмент приёмки: сброс подписки и перевыпуск личного промокода без ручных правок БД

> Статус: **Открыта** (постановка Super Z по результатам приёмки Блока А 22.09)
> Приоритет: **P1** — обслуживающий инструмент живых приёмок (SZ-056/057, T-014)
> Исполнитель: zcode · Репо: `lovii-core` (консольная команда) · Постановка: Super Z

## Проблема

При живой приёмке владельцу нужно переоформить подписку и пере-выдать личный
промокод (копирование кода/ссылки не работает — доработка T-014/F-058; у
подписавшихся до SZ-057 кода может не быть — довыдача только при продлении
кроном). Ручные правки БД запрещены практикой: инъекции мимо машины состояний
рассинхронизируют проводки и статусы.

## Что сделать

1. Консольная команда core (tinker-однострочники не считать инструментом):
   сброс подписки пользователя в честное состояние машины (`user_cancelled`,
   отмена grace-переходов) + опционально перевыпуск личного промокода
   (переиспользовать `roles:issue-promo`), аргументы — телефон/ID юзера.
2. Команда действует только штатными механизмами модели (никаких прямых
   UPDATE мимо Eloquent/сервисов) и пишет лог своих действий.
3. Защита окружения: запуск запрещён на проде (env-гейт, как у payments-guard).

## Границы

- Биллинг подписки (SZ-053: каскад, retry, grace-cron) не менять — команда
  только переводит состояния штатными переходами; проводки подписки не
  трогаются и не разворачиваются этой командой.
- Зона core-billing не трогается (WORK_PROTOCOL §1.2).

## Разведка нового исполнителя (23.09) — факт-чек Super Z по origin/staging `16e062b`

- Переходы (`SubscriptionStatus.php:42–48`): Active достижим из
  GracePeriod/Suspended/Cancelled одним легальным переходом; Active→Active
  запрещён (BusinessException `invalid_status_transition` в
  `SubscriptionStatusMachine::transition`). Сброс из Active — через
  промежуточный статус либо идемпотентный no-op с отчётом в логе.
- Машина чистит только `grace_ends_at` (выход из grace);
  `suspended_at`/`cancelled_at`/`current_period_*` не сбрасываются —
  полный сброс требует `forceFill()`. Прецедент в ядре:
  `SubscriptionBillingService.php:79/:219/:490`. `forceFill()` — штатный
  Eloquent-механизм и пункту 2 постановки («никаких прямых UPDATE мимо
  Eloquent/сервисов») НЕ противоречит.
- Перевыпуск промокода: `RepresentativePromoService::issue()`
  (`app/Domain/Roles/Services/RepresentativePromoService.php:32`).
- Идиома env-гейта в командах: `app()->environment('production')`
  (прецедента отдельного env-флага в командах нет).
