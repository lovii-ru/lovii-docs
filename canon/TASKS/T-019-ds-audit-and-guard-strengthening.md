## Что сделать

### Фаза А — Аудит (read-only, produce discrepancies report)

А.1. **Сканировать все `.vue`/`.scss` в `src/modules/` + `src/scss/`** на 4 категории
нарушений (которые DS-guard сейчас НЕ ловит):
- **padding/margin/gap-литералы** — `padding: 16px` / `margin-top: 12px` / `gap: 14px`
  не через `var(--lv-pad-x)` или токен-шкалу;
- **font-size/font-family-литералы** — `font-size: 14px` / `font-family: 'Inter'` не
  через `var(--lv-font)` или font-scale систему (см. SZ-076 session 129: `calc(var(--font-scale,1) * Npx)`);
- **сабхедер** — экраны без `<AppPageHeader>` или с `.set-sub` не следующими
  `--lv-subheader-h: 48px` (отлип от хедера, не sticky, неправильный gap);
- **text overflow** — блоки (`.row-item`, `.list-card`, `.seg` и т.д.) где текст может
  превысить контейнер (нет `overflow-wrap`/`text-overflow: ellipsis`/`min-width: 0` для
  flex-детей).

А.2. **Scope**: все недавно добавленные/изменённые экраны на staging (коммиты с 2026-09-13
до текущего HEAD) — определить по `git log --name-only` (transfers/settings/loyalty/wallet/
representative/platform). Плюс 3 названных явно (transfers, settings, MSP loyalty ×10).

А.3. **Скриншот-регрессия** (Playwright, 390 и 1280, светлая/тёмная) — всех аудит-экранов,

### Фаза Б — Усилить DS-guard (код + baseline)

Б.1. **Добавить правила в `design-system.guard.test.ts`**:
- `padding-literal` — `padding`/`padding-*` в px без `var(--lv-*)` (кроме `0`);
- `margin-literal` — `margin`/`margin-*` в px без `var(--lv-*)` (кроме `0`);
- `gap-literal` — `gap`/`row-gap`/`column-gap` в px без `var(--lv-*)` (кроме `0`);
- `font-size-literal` — `font-size` в px без `var(--lv-*)` или `calc(var(--font-scale,...))`;
- `font-family-literal` — `font-family` не `var(--lv-font)`/`inherit`;
- (опционально) `max-width-literal` — не `var(--lv-content-max)`/`--lv-container*`.

Б.2. **Разумные исключения** (чтобы не завалить CI на компонент-внутреннем микро-спейсинге):
- разрешить `padding: 0` / `margin: 0` / `gap: 0` (часто нужен для сброса);
- разрешить литералы в `src/scss/tokens.scss` и `src/scss/lovii-tokens.scss` (это файлы
  токенов — там литералы — определение токенов);
- микро-спейсинг `< 8px` (1-7px) — обсудить с владельцем порог (см. Фаза В).

Б.3. **Жёсткий на локальной сборке**: `yarn test` (format → lint → unit → type-check →
build + DS-guard) — DS-guard должен **сразу показывать ошибки** с указанием `file:line` и
токеном-кандидатом, не дожидаясь CI. Добавить человеко-читаемый вывод (не только
«baseline regression»).

Б.4. **Baseline**: пересчитать `design-system.baseline.json` через `DS_GUARD_UPDATE=1`
после добавления правил — зафиксировать текущий долг (A4: свести к минимуму по итогу
аудита — это Фаза Д, не Б; здесь — только зафиксировать).
