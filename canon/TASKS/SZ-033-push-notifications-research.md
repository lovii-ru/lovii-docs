## 1. Разделение с SZ-010

В SZ-010 уже проработано (НЕ дублируем): архитектура Web Push/VAPID,
таблица `push_subscriptions`, NotificationService с каналами, SW-обработчики,
iOS 16.4 «только установленная PWA» — одним абзацем.

SZ-033 закрывает то, чего в SZ-010 нет, чтобы реализация начиналась без
вопросов:

1. **Матрица сред РФ (факт-чек по официальным докам):** iOS Safari (PWA
   установлена / обычная вкладка), Android Chrome, Яндекс.Браузер,
   десктопные браузеры; webview-среды — VK/MAX/TG мини-аппы (SZ-014) и
   in-app браузеры: пуш web-страницы там не работает → каким каналом
   этих пользователей покрываем (боты живы).
2. **UX согласия**: soft-ask паттерн (не по заходу; после ценного
   действия — например после первого заказа), экран-подсказка «установите
   на главный экран» для iOS, состояние отказа/повторного запроса,
   управление подпиской в шите «Настройки» приложения (куда ляжет
   будущий тумблер — паттерн уже есть, session 022 app).
3. **Канальная матрица «событие × канал»**: push vs Telegram vs MAX vs
   e-mail (SZ-009) по событиям (статусы заказа покупателю, новый заказ
   продавцу, промо) — где push незаменим (нет бота), где избыточен;
   правило анти-дублей (одно событие — один канал по предпочтениям).
4. **MVP-приоритизация и 🔶-решения владельца**: минимальный первый
   релиз (кому и о чём), что отложить; каждый 🔶 — закрывающий выбор
   из вариантов.
