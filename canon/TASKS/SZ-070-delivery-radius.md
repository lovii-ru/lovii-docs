# SZ-070 — Гео-зона доставки = простой радиус от адреса точки

> Статус: **Открыта**
> Приоритет: P2 (решение владельца 21.09 по П-2)
> Источник: диктовка владельца 2026-09-21; `as-is/00` П-2
> Исполнитель: zcode · Репо: `lovii-core` (+ UI радиуса в `lovii-b2b`/`lovii-app`) ·
> Дата постановки: 2026-09-21

## Решение владельца (21.09, канон)

- Зона доставки — **простой радиус относительно адреса точки** (без полигонов).
- **За радиусом оформить заказ С ДОСТАВКОЙ нельзя**; с **самовывозом — можно**.
  Смысл: не терять дальних покупателей, поднимая средний чек и число заказов.

## Что проверить/сделать (staging — точка интеграции)

- `MerchantDeliveryZone` существует в ядре и читается чекаутом
  (`CheckoutBuilder`); текущее поведение «первой активной зоны» — заменить на
  выбор **содержащей** точки адреса, для радиус-модели — сравнение расстояния
  точка↔адрес (PostGIS уже в стеке: `ST_DWithin`/haversine — на усмотрение).
- Радиус задаётся на точке (b2b-настройка; в app — базовая версия в рамках
  SZ-068, если попадает в её скоуп).
- Чекаут: если доставка не проходит радиус — блокировать ТОЛЬКО доставку
  (честный текст «точка не доставляет сюда — доступен самовывоз»), самовывоз
  остаётся доступным; не повторять UX-баг SZ-036 (пустой экран).
- Ошибка `delivery_not_supported` (422) сохраняется, но с явной подсказкой
  про самовывоз в UI.

## Готово, когда

- Адрес в радиусе → доставка доступна; вне радиуса → доставка честно
  недоступна, самовывоз оформляется.
- Настройка радиуса на точке работает через UI (не через SQL).
- Тесты: пограничные случаи (на границе радиуса, без координат адреса,
  точка без зоны = доставка выключена), гейты зелёные, живой прогон.
