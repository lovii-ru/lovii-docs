## Зачем

Приложение выросло волнами: витрина, кабинеты МСП и ролей накопили расхождения
в паттернах, перекрытия навигацией, «сырые» экраны и неполные состояния.
Точечные правки не решают проблему: нужен единый контур ревизии с очередью,
исполнителем, независимым ревьюером и публичной фиксацией решений.

## Что сделано 19.10

- Создан публичный репозиторий `rucorp/lovii-app-revision` (public, GitHub Pages,
  branch protection: PR + 1 approval + conversation resolution).
- Опубликованы: устав, процесс трио, доступы, дорожная карта, карта 60 страниц
  и 9 модалок, стандарт качества, стандарт доказательств, чек-лист SZ,
  реестр находок (25 позиций), 13 постановок задач W0–W6.
- Созданы 13 issue с метками `executor:arena` / `reviewer:sz` / `wave:*` /
  `priority:*` и вехами W0–W6.
- Доступ: Арена — через GitHub App (доступ к публичному репо и приватному
  `lovii-app`); SZ — через fine-grained PAT владельца (repo-only, два репо).
  Секреты в публичный репозиторий не попадают.
- Подготовлены брифы первого запуска: `docs/handoff-arena.md`,
  `docs/handoff-sz.md`, `docs/handoff-owner.md`.

## Роли

- **Арена** — одна задача за сессию: ветка `arena/<session>-<task>`, реализация,
  PR в `staging`, отчёт и evidence. Не мержит и не закрывает issue.
- **SZ** — независимая проверка дифа, гейтов, трёх viewport, состояний, a11y,
  текстов и регрессий. Вердикт: `ACCEPT` / `ACCEPT WITH NITS` /
  `CHANGES REQUIRED` / `BLOCKED`.
- **Координатор** — очередь, контекст, ruling по трактовкам, приёмка, squash,
  закрытие, канон.
- **Владелец** — продуктовые развилки, финальное «го», демо W6.

## Границы публичного репозитория

Публично: устав, процесс, карта экранов, критерии, задачи, решения,
санитизированные доказательства.
Не публично: исходный код, секреты, PII, внутренние адреса/порты, детали
security-аудита и платёжной логики.

## Риски

1. **Публичность.** Скриншоты и постановки видны всем. Смягчение: только
   санитизированные кадры, без кода и PII; правило в `ACCESS.md`.
2. **Пересечение с текущими волнами app.** Ревизия идёт от `staging`; мерж
   только после свежего среза и зелёных гейтов.
3. **Расползание объёма.** Одна задача = один PR; находки вне задачи — отдельный
   issue.
4. **Разные планки.** Единый контракт приёмки W0-002; без evidence — `CHANGES`.
