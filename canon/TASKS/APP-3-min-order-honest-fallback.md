# APP-3 — мин-чек точки: пустое поле не должно превращаться в 500 ₽

> Открыт 09.10 (session 152). P2. Реализация 09.10, lovii-app.

## Факт

`parsedMinOrder()` парсит пустое поле в 0 («без своего минимума»); клэмп
`value < floor → floor` поднимал 0 → 500 и отправлял 500 как СОБСТВЕННЫЙ
минимум точки. Подпись поля обещает «пусто = рекомендованный минимальный чек
(600 ₽)» — текст противоречил поведению.

Ядро (`UpdateMspBranchSettingsController`): 0 и null → `min_order_amount = NULL`
→ работает платформенный дефолт 600 ₽. Т.е. правильное «пусто» = 0/null без клэмпа.

## Решение

Клэмп только для введённых положительных значений ниже пола
(`effectiveMinValue > 0 && value < floor`). Пустое поле уходит нулём,
ядро превращает его в NULL, чекаут работает по дефолту 600 ₽.

## Критерий приёмки

- [x] Пусто → уходит 0 (тест «очищенное поле…» остаётся зелёным).
- [x] 0 не клэмпится до пола (новый тест APP-3).
- [x] Введённые 300 ₽ поднимаются до пола 500 ₽ (новый тест APP-3).
- [x] Гейт app 🟢.
