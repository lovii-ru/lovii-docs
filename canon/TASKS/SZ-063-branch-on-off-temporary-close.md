## Контекст (проверено 2026-09-21)

Сегодня «включить/выключить точку» доступно **только в b2b-кабинете**, в приложении
такого управления нет вообще; владелец считает это пропажей (в очередь задач пошло
именно так). Факты:

- `merchant_branches.status` — `varchar(20) NOT NULL DEFAULT 'active'`, значения —
  enum `App\Domain\Merchant\Enums\BranchStatus` = `active | inactive | closed`
  (lovii-core). Отдельного `is_active` у точки нет.
- Витрина и каталог читают **только** `active`: `app/Application/Home/Queries/GetHomeQuery.php:87,102,129`,
  `app/Application/Home/Queries/GetPopularStoresQuery.php:51,73`,
  `app/Application/Merchant/Queries/GetStoresQuery.php:55`,
  `app/Models/Core/MerchantBranch.php:100` (`scopeActive`).
- Чекаут без активной точки: `app/Domain/Checkout/Services/CheckoutBuilder.php:79` → `merchant_closed`.
- В b2b статус правится селектом: `lovii-b2b/app/Filament/Resources/BranchResource.php`
  (секция «Основное», рядом `name`).
- В приложении экран «Настройки» кабинета МСП (`lovii-app/src/modules/roles-module/msp/MspBranchSettings.vue`)
  статус точки не показывает и не меняет; контракт ядра
  (`app/Http/Controllers/Api/V1/Msp/ShowMspBranchSettingsController.php`,
  `UpdateMspBranchSettingsController.php`) принимает только `name`, `address_line`,
  `working_hours`, `min_order_amount_rubles`.
- Права: правка настроек точки — `branch.update` (`App\Domain\Merchant\Services\MspAccess`);
  у роли `operator` этого права нет, у владельца и администратора — есть.
- Существует гейт видимости мерчанта уровня точки (`StorefrontState::Teaser/Hidden/Active`,
  SZ-035) — он про мерчанта, не про статус точки; не путать.

## Что сделать (решения принимает исполнитель, обоснование — в отчёте)

1. **Включение/выключение точки из приложения.** Дать владельцу МСП гасить и
   поднимать точку с телефона. Решить и явно описать:
   - что значит «точка выключена» для покупателя (точка исчезает из каталога и
     «рядом» / остаётся страница точки со статусом «закрыто» / что-то третье);
   - что происходит с корзинами и незавершёнными заказами на выключенной точке
     (сборка корзины, превью чекаута, уже созданный заказ — у каждой поверхности
     своё поведение, сейчас они читают разные признаки);
   - как это сочетается с `working_hours` (график) и с `is_24h` — покупателю
     нельзя показывать два противоречащих состояния сразу.
2. **Временное закрытие точки (как в Яндекс Картах): 30 минут / 1 час.** Из
   приложения, с автоматическим возвратом точки в работу по истечении срока и
   возможностью отменить закрытие вручную. Решить: отдельная ли это сущность или
   значение `closed` + срок; что видит покупатель (и когда именно — «откроется в
   HH:MM»); что видит сама точка и её команда; что происходит с заказами, которые
   попали в окно закрытия; как это уживается с расписанием и с п.1.
3. **Честное отображение состояния точки в кабинете МСП** — включена / выключена /
   временно закрыта до HH:MM. Сегодня экран показывает только часы и минимум заказа,
   поэтому владелец не видит, в каком состоянии его точка для покупателя.
4. **Права ролей точки** на оба действия: кто может (владелец, администратор,
   сотрудник). По умолчанию сотрудник прав не получает — подтверди это осознанно
   или измени; матрица прав живёт в `SZ-038`/`SZ-047`.
5. **Тесты и живые проверки**: сценарий «выключил → покупатель не видит/не может
   заказать → включил → вернулось» и сценарий временного закрытия с авто-возвратом
   (проверяется без ожидания реального часа — время в тестах управляемое).

## Что не делать

- Не менять молча семантику статуса точки в b2b (`active|inactive|closed`) и не
  ломать существующие фильтры витрины: b2b-кабинет продолжает работать как есть.
- Не трогать биллинг, подписки, выплаты и пул — задача про видимость точки.
- Не менять публичные контракты чужих эндпоинтов (витрина/чекаут) так, чтобы это
  требовало синхронной правки в репозиториях вне объёма (если требуется — сначала
  вернуть вопрос).
- Не пушить в `staging`/`master` без явного «го» владельца, не трогать прод-данные.

## Приёмка

- Из приложения владелец МСП выключает точку → покупатель на витрине не может
  заказать на этой точке; обратное включение возвращает точку. Проверено живьём
  на стенде, поведение всех трёх состояний экрана показано.
- Временное закрытие на 30 мин / 1 час: покупатель видит честный статус с временем
  открытия; точка возвращается в работу автоматически; отмена вручную работает.
- Тесты: новое поведение покрыто (в т.ч. права ролей: сотрудник → отказ);
  витринные выборки не деградировали (стражи из корневого `CLAUDE.md`: `smoke.sh`
  перед мержем горячих путей, `db.slow_requests` без всплеска).
- `yarn test` (app) / `composer test` (core) зелёные; при затрагивании горячих
  путей — прогон стресс-стража на локальном стенде и сравнение с базлайном.
