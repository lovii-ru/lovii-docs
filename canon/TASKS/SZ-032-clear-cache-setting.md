# SZ-032 — «Очистить кэш» в настройках приложения (самопомощь при PWA-квирках)

> Статус: **На приёмке** (app `0fdf130` «Очистить кэш
> и обновить»: строка в шите «Приложение», подтверждение двойным тапом 4с
> вместо отдельного AppBottomSheet — меньше шагов, reload после очистки;
> hint честно перечисляет, что сохранится). Постановка (2026-09-10, zcode
> по запросу владельца — пачка улучшений настроек)
> Приоритет: **P2** — сейчас сброс устаревшего SW вручную (DevTools),
> что владелец делает регулярно; действие разрушающее → делаем аккуратно
> Исполнитель: Super Z · Репо: `lovii-app` · Гейт: `yarn test`
> База: session 022; грабли PWA-кэша задокументированы в памяти воркспейса
> (SW прячет новые API, сброс обязателен при каждой приёмке стенда)

## 1. Контекст

Приложение — PWA (vite-plugin-pwa, generateSW, прекэш ~163 записей).
Известная боль: устаревший service worker прячет свежий UI/API, владельцу
при каждой приёмке надо вручную снимать SW в DevTools. Кнопка в настройках
делает это самопомощью — и для владельца, и в будущем для поддержки
пользователей.

## 2. Задача

- Строка «Очистить кэш» внизу шита «Настройки» — после версии (SZ-031),
  деструктивный акцент в системе приложения (как «Выйти» в профиле —
  negative-цвет, но строка, не кнопка на весь экран).
- **Подтверждение обязательно**: AppBottomSheet «Очистить кэш приложения?»
  с честным текстом: приложение перезагрузится; кэш обновится; данные
  аккаунта, заказы и адреса НЕ пострадают (они на сервере). Кнопки
  «Отмена» / «Очистить» (negative) — паттерн подтверждения выхода.
- Действие: `caches.keys()` → удалить все кэши, SW-регистрации разрегистрировать
  (`getRegistrations()` → `unregister()`), затем `location.reload()` — SW
  перерегистрируется и пересоберёт прекэш сам.
- Если SW/caches API недоступны (старый браузер) — строку не показывать.
- Пограничное: не чистить localStorage (там токен, адрес, настройки темы —
  их трогать нельзя). Только Cache Storage + SW.

## 3. Ожидаемый конечный результат (приёмка zcode)

1. Сценарий «устаревший кэш»: захардкоженная старая сборка в IAB → кнопка →
   перезагрузка → свежая сборка работает, повторный вход не требует
   ре-логина (токен цел).
2. «Отмена» в подтверждении ничего не делает; SW и кэши на месте.
3. Юнит-тесты: подтверждение открывается/отменяется/подтверждается
   (caches/reload замокать); строка скрыта без SW API; `yarn test` 🟢.
4. В доке-отчёте (session) — что именно чистится и что НЕ чистится,
   поведение на iOS standalone (SW перерегистрация после reload).
5. Кнопка НЕ видна гостю в состоянии, где шита нет (гость шит настроек
   тоже видит? — проверить: сейчас шит доступен из профиля авторизованному;
   у гостя профиль = экран входа, значит ок, но проверить явно).

## 4. Приёмка владельца

Стенд обновили, у него в PWA старьё → открыл настройки → «Очистить кэш» →
приложение само стало свежим, без DevTools.
