## 1. Цель

Довести промо-механики из демо до продукта в двух уровнях:

1. **Базовый конструктор — в приложении.** Владелец точки настраивает акции прямо
   в `lovii-app` (раздел кабинета точки, как в демо), без отдельного веб-кабинета.
2. **Сложные механики — в `lovii-b2b`.** Расширенные правила и массовые настройки
   по сети точек — в кабинете партнёра. Оба входа пишут в **один конструктор**.

Покупатель видит акцию, понимает выгоду и приходит в **конкретную торговую точку**,
где всё отображается и работает корректно.

| Ротация | Акции на главной **ротируются** | `BRD.md` §7.3.1 |

## 3. Объём механик

| Механика | Триггер | Что видит покупатель |
|---|---|---|
| Кэшбэк по умолчанию / группы | любой заказ | процент на карточке, сумма в корзине |
| Порог чека | чек ≥ N ₽ | «Кэшбэк +N%» / «Подарок от N ₽» |
| Комбо | 2+ товара | комбо-товар в **категории «Комбо»** точки |
| Штампы «N-й в подарок» | N товаров категории | «Штампы 2 из 6», подарок |
| Счастливые часы | дни недели + интервал | «Счастливые часы · +N%» |
| Бюджет + авто-стоп | исчерпание лимита | акция тихо выключается |

## 5. Работы

### 5.1 `lovii-core` — модель, движок, API

1. **Модель:** `promo_rules` (`merchant_id`, `branch_id`, `type`
   `cashback|threshold|combo|stamps|hours`, `trigger/reward/limits/storefront`
   jsonb, `priority`); `loyalty_product_groups` + пивоты; комбо — оффер
   `merchant_offers.offer_type='bundle'` + `merchant_offer_bundle_items`;
   бюджет (`limits.budget`, `limits.autostop`, учёт расхода). Миграция переносит
   текущую глобальную строку как `type='cashback'`, `merchant_id=NULL`.
2. **Движок** `App\Domain\Promo\PromoResolver`: приоритеты (товар → категория →
   группа → умолчание), стекирование, окно часов, штампы, бюджет. База кэшбэка —
   **фактически оплаченная сумма** (после скидок). **Без потолков** — значения
   точки не ограничиваются. Контракт `LoyaltyService` (идемпотентность
   earn/refund) сохранить.
3. **Актуальность без задержки:** сохранение правила инвалидирует кэш правил
   (Redis) — следующее чтение витрины отдаёт новое состояние.
4. **API:**
   - `GET /api/v1/promos` — лента активных акций для главной, ротация; в каждой
     записи **`branch_id` (+ `merchant_id`) для перехода к точке**;
   - `GET /api/v1/storefront/promos?branch_id=` — акции точки;
   - витрина точки: категория **«Комбо» первой** в ответе `storefront/info`
     (авто-категория из активных комбо-офферов);
   - расширить `StorefrontOfferCard`: `cashback_percent`, `promo_badges[]`,
     `bundle` (состав комбо);
   - `POST /orders/preview` — разбивка выгоды (`cashback`, `bonus_total`,
     `gifts[]`, `stamps{have,count}`, `hours_pct`);
   - `POST /orders/checkout` — применение правил;
   - **конструктор для приложения:** эндпоинты чтения/записи правил от лица
     владельца точки (право по матрице `PartnerRole`), те же, что использует `b2b`.
5. **Производительность:** без N+1, тяжёлое — в очередь; при изменении горячих
   путей — страж SZ-060.

### 5.2 `lovii-app`

1. **Кабинет точки → новый раздел «Акции»** (базовый конструктор, как в демо):
   экран `src/modules/roles-module/msp/MspLoyalty.vue` + дочерние представления
   (кэшбэк/группы, порог чека, комбо, штампы, часы, бюджет); маршрут рядом с
   `MspOverview`, вкладка в `cabinetTabs` с новым правом (напр. `loyalty.manage`
   или `merchant.update` — согласовать с матрицей `PartnerRole`).
2. **Витрина точки:** категория **«Комбо» первой** (`StoreCategories.vue`),
   товары категории — комбо-офферы; блок «Акции точки»; бейджи на товарах
   («Кэшбэк N%», «Комбо −X%»).
3. **Главная:** заменить статичный `HomeBanner` на **API-блок акций с ротацией**;
   тап ведёт на `/stores/{branch_id}`.
4. **Карточка товара / корзина / чекаут:** процент и баллы, состав комбо,
   разбивка выгоды (часы, штампы, подарки) — одинаково в корзине и на чекауте.
5. **Переход «акция → точка»:** есть `branch_id` — прямо на точку; только
   `merchant_id` — на ближайшую его точку (`/home` → `near_you`); иначе честный
   текст, не битая ссылка.
6. **Качество** (`canon/PRODUCT_QUALITY_BAR.md`): mobile-first 390px+, три
   состояния, токены `lovii-design`, тап ≥44px, деньги через `formatPrice`, a11y.

## 7. Критерии приёмки
1. Владелец точки настраивает акцию **из приложения** (раздел «Акции»), она
   появляется у его точки **сразу** после сохранения.
2. Карточка акции на главной ведёт на торговую точку; промо-блок **ротируется**;
   битых ссылок нет ни при `branch_id`, ни при `merchant_id`.
3. На витрине точки **«Комбо» — первая категория**; если других категорий нет —
   она всё равно есть и содержит комбо-офферы.
4. Товар из группы показывает свой процент; вне групп — умолчание; **потолков
   нет** (значение точки не подрезается).
5. Кэшбэк считается от **фактически оплаченной** суммы.
6. Корзина и чекаут показывают одинаковую разбивку, совпадающую с начислением.
7. Штампы срабатывают один раз на N-й позиции; бюджет гасит акцию без ошибок у
   покупателя; отмена/возврат возвращает начисленное.
8. Три состояния и адаптив; гейты зелёные; сессия-док и `status.md` обновлены.

- Не менять контракт `wallet_transactions` и не ломать возвраты.
- Не вводить платформенные потолки % (решение владельца) — только модерация.
- Не хранить числа промо в производных доках — только `PARAMS.md`.
- Не тянуть синхронные внешние вызовы в request path.
- Не оставлять демо-заглушки в прод-данных.
