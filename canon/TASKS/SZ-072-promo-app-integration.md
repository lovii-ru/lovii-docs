## 1. Цель

Довести промо-механики из демо до рабочего продукта: партнёр настраивает акции
(кэшбэк, группы товаров, порог чека, комбо, штампы, счастливые часы, бюджет),
а покупатель в `lovii-app` **видит их, понимает выгоду и приходит в конкретную
торговую точку**, где акция корректно отображается и применяется.

Ключевое требование владельца (дословно): *«акции вели к торговой точке и там
всё это корректно отображалось, и всё работало»*.

## 2. Объём механик (из демо)

| Механика | Триггер | Что видит покупатель |
|---|---|---|
| Кэшбэк по умолчанию / группы | любой заказ | процент на карточке товара, сумма в корзине |
| Порог чека | чек ≥ N ₽ | «Кэшбэк +N%» / «Подарок от N ₽» в итогах |
| Комбо | 2+ товара | товар-комбо в каталоге точки со составом и скидкой |
| Штампы «N-й в подарок» | N товаров категории | «Штампы 2 из 6», подарок |
| Счастливые часы | дни недели + интервал | «Счастливые часы · +N%» |
| Бюджет + авто-стоп | исчерпание лимита | акция выключается, покупателю ничего не ломается |

## 3. Что есть сейчас (факты)

**`lovii-core` (API):**
- единственное глобальное правило: `loyalty_rules`
  (`database/migrations/2025_01_01_000024_create_loyalty_rules_table.php`),
  начисление и списание — `app/Domain/Loyalty/Services/LoyaltyService.php`

  `GET /api/v1/wallet`, `GET /api/v1/wallet/transactions` (`routes/api.php:266–267`).

**`lovii-app` (Vue 3 + TS + Vite + Pinia):**

  (`src/package/global-types/api/catalog.ts:155–167`) — `id`, `title`, `price`
  (**копейки**), `old_price`, `unit_*`, `image_url`, `requirements`. **Полей
  промо нет.**
- модули: `home-module` (`HomeModule.vue`, `HomeBanner.vue`,
  `api/home-api.ts`), `store-module`, `store-product`, `cart-module`
  (`CartInfo.vue`, `CartProduct.vue`), `create-order` (`CreateOrder.vue`),
  `profile-balance` (баллы).
- промо-блок сейчас — **статические картинки** в `HomeBanner.vue` (локальные
  `assets/images/banners/*.webp`), без API, без ссылок. Это и есть главный
  разрыв для требования «акции ведут к точке».

## 4. Работы

### 4.1 `lovii-core` — модель, движок, API

1. **Модель** (миграции; сверх дизайна `loyalty/`):
   - `promo_rules` — обобщение `loyalty_rules` (`merchant_id`, `type`
     `cashback|threshold|combo|stamps|hours`, `trigger/reward/limits/storefront`
     jsonb, `priority`); глобальная строка миграцией переносится как
     `type='cashback'`, `merchant_id = NULL`;
   - `loyalty_product_groups` + `loyalty_group_categories/_products`;
   - комбо — оффер: `merchant_offers.offer_type='bundle'` +
     `merchant_offer_bundle_items`;
   - бюджет: `limits.budget`, `limits.autostop`, учёт `spent` (поле/счётчик).
2. **Движок** `App\Domain\Promo\PromoResolver`: резолвинг по позиции
   (товар → категория → группа → умолчание → платформенное), приоритеты,
   стекирование, лимиты/бюджет, окно «счастливых часов», штампы. Контракт
   `LoyaltyService` (идемпотентность earn/refund по
   `wallet_transactions`) **сохранить**.
3. **Производительность**: без N+1 в request path, правила кэшировать
   (Redis), тяжёлое — в очередь; при изменении горячих путей прогнать страж
   SZ-060 (`lovii-app/scripts/stress/README.md`).
4. **API (новое/расширение)** — имена согласовать с `canon/API_SPEC.md`:
   - `GET /api/v1/promos` — лента активных акций для главной; в каждой записи
     **обязательно `branch_id` (+ `merchant_id`) для перехода к точке**;
   - `GET /api/v1/storefront/promos?branch_id=` — акции конкретной точки
     (блок «Акции точки» + бейджи товаров);
   - расширить `StorefrontOfferCard`: `cashback_percent`, `promo_badges[]`,
     `bundle` (состав комбо);
   - `POST /api/v1/orders/preview` — ответ с разбивкой выгоды
     (`cashback`, `bonus_total`, `gifts[]`, `stamps{have,count}`, `hours_pct`);
   - `POST /api/v1/orders/checkout` — применение правил при размещении заказа.

### 4.2 `lovii-app` — применения в интерфейсе

1. **Главная** (`home-module`): заменить `HomeBanner` (статичные картинки) на
   **API-блок акций**: карточка акции → тап ведёт на `/stores/{branch_id}`
   (торговая точка). Состояния: скелетон / пусто (блок скрывается) / ошибка.
2. **Страница точки** (`store-module`): блок **«Акции точки»** над каталогом;
   на карточках товаров — бейдж «Кэшбэк N%» / «Комбо −X%».
3. **Карточка товара** (`store-product`): процент кэшбэка и баллы; для комбо —
   состав и зачёркнутая цена.
4. **Корзина** (`cart-module`): под позицией «Кэшбэк N% · +K балл.»; в итогах
   «Счастливые часы», «Штампы X из N», подарки.
5. **Чекаут** (`create-order`): те же строки выгоды до подтверждения заказа.
6. **Переход «акция → точка»**: если у акции задан `branch_id` — ведём прямо на
   точку; если только `merchant_id` — на ближайшую точку мерчанта (данные
   `/home` → `near_you`), с честным текстом, если точки рядом нет.
7. **Качество** (`canon/PRODUCT_QUALITY_BAR.md`): mobile-first 390px+, три
   состояния, токены `lovii-design` (без локальных цветов), тап ≥44px,
   деньги — через `formatPrice`, a11y (контраст AA, подписи).

## 6. Критерии приёмки (проверяемые)

1. Партнёр включает акцию в кабинете → она появляется в `lovii-app` у его точки
   **в течение X минут** (согласовать: кэш/инвалидация).
2. С главной карточка акции ведёт **на торговую точку** (`/stores/{branch_id}`),
   где виден блок «Акции точки» и бейджи на товарах; битой ссылки нет ни при
   `branch_id`, ни при `merchant_id`-онли.
3. Товар из группы показывает свой процент; товар вне групп — процент по
   умолчанию.
4. Комбо-товар в каталоге показывает состав и цену со скидкой; попадает в заказ
   как одна позиция.
5. Корзина и чекаут показывают одинаковую разбивку: кэшбэк по позициям, часы,
   штампы, подарки; суммы совпадают с начислением после оплаты.
6. Штампы: на N-й позиции категории подарок применяется один раз, повторно —
   нет.
7. Бюджет: при исчерпании лимита акция выключается сама, покупатель не видит
   ошибок и не теряет уже начисленное.
8. Отмена/возврат заказа возвращает начисленное (контракт `refund` сохранён).
9. Три состояния (загрузка/пусто/ошибка) у промо-блока, страницы точки и
   корзины; экраны не разваливаются на 390px и на десктопе.
10. Гейты зелёные; сессия-док и `status.md` обновлены.

- Стенд: приёмка на `app-staging.lovii.ru` + `api-staging.lovii.ru`.
- При изменении горячих путей (каталог/корзина/чекаут) — прогон стража SZ-060
  на локальном стенде.

## 8. Стоп-лист
- Не менять контракт `wallet_transactions` (идемпотентность) и не ломать
  возвраты.
- Не хранить числа промо в производных доках — только ссылка на `PARAMS.md`.
- Не тянуть синхронные внешние вызовы в request path (только очередь).
- Не публиковать акции в прод-пути при выключенном `PRODUCT_QUALITY_BAR`
  чек-листе (сначала сверка с каноном дизайна `lovii-demo`/`lovii-design`).
- Не использовать демо-заглушки в прод-данных.
