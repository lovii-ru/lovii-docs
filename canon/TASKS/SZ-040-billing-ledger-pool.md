# SZ-040 — Рублёвый ledger (A-1) + пул 40/40/20 (A-2)

> Статус: **Открыта** (zcode, 2026-09-11; владелец: «го» на A-1+A-2 после приёмки SZ-039)
> Приоритет: **P1** — деньги контура: один баланс на профиль / один на ИНН
> Исполнитель: zcode · Репо: `lovii-core` (UI b2b/app — следующей задачей A-3/A-4)
> Гейт: `docker exec lovii-core-app-1 composer test`
> Источники: FIN_BALANCE_REFERRAL_BRIEF v0.5 (A-1, A-2), FINANCIAL_MODEL §2.6,
> BRD §7, §9.4, SAGA-2, решения владельца №2 (pull), №9 (баллы = пул 10% без комиссии)

## 1. A-1 — счета и проводки (рублёвый контур)

- `accounts`: владелец = `user` (профиль: покупатель/представитель/амбассадор),
  `partner` (ИНН точки) или `platform` (Компания). Ровно один счёт на владельца,
  баланс в копейках, обновляется в одной транзакции с проводкой (row-lock).
- `ledger_entries`: append-only — счёт, тип, сумма со ЗНАКОМ (+приход/−расход),
  ссылка на источник (order/payment — морф), аналитика: merchant_id, branch_id,
  канал оплаты, роль в сплите, meta jsonb. Без updated_at.
- Инвариант (тест): `balance = Σ(знаковых amount)` по счёту. Идемпотентность
  постинга: unique (source_type, source_id, type, account_id).

## 2. A-2 — распределение при подтверждённом платеже

Триггер — тот же CONFIRMED вебхука Т-Банка (после кэшбэка SZ-039). T = заказ,
копейки, ROUND_HALF_UP:

```
platform   = round(T × 10%)                     # нагрузка канона: 90/10
fee        = max(round(T × ставка канала), 349) # карта 3,16% / СБП 0,7% / T-Pay 2,59%
                                                # оплата баллами: fee = 0 (решение №9)
pool       = platform − fee
point      = T − platform                       # выручка точки на счёт ИНН
company    = round(pool × 40%)                  # доли сплита
rep        = round(pool × 40%)
ambassador = round(pool × 20%)
remainder  = pool − сумма долей → Компания      # сумма долей = пул ровно
```

Проводки (Σ = T − fee = фактическое зачисление от банка):
- точка (partner-счёт ИНН): `+point` — тип `order_income`;
- Компания (platform-счёт): `+company`, тип `pool_share`;
- представитель (user-счёт): `+rep`, тип `pool_share`;
- амбассадор (user-счёт): `+amb`, тип `pool_share`.

Резолв представителя: заявка точки (`partner_applications` по branch_id) с
`representative_user_id` + `rep_approved_at` (SZ-038 фаза 1). Амбассадор:
активный код представителя → префикс → активный `ambassadors` (SZ-038).
Нет связки / амбассадор неактивен / представитель не подтверждён → его доля
уходит Компании (EC-33/EC-11). Гейт подписки представителя — флаг
`billing.rep_subscription_gate` (default off) до Б-3; Kuper-импорт без заявки
в контур не попадает (доля Компании).

Канал оплаты: `payments.method` пока нет — default `card` (3,16%); ветки
СБП/T-Pay/баллы готовы в конфиге ставок, включатся с появлением канала.

## 3. Тесты (гейт)

- Табличные BRD §9.4: заказ 1000 ₽ карта → точка 900, Компания 27,36,
  реп 27,36, амб 13,68, банк 31,60; остаток округления → Компания; мин-комиссия.
- Не резолвится реп/амб → доли Компании; только МСП со связкой.
- Двойной CONFIRMED → по одному постингу (идемпотентность).
- Инвариант баланса; конкурентность (два постинга в одной транзакции).
