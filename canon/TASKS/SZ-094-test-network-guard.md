# SZ-094 — CI-флейк «localhost:3000»: тесты дёргают реальную сеть через happy-dom

> Источник: прод-деплои 08.10 (PR #23/#24) дважды упали на прогоне с
> «Tests 1066 passed (1066), Errors 1 error». «Го» на немедленный фикс:
> владелец 08.10. Статус: **реализована** (см. конец карточки).

## Аудит (факт-чек, 08.10)

Симптом: CI-прогон Unit tests падает с `Errors 1 error: AggregateError
[ETIMEDOUT ::1:3000, ECONNREFUSED 127.0.0.1:3000]` при **всех** пройденных
тестах; воспроизводится только на загруженном self-hosted раннере (gostiny-ci,
прод-сервер), локально — никогда. Тайминг: ошибка вылезает в конце прогона
(дрейн необработанных промисов), Duration CI 167с против локальных 45с.

Цепочка (файл:строка):
1. `src/router/__tests__/chunk-recovery.test.ts` — тест «защита от цикла:
   повторный сбой сразу после перезагрузки не прыгает» вызывает **настоящий**
   `purgeShellAndReload()` без инъекций (второй вызов в цикле восстановления).
2. `src/package/global-helpers/version-gate.ts:77-79` — `await purge()` затем
   `reload()` = `window.location.replace(cacheBustUrl(...))`.
3. happy-dom исполняет навигацию как загрузку документа по абсолютному URL:
   относительный адрес резолвится против origin тестового окружения
   `http://localhost:3000` (дефолт vitest+happy-dom).
4. Node/undici коннектится к `::1:3000`, затем `127.0.0.1:3000`. На прод-сервере
   (gostiny-ci) пакеты на loopback-порт без слушателя дропаются файрволом →
   ETIMEDOUT через десятки секунд → необработанная ошибка → прогон X.
   Локально ECONNREFUSED мгновенный и тихий — поэтому не воспроизводилось.

Что НЕ является причиной (проверено): test-setup.ts:53 уже ставит безопасный
глобальный fetch (200 {}); в src единственный прямой fetch — version-gate
(его реджект пойман try/catch); axios-адаптер и runtimeCaching не участвуют.

## Решение

`vi.mock("@/package/global-helpers/version-gate.ts")` в
chunk-recovery.test.ts: purgeShellAndReload → `vi.fn(async () => true)`,
`cacheBustUrl` остаётся настоящим (кэшбастер тестируется в version-gate.test).
Отклонённые альтернативы: `dangerouslyIgnoreUnhandledErrors: true` (маскирует
реальные необработанные ошибки); правка test-setup (источник не там); резолв
localhost на раннере (обход на инфре, не лечит корень).

## Критерий приёмки

1. Локальный и CI-гейты зелёные без необработанных ошибок, многократно.
2. Ни один unit-тест не инициирует реальную сетевую загрузку документа
   (grep-аудит: purgeShellAndReload/reload/replace в тестах — только с
   инъекциями или через мок).
3. Флейк не воспроизводится на 3 подряд CI-прогонах (наблюдение — первый
   прогон после фикса считается контрольным).
