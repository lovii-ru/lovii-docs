# T-031 · Промо на покупательских экранах: дизайн-проход всех выводов акций

> Статус: **Готова к работе**. Исполнитель: продукт-агент (zcode) с продуктовыми/
> дизайнерскими скилами (канон `PRODUCT_QUALITY_BAR.md` обязателен: скрин-тест
> «премиальный банк», три состояния, адаптив, честные цифры, a11y).
> Приёмка — владелец на локальном стенде :5174/:5175.
**Связано:** T-029 (промо в оформлении и квитанции, session 071), T-030 (промо в
предрасчёте, session 074), SZ-073 (конструктор промо), SZ-076 (канон демо),
справочник операций `canon/LEDGER_OPERATIONS_REFERENCE.md`.

## Зачем

Контур промо заработал целиком (T-029 + T-030 вылиты на staging), и у покупателя
появились **новые точки контакта с акциями**, которые пока выведены служебно:
в предрасчёте — сырые строки, в квитанции — блок `promo` без дизайн-прохода,
на витрине — только бейджи у товаров. Механики разные (кэшбэк, скидка, подарок,
штампы, счастливые часы), и человек должен в каждом месте видеть понятную
честную картину «что я получу». Задача — оформить эти выводы по канону дизайн-
системы «Лови» (источник: `lovii-demo`, токены `lovii-design`).

## Где что уже есть (данные — всё готово, работы только по выводу)

| Экран | Данные | Что сейчас |
|---|---|---|
| Витрина точки | `cashback_percent`, `promo_badges` у товара | бейджи есть; нет внятного блока «Акции точки» (лента `GET /loyalty/promos?merchant_id=X&branch_id=Y` отдаёт карточки с заголовком/бейджем/сроком) |
| Корзина | нет промо-полей | ничего (можно не делать — см. «Границы») |
| Оформление (`orders/preview`) | блок `promo`: `discount_total`, `cashback_total`, `badges`, `gifts`, `final_total` | строки «Скидка по акциям / Кэшбэк за заказ / Подарок» — служебно (T-030) |
| Квитанция заказа (`OrderDetailResource.promo`) | тот же блок + `stamps` | блок без дизайн-прохода (T-029) |
| Кошелёк (история) | подписи операций уже приведены (65d423e) | не трогать, только сверить |
| Штампы | `stamps: {threshold, have}` | прогресс не показан нигде, кроме служебного поля |

## Что сделать

1. **Экран оформления (главный фокус):** переработать промо-строки в канонную
   карточку «Выгода» (или подключить к `OrderSummary`): итог с учётом скидки —
   крупно, скидка −X ₽ и кэшбэк +Y б. — отдельными строками с тональностью
   канона (кэшбэк — тиффани, скидка — чернила), подарок — отдельной строкой с
   иконкой gift и названием товара. Бейджи механик («Комбо −15%», «Подарок»)
   — пилюлями канона. Три состояния: промо есть / промо нет (блок не рисуется) /
   загрузка (скелетон или без блока).
2. **Квитанция заказа:** тот же визуальный язык, что на оформлении (один
   компонент на оба места, если уместно); «Кэшбэк» строкой с пометкой
   «начислится после подтверждения оплаты» до оплаты и «начислено» после —
   честная цифра из снапшота (T-029 уже различает — сохранить).
3. **Витрина:** блок «Акции точки» из ленты `loyalty/promos` (карточки:
   заголовок, бейдж, срок «до 6 октября»), размещение по канону витрины; штампы
   — прогресс «2 из 3» (товары категории → подарок), если механика активна.
4. **Подарок к чеку:** в предрасчёте и квитанции показывать «Подарок: Пончик с
   сахарной пудрой ×1» (данные есть) — не терять в свёрнутых состояниях.
5. **A11y и честность:** контраст по AA в обеих темах; цифры только из API —
   ничего не считать на клиенте; не обещать кэшбэк, если `cashback_total = 0`.

## Границы

- Бэкенд не менять: все данные уже отдаются (T-029/T-030). Если чего-то
  критично не хватает — сначала согласовать с владельцем, не молча расширять API.
- Корзину (список корзин) не трогать — промо считается на оформлении
  (решение владельца 29.09, T-030).
- Кошелёк и подписи операций — вне задачи (сделаны, `65d423e`).

## Приёмка (владелец на :5174/:5175)

Витрина с активными акциями → товар с бейджем → корзина → оформление: карточка
«Выгода» (скидка, кэшбэк, подарок, итог со скидкой) → оплата → квитанция (те же
цифры, честная подпись кэшбэка до/после оплаты) → кошелёк (начисление). Прогнать
при включённых: кэшбэк-дефолт, комбо, подарок к чеку, счастливые часы.
