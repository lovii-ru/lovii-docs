## 1. Что

Первоисточник: «снапшоты / in-memory temp table + intersection вместо
upsert-циклов». Профилировать текущий `reconciliation` (RunCatalogImportAction
и связанные джобы): где время — в цикле upsert по позициям.

Оптимизация (по итогам профиля):

1. Temp table (или массивы) с ключами external_id → set-пересечение
   (что новое/изменённое/пропавшее) одним проходом;
2. Массовые insert/update (chunked) вместо поштучных save();
3. Метрики: время полного прогона до/после, память — в отчёт задачи.

## 4. Отчёт исполнителя (Super Z, 2026-09-11)

**Профиль (структурный).** `KuperReconciler` (946 строк, 6 фаз) уже был
булковым в самом тяжёлом месте — фаза 5 (офферы: raw INSERT ... ON CONFLICT
чанками по 500, bulk mapping-апдейты, деактивация одним UPDATE). Горячая
оставшаяся точка — **фаза 3 (таксоны)**: `find()+update()` = 2 запроса на
каждый такон (на дереве в тысячи узлов — 2N statements). Фазы 0/1/2 делали
построчный `$mapping->update(['internal_id' => …])` (1 запрос на строку,
N = labels/retailers/stores — объёмы малы, но тот же паттерн). Фаза 4
(продукты) была уже булковой.

**Оптимизация (3f8af65, +153/−57).**
1. Фаза 3: строки группируются по `payload.depth` (родитель всегда имеет
   depth меньше дочерней → рёбра дерева только между группами), каждая
   группа выгружается одним `upsert()` по id + одним INSERT ... RETURNING
   (общий хелпер `insertReturningIds()`, вынесен из фазы 4). Семантика
   `find()?->update()` с молчаливым пропуском отсутствующих строк сохранена
   фильтром по фактически существующим id перед upsert. Обновление
   mapping.internal_id — один bulk UPDATE ... FROM VALUES на группу.
2. Фазы 0/1/2: построчные mapping-апдейты → один bulk UPDATE ... FROM VALUES
   на чанк (переиспользован существующий `bulkUpdateMappingInternalIds`).
3. Дублированный inline INSERT ... RETURNING фазы 4 вынесен в общий хелпер.

**Эквивалентность.** Счётчики created/updated/errors не изменились; набор
данных бит-в-бит (те же колонки, те же значения, slug-генерация и
parent-резолв построчно те же). Щит: **32/32 теста KuperReconcilerTest
зелёные** (в т.ч. «creates depth=1 category with correct local parent_id» —
порядок родитель→потомок покрыт), полный Pest-прогон CI 🟢. Единственное
осознанное отличие: `integration_entity_mappings.updated_at` в фазах 0–3
больше не трогается построчными save() (bulk-апдейт пишет только
internal_id) — metadata-колонка, в снапшот импорта не входит.

**Метрики времени.** Песочница без PHP/БД — wall-clock до/после не снимался.
Структурная оценка для дерева из N таконов: было 2N+1 statement'ов, стало
O(глубина дерева × 2 + 1); для чанков mapping-апдейтов — с N запросов на 1
на чанк. Прогон на staging-объёме (1.2M офферов) — за zcode при включённом
INTEGRATIONS_ENABLED (окно безопасное, импорт выключен).
