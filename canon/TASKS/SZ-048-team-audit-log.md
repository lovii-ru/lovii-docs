## 1. Контекст

При утверждении канона приглашения в команду (`cabinet/msp/team`, канон
«бренд → точки бренда → роль → телефон») владелец подтвердил матрицу прав:
**администратор = всё, что и владелец** (доверенное лицо), **сотрудник = заказы
и наличие**. Из этого следует два требования ниже.

Серверная база уже готова: у `manager` в `PartnerRole::abilities()` есть все
права владельца кроме `partner.verify` (карточка SZ-047 §2). Право `audit.view`
в enum **есть, но ничего не стоит за ним** — механизма аудита в core нет
(проверено 2026-09-17: ни activity-log пакета, ни таблиц, ни событий).

## 2. Требование 1 — лог действий (аудит)

- **Что пишем**: все изменения из кабинетов (МСП `/cabinet/msp` и команды
  `/cabinet/team`) по сущностям юрлица: товары/офферы (создание, правка,
  удаление, цены, наличие), категории, точка (название, адрес, график,
  мин. сумма, зоны доставки), карточка магазина (название, описание, логотип),
  команда (приглашение, принятие, смена роли, отзыв доступа), заказы
  (смена статуса, отмена — уже есть `cancelled_by`/`cancel_reason` в orders).
- **Формат записи**: кто (участник: имя · телефон · роль на момент), когда
  (timestamp), что (сущность + поле), **с какого значения на какое**.
- **Где смотрят**: экран «Лог»/«История изменений» — владелец и администратор
  (`audit.view`; право уже в матрице обоих). Сотруднику лога нет.
- **Границы**: лог читаемый список с фильтром по участнику — без аналитики.
- Предлагаемая реализация: таблица в `lovii_b2b` (partner-scoped,
  append-only), запись из контроллеров Msp*/Team* после успешной операции;
  контракт API — `GET /api/v1/msp/audit` (пагинация, фильтр по membership).

## 3. Требование 2 — настройки в кабинете команды

Администратор должен видеть в `/cabinet/team` те же настройки, что и владелец
в МСП (сейчас экранов нет, хотя сервер разрешает):

| Экран | Право (уже есть у manager) |
|---|---|
| Карточка магазина (название/описание/логотип) | `merchant.update_profile` |
| Точка: название, адрес | `branch.update` |
| График работы v1 | `branch.update_working_hours` |
| Мин. сумма заказа | `branch.update` |
| Зоны доставки | `branch.update_delivery_zones` |

Граница (из канона кабинета, SZ-047 §4): витрину (`is_active`) администратор
не правит — только владелец.

## 4. Попутная мелочь (можно отдельным мини-PR)

`GET /api/v1/msp/overview` не отдаёт `logo_url` merchants[] — карточка бренда
на экране команды показывает фолбэк-иконку (реализовано 2026-09-17,
`lovii-app` `feat/sz047-team-invite-canon`). Добавить `'logo_url' =>
$merchant->logo_url` в `ShowMspOverviewController` — и UI покажет логотип без
правок клиента (поле в типе уже опциональное).

## 5. Открытый вопрос (не блокирует)

Тумблеры товара: владелец отметил «тумблеры надо разобрать отдельно. я там
тоже перебор» — в «Товарах» сейчас два тумблера (`is_available` «в продаже» и
`is_active` витрины). Разобрать с владельцем до реализации: возможно, оставить
один для администратора (`is_available`), `is_active` — только владелец.
