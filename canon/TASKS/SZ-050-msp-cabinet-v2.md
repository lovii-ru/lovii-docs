## 1. Канон (утверждается этой карточкой)

**МСП = юрлицо (ИНН). Один кабинет, переключение юрлиц — чип в шапке → шит
списка** (паттерн СберБизнес/Т-Бизнес). Внутри юрлица: бренды → точки;
рабочая точка — из точек выбранного юрлица. Умолчание — последнее юрлицо
(локально). Отдельные кабинеты на юрлицо отклонены владельцем (не назначить
одного администратора на всё); администратор в нескольких юрлицах = одно
и то же приглашение номера в каждое юрлицо, у его кабинета тот же свитчер.

Каталог: категории с `parent_id` (модель уже есть — `catalog_categories`),
любая глубина, drill-down на мобильном; поля товара минимальные (название +
цена), остальное опционально. iiko-импорт (Ф4) апсертит по external_id через
`integration_entity_mappings`, перезаписывает структуру/цены, НЕ трогает
локальные флаги (скрыт/наличие/фото).

## 2. Фазы

| Фаза | Объём | Репо |
|---|---|---|
| **Ф1** — свитчер юрлиц: шапка-чип, шит «Мои юрлица» (название, ИНН, статус, «N брендов · M точек», «Добавить юрлицо» → заявка), фильтрация Обзора/Заказов/Настроек/Команды по юрлицу, пустые состояния («Добавить бренд» — АКСИОМА, «Добавить точку» — Grand) | app | средняя |
| **Ф2** — создание бренда и точки из приложения: `POST /api/v1/msp/merchants` (название, логотип), `POST /api/v1/msp/branches` (название, адрес, график); права `merchant.create`/`branch.create` уже в матрице; CTA на Обзоре. **Поглощает SZ-049**. **Плюс правило ИНН (баг найден 2026-09-17 на стенде)**: заявка с уже верифицированным ИНН создаёт ДУБЛЬ юрлица (локальный кейс: партнёр 271 «Пончики» = ИНН АТМОСФЕРЫ → выглядел как «переключение мерчантов в рамках одного МСП»); должно быть: существующий ИНН → новый мерчант (бренд) под существующим юрлицом, новый ИНН → новое юрлицо. Чинить в `CreatePartnerApplicationController` (+ дедуп-подсказка в форме заявки) | core + app | средняя |
| **Ф3** — каталог: API категорий app (вложенные, права `category.*` есть) + экран-дерево (drill-down) + товары (+ перенос между категориями, скрытие) | core + app | большая |
| **Ф4** — iiko-импорт (после включения `INTEGRATIONS_ENABLED`): воркер, маппинги, правило совместного владения §1. Отдельная задача на базе Ф3 | core | большая |
