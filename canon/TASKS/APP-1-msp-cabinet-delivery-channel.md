## Факт (что сломано)

Экран «Точка» в app-кабинете МСП (`MspBranchSettings.vue`) принимает радиус
доставки 300–1000 м. Текст экрана: «Пока радиус не задан, заказы с доставкой
точка не принимает — самовывоз работает всегда» → обещает, что задание радиуса
включает доставку. Фактически:

- `UpdateMspBranchSettingsController` принимает только `delivery_radius_meters`
  и создаёт активную зону (`applyDeliveryRadius`), но не трогает канал;
- `branches.delivery_available` остаётся `false` → покупателю доставка
  недоступна (`MerchantBranch::delivery_available` + зоны).

Обход на 09.10: тумблер «Доставка доступна» в b2b (включён для точки 2).

## Решение (вердикт владельца 09.10: «соглашусь… делай» — вариант из текста экрана)

**Радиус включает канал:** сохранение радиуса из app поднимает
`delivery_available = true` (идемпотентно). Выключение канала из app не
добавляем (b2b остаётся местом тонкой настройки зон — API-контракт не расширяяем).

## Критерий приёмки

1. Точка без зон + `delivery_available=false`: PATCH настроек с радиусом →
   `delivery_available=true`, зона активна, покупателю доступна доставка.
2. Повторный PATCH радиуса не меняет канал (идемпотентно), зоны в b2b не
   затираются (управление зонами остаётся в b2b).
3. Тест-кейсы core (feature-тест контроллера) — зелёные; полный гейт 🟢.

## Развилки/ограничения

- Право `branch.update_delivery_zones` не меняется.
- Зоны в b2b: if зоны управляются там (`delivery_zone_managed_in_b2b`) —
  радиус из app по-прежнему отклоняется, поведение не меняем.
