## 5. Отчёт исполнителя (Super Z, 2026-09-11, core+app `72e7e62`)

### 5.1. §2.1 Ресёрч лучших практик (кратко)
1. Шапка = лого + название + статус точки (цветовой/текстовый) — у всех.
2. Статус всегда живой: «Открыто до HH:MM» / «Откроется в HH:MM» / «Закрыто до дня» —
   никогда не статичный текст.
3. Описание — короткий абзац сразу под шапкой (у Еды — под лого, свёрнуто после 2 строк).
4. График — строкой («Ежедневно 08:00–21:00»), без таблиц по дням.
5. Контакты — кликабельные (tel:), вторичный телефон поддержки отдельно.
6. Условия — мин. сумма/доставка — в конце, приглушённым текстом.
7. Пустых секций нет: блок без данных не рендерится.

### 5.2. §2.3 Бэкенд (core)
- `/v1/storefront/info` merchant-блок расширен: `description`, `phone`,
  `support_phone`, `cover_url` (+ уже были logo/mini_logo/logo_background_color).
- Контракт-тест ShowStorefrontTest расширен (structure + значения полей).
- Аномалия «пустых логотипов» на staging НЕ воспроизводится (live-проверка:
  logo_url/mini_logo_url отдаются полными URL — бэкфилл SZ-006 §1 отработал).
- `working_hours` в payload остался (TODO removal) — app мигрировал на
  schedule+availability; удаление поля — следующий мелкий PR (NB zcode).

### 5.3. §2.4 UI (app)
- `StoreInfoSheet` переписан: статус (availability → «Открыто/Откроется в
  08:00/Откроется завтра в …/Закрыто до понедельника/Закрывается через N мин»),
  «О магазине» (description), график строками (schedule), контакты (tel:,
  кликабельные), условия (мин. сумма). Пустые секции не рендерятся (v-if).
- `StoreCard`: статус из availability вместо захардкоженного «Открыто».
- Типы MerchantStorefront.merchant расширены (description/cover/phones — optional).
- Тесты vitest ×3 (StoreInfoSheet: полный контент, статусы, отсутствие пустых секций).
