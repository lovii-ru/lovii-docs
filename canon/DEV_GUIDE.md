# DEV_GUIDE — Руководство по локальной работе и публикации

> **Назначение:** точное и воспроизводимое описание «как настроить и работать» —
> любой участник (или агент) может поднять проект с чистого клона, отредактировать
> документ и опубликовать его в публичный репозиторий. Команды взяты из реальных
> скриптов и CI этого репозитория, не из схемы.

## Что публикуется, а что нет

`lovii_docs` — приватный репозиторий. В публичный `axiiom-ru/lovii` (GitHub Pages)
при каждом пуше в `main` попадают ровно 4 файла:

| Локальный путь | Путь в публичном репо | Строка версии |
|---|---|---|
| `public/money_flow_public.md` | `public/money_flow_public.md` | да |
| `public/Публичная_оферта.md` | `public/Публичная_оферта.md` | да |
| `public/Оферта_присоединения.md` | `public/Оферта_присоединения.md` | да |
| `README.md` | `README.md` | нет |

Всё остальное (`canon/`, `versions/`, `scripts/`, `.omo/`, `REGISTRY.md`,
`compare.html`) остаётся в приватном репо. `compare.html` публикуется на GitHub Pages
как инструмент сравнения версий, но не через `sync-public.sh`.

## Предусловия

- **Git** и доступ к приватному репозиторию `bestdeejay-design/lovii_docs`.
- **GitHub CLI (`gh`)**, авторизован (`gh auth status`), с доступом к
  `axiiom-ru/lovii` (нужен для записи через API при публикации).
- **Python 3** (используется скриптом для декодирования base64 контента из API).
- **Bash** (скрипт `scripts/sync-public.sh` — POSIX-совместимый, `set -euo pipefail`).
- Секрет репозитория `lovii_docs`: `PAT` — personal access token с правами
  `contents: read/write` на `bestdeejay-design/lovii_docs` И `axiiom-ru/lovii`.
  Нужен только CI; локально публикацию делает `gh` под твоим аккаунтом.

## Быстрый старт

```bash
# 1. Клонировать приватный репозиторий
git clone git@github.com:bestdeejay-design/lovii_docs.git
cd lovii_docs

# 2. Убедиться, что gh авторизован и видит публичный репо
gh auth status
gh repo view axiiom-ru/lovii >/dev/null   # ошибка прав доступа = нет публикации

# 3. Проверить логику публикации без записи (dry-run)
bash scripts/sync-public.sh --dry-run
```

## Как редактировать документ

1. **Публичный канон** — правь файлы в `docs/` (`Публичная_оферта.md`,
   `Оферта_присоединения.md`, `money_flow_public.md`). Это единственные документы,
   которые увидит публика.
2. **Рабочая документация** — правь файлы в `canon/`. Они приватные,
   не публикуются, но отслеживаются в VCS.
3. **Строка версии.** У трёх канон-документов версия задана в таблице метаданных
   в формате `| **Версия** | X.Y.Z |`. Скрипт публикации читает её оттуда.
   Актуальная версия канона — `v2.0.3` (см. `REGISTRY.md` и `versions/`).
4. **Не трогай источник комиссий** — `LOVII/lovii-docs/tbank/05_Мультирасчеты_без_акта_ООО_АКСИОМА.md`
   (помечен `read_only` в манифесте).
5. **Закоммить изменения** в `lovii_docs` (ветка `main`).

## Конвейер публикации (реальный)

Публикация полностью автоматическая и управляется одним скриптом.

### Локальный запуск (вручную)

```bash
# Авто-бамп уровня по объёму изменений (<=5 строк тела → patch, иначе minor)
bash scripts/sync-public.sh

# Принудительный уровень бампа
bash scripts/sync-public.sh --level minor      # major | minor | patch

# Только показать решения, без записи и публикации
bash scripts/sync-public.sh --dry-run

# Не коммитить бамп версии обратно в lovii_docs
bash scripts/sync-public.sh --no-commit

# После коммита ещё сделать git push в lovii_docs
bash scripts/sync-public.sh --push
```

Скрипт (`scripts/sync-public.sh`) для каждого из 4 файлов:

1. Загружает опубликованный контент и `sha` из `axiiom-ru/lovii` через `gh api`.
2. Для файлов с версией сравнивает локальную версию с опубликованной:
   - **выше** → публикует как есть, версию не трогает;
   - **равна, а тело изменилось** → поднимает версию на 1 уровень (по объёму
     изменений или принудительно через `--level`), коммитит бамп обратно в
     `lovii_docs`, затем публикует;
   - **ниже** → защита от понижения, пропускает (не публикует);
   - **равна и тело не изменилось** → пропускает (без изменений).
3. Для `README.md` (без версии) — публикует, только если файл изменился.
4. Публикует через `gh api ... --method PUT` с актуальным `sha` (защита от
   одновременной перезаписи).

### Автоматическая публикация (CI)

При каждом пуше в `main` срабатывает `.github/workflows/sync-public.yml`:

```yaml
on:
  push:
    branches: [main]
  workflow_dispatch:
```

Шаги в workflow:

1. `Checkout lovii_docs` с токеном `secrets.PAT` (fetch-depth: 0).
2. Настройка git-идентичности (`Sisyphus <bestdeejay@gmail.com>`) и remote-auth
   через `x-access-token:${{ secrets.PAT }}` — чтобы бамп можно было запушить обратно.
3. Запуск `bash scripts/sync-public.sh --push` с `GH_TOKEN=${{ secrets.PAT }}`.

То есть **достаточно запушить правки в `main`** — workflow сам опубликует канон
в `axiiom-ru/lovii` и при необходимости закоммитит бамп версии обратно в `lovii_docs`.

## Переменные окружения и секреты

| Имя | Где | Значение |
|-----|-----|----------|
| `PAT` | секрет репозитория `lovii_docs` | personal access token с `contents: read/write` на оба репо |
| `GH_TOKEN` | CI (из `secrets.PAT`) | передаётся скрипту для `gh api` |

Локально `gh` берёт токен из твоего `gh auth`; отдельно задавать `GH_TOKEN` не нужно.

## Отладка

- **`bash scripts/sync-public.sh --dry-run`** — главный инструмент: показывает,
  что скрипт решил бы сделать (бамп/пропуск/публикация) без записи.
- **Лог публикаций** — `scripts/sync-public.log` (дописывается при каждом запуске).
- **Ошибка «не удалось загрузить … (sha/content)»** — нет доступа `gh` к
  `axiiom-ru/lovii` или файл отсутствует в публичном репо. Проверь `gh auth status`
  и права токена.
- **Защита от понижения версии** — если видишь «версия источника ниже опубликованной»,
  подними версию в локальном файле выше опубликованной вручную, иначе публикация
  этого документа пропустится.
- **Бамп не закоммитился** — скрипт логирует `WARN`, но продолжает; при следующем
  пуше бамп применится снова. Можно запустить без `--no-commit` (по умолчанию коммит
  есть).
