## 2. Правила размещения

1. Каждый `.md` платформы — один футер (§1.1 или §1.2) в самом низу, после всего контента.
2. Гриф «Внутреннее» (§1.1) обязателен для `docs/sessions/`, `workspace/`, `canon/TASKS/`, черновиков.
3. Публичный футер (§1.2) — только там, где документ реально публикуется наружу. Внутренний док с публичным футером — дефект.
4. Полные реквизиты (ООО, ИНН, ОГРН) — только на странице «Реквизиты», не в футере.
5. Даты в футерах — полные (`29.09.2026`); год в строке © — текущий.
6. Обращение в доках — нейтральное («пользователь»); «ты» — только в цитатах UI.
7. Секреты (ключи, токены, пароли) в доки не класть — ни в текст, ни в футер.

## 3. Копирайтинг внутри доков (поверх brand-voice)

1. Заголовок — до 60 знаков, sentence case, без точки. Первый абзац — что это и зачем.
2. Одна мысль — один абзац. Канцелярит запрещён («осуществить», «данный», «уважаемый пользователь»).
3. Термины только из словаря `11-brand-voice.md` §4: точка (не магазин), витрина (не каталог), самовывоз, корзина, район, баланс, выплата.
4. Числа конкретные (`7 мин пешком`, `249 ₽`, `до 18:00`); факты с источником (дом факта, не пересказ). <!-- fact-guard: allow — иллюстративные примеры формулировок в стандарте, не факты платформы -->
5. Маркетинг в фактах запрещён: нет «лучший», «уникальный», «мгновенно» без замера.

## 5. Открытые решения (блокеры массового внедрения)

1. **Владелец в строке ©:** сейчас бренд `© «Лови», 2026` (достаточно для черновика). Если нужен `© ООО «…», 2026` с ИНН/ОГРН — решение владельца, затем одна замена по всем футерам.
2. **`LICENSE` в `lovii-tech/*`:** сейчас файлов нет. Для проприетарных репо нужен proprietary-текст или решение «не кладём» — до решения файлы не создавать.
