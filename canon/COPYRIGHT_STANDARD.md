# COPYRIGHT_STANDARD — шапка и подвал копирайта в каждом файле

> **Статус:** черновик (на приёмке у владельца).
> **Дата:** 04.10.2026, дополнен ресёрчем 05.10.2026 (§5, RES-015).
> **Единственный вопрос документа:** как выглядит блок копирайта в шапке и подвале каждого файла проекта.
> **Охват:** все репо платформы (`lovii-core`, `lovii-app`, `lovii-b2b`, `lovii-admin`, `lovii-design`, `lovii-demo`, `lovii_docs`).
> **Дом:** только форма и содержание блока. Факты — `PARAMS.md`, юр-блок UI — `lovii-design/docs/11-brand-voice.md` §6.

## 1. Идея

Как в опенсорсных файлах: при открытии файла **сверху** и **снизу** видно автора и владельца.
Всё внутри комментария — в отрендеренный документ или выполнимый код ничего не вылезает.
Один и тот же текст во всех типах файлов, меняется только синтаксис комментария.

## 2. Канонический текст блока

Строка автора (единственная, дословно):

```
© 2026 ООО «Аксиома» · бренд LOVII («Лови») · https://lovii.ru · все права защищены
```

Вторая строка — только для файлов, которые уходят наружу (публичные доки, лендинги):

```
Реквизиты: https://lovii.ru/requisites
```

Правила:

- **Владелец:** ООО «Аксиома» (компания), **бренд:** LOVII / «Лови». Не менять местами и не сокращать до «Лови».
- **Год:** год первого коммита файла. Ежегодно не обновляем, массовых замен года не делаем.
- **Автор-исполнитель** (человек/агент) — отдельной строкой НЕ дублируем: автор — компания.
- **Секреты, ИНН/ОГРН, ставки** в блок не входят. Реквизиты — только ссылкой (строка 2).
- Блок вставляется **один раз**: если в файле уже есть `ООО «Аксиома»` — второй раз не ставить.

## 3. Шаблоны по типам файлов

### 3.1 Markdown (`.md`) — HTML-комментарий, в рендере не виден

Шапка — первые строки файла:

```md
<!--
© 2026 ООО «Аксиома» · бренд LOVII («Лови») · https://lovii.ru · все права защищены
Документ проекта LOVII.
-->

# Заголовок дока
```

Подвал — последние строки файла:

```md
<!-- © 2026 ООО «Аксиома» · LOVII — конец файла -->
```

### 3.2 PHP (`.php`) — блочный комментарий

Шапка — сразу после `<?php`, ДО `declare`/`namespace`/`use` (комментарии разрешены):

```php
<?php
/*
 * © 2026 ООО «Аксиома» · бренд LOVII («Лови») · https://lovii.ru · все права защищены
 * Код проекта LOVII. Внешнее копирование запрещено.
 */

declare(strict_types=1);
```

Подвал — последняя строка файла:

```php
// © 2026 ООО «Аксиома» · LOVII — конец файла
```

### 3.3 TypeScript / JavaScript / SCSS / CSS (`.ts`, `.js`, `.scss`, `.css`)

Шапка — первые строки файла:

```ts
/*
 * © 2026 ООО «Аксиома» · бренд LOVII («Лови») · https://lovii.ru · все права защищены
 * Код проекта LOVII. Внешнее копирование запрещено.
 */
```

Подвал — последняя строка:

```ts
// © 2026 ООО «Аксиома» · LOVII — конец файла
```

### 3.4 Vue SFC (`.vue`)

HTML-комментарий в корне шаблона Vue рендерится ненадёжно, поэтому блок ставится
**в начало блока `<script>`** и **в конец файла после `</template>`** (это невалидная
разметка — так нельзя; корректно: подвал внутри скрипта/стилей не работает, поэтому
для `.vue` — **только шапка в `<script>`**, подвал не ставится):

```vue
<script setup lang="ts">
/*
 * © 2026 ООО «Аксиома» · бренд LOVII («Лови») · https://lovii.ru · все права защищены
 */
import ...
</script>
```

> Решение зафиксировано: у `.vue` — шапка в `<script>`, подвала нет (иначе ломает SFC).

### 3.5 HTML (`.html`)

```html
<!--
© 2026 ООО «Аксиома» · бренд LOVII («Лови») · https://lovii.ru · все права защищены
-->
<!doctype html>
```

Подвал — перед `</body>` или последней строкой:

```html
<!-- © 2026 ООО «Аксиома» · LOVII — конец файла -->
```

### 3.6 Shell / Python / YAML (`.sh`, `.py`, `.yml`) — решётка

Шапка:

```sh
# © 2026 ООО «Аксиома» · бренд LOVII («Лови») · https://lovii.ru · все права защищены
# Скрипт проекта LOVII.
```

Подвал:

```sh
# © 2026 ООО «Аксиома» · LOVII — конец файла
```

### 3.7 SVG (`.svg`) — XML-комментарий после `<?xml …?>`

```svg
<?xml version="1.0" encoding="UTF-8"?>
<!-- © 2026 ООО «Аксиома» · бренд LOVII («Лови») · https://lovii.ru -->
<svg …>
```

Подвал не ставим (иконки потребителей инлайнятся в DOM — комментарий уехал бы в страницу).

### 3.8 Файлы БЕЗ комментариев — не трогаем

| Тип | Почему | Что делаем |
|---|---|---|
| `.json` | комментарии невалидны, ломают `json_decode`/импорт | копирайт живёт в сопроводительном `.md` или `_comment`-поле только там, где парсер допускает |
| `.lock`, `.min.*`, генерированные файлы | перезаписываются сборкой, правка бессмысленна | пропускаем |
| бинарное (`.png`, `.jpg`, `.woff2`, `.pdf`) | не текст | EXIF/метаданные не гарантируем — пропускаем |
| `vendor/`, `node_modules/`, чужой код | чужие авторские права | никогда не ставим |

## 4. Порядок внедрения

1. Новые файлы — блок ставится **при создании**.
2. Существующие — при первой правке файла (заодно шапка/подвал).
3. Массовая простановка скриптом — по отдельному решению владельца
   (идемпотентно: пропускать файлы, где уже есть `ООО «Аксиома»`; после — прогон
   гейтов репо: тесты core/b2b/admin, `yarn type-check`+`build-only` app).
4. Скрипта пока нет — массово не ставим, только точечно по п.1–2.

## 5. Copyright-код и защита от массового удаления

Основание: ресёрч `artifacts/RES-015-copyright-headers-provenance.md` (SPDX/REUSE,
практика гигантов, traitor tracing, ГК РФ).

### 5.1 Код принадлежности (точный маркер)

Вторая строка шапки важных файлов (публичные доки, контракты, вёрстка, всё,
что может утечь наружу):

```text
Код: LOVII-CR-26-XXXXXX
```

- `XXXXXX` — 6 hex-символов, генерируются **один раз на файл**, дальше не меняются.
- Ключ — приватный реестр `canon/COPYRIGHT_REGISTRY.md` (живёт в приватном
  `lovii_docs`, наружу не выходит): `код → файл, репо, дата, автор`.
- Grep утёкшего файла по `LOVII-CR-26-` → реестр → точная принадлежность.
- Юридически код защищён: **ст. 1300 ГК РФ** относит к «информации об авторском
  праве» «любые цифры и коды»; удаление шапки — самостоятельное нарушение
  (компенсации — по ст. 1300–1301 ГК РФ; шкалы — в `artifacts/RES-015-copyright-headers-provenance.md` §2.1).
- Ограничение: пассивный маркер ловит копию целиком; при ручной перепечатке/минификации
  комментарий умирает — поэтому код не единственный слой (см. 5.2).

### 5.2 Слои защиты («луковица»)

1. видимая шапка в файле;
2. строка `SPDX-FileCopyrightText: 2026 ООО «Аксиома»` рядом (машиночитаемый
   эталон REUSE — парсится сканерами, переживает копирование файла);
3. корневой `LICENSE` + метаданные пакетов (`composer.json`/`package.json` author);
4. CI-гейт (ниже).

Снос любого одного слоя не убивает остальные.

### 5.3 CI-гейт (обязательный при массовой простановке)

Единственная реальная защита от «одним прогоном снесли все шапки» — падающий
гейт, как у гигантов (`addlicense -check`, `hawkeye`, `reuse lint`):

- **pre-commit хук:** список tracked-файлов без `ООО «Аксиома»` → warn/exit 1.
- **CI (required check):** то же в пайплайне; PR, снёсший шапки, не мержится.
- **CODEOWNERS:** изменения `COPYRIGHT_REGISTRY.md` — только аппрув владельца.

Гейт включается вместе с массовой простановкой (§4 п.3) — без него массовая
простановка не запускается.

### 5.4 Наружу (контрагентам)

Выдача файлов/копий внешним получателям — отдельный батч-код в реестре:
`код → получатель, дата, объём` (canary trap по опыту Apple/Tesla — см. RES-015 §3.1).

## 6. Пилот (образцы в живых файлах)

- `canon/COPYRIGHT_STANDARD.md` — сам этот файл (шапка + подвал, `.md`).
- `canon/PRODUCT_QUALITY_BAR.md` — шапка + подвал (канон-док).
- Шаблоны `.php` / `.ts` — §3 выше; живой код не трогаем до решения о массовой простановке (§4 п.3).

## 7. Открытые решения

1. **Год в ©** — 2026 по файлу первого коммита (согласовать, если нужен диапазон).
2. **Массовая простановка** — да/нет и объём (весь код или только новые/правленые).
3. **`LICENSE` в `lovii-tech/*`** — сейчас отсутствует; proprietary-текст по решению владельца.
