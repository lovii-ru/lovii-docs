## 1. Глоссарий

| Термин | Определение |
|---|---|
| **UDID** | Уникальный идентификатор пользователя в системе LOVII. Создаётся в момент регистрации. |
| **Промокод** | Строка формата `PPXXXX` (6 символов). Способ встать в структуру + привязка к подписке + канал начислений. |
| **Префикс промокода** | Первые 2 символа промокода. Определяет «ветку» (Амбассадора). |
| **Суффикс промокода** | Последние 4 символа промокода. Уникальны в рамках префикса. |
| **Алфавит промокода** | 33 символа: `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`. Исключены: 0, 1, I, O. |
| **Амбассадор** | Владелец ветки (уникального префикса). Получает 20% от пула LOVII по промокодам своей ветки. |
| **Представитель** | Пользователь с активной подпиской, приглашающий других. Получает 40% от пула LOVII. |
| **МСП** | Микро/малое предприятие, продающее товары/услуги через платформу. |
| **Клиент МСП** | Покупатель (физлицо), оплачивающий заказ. |
| **Активный статус** | Состояние промокода, при котором начисления идут его владельцу. Зависит от подписки. |
| **Пул LOVII** | Комиссия платформы с заказа: 10% нагрузки на МСП минус комиссия банка-эквайера. |
| **Сплит 40/40/20** | Базовое распределение пула LOVII: Компания 40% / Представитель 40% / Амбассадор 20%. |
| **UDID-счёт** | Внутренний рублёвый баланс пользователя. Копится, можно выводить, тратить, переводить. |
| **МСП-счёт** | Отдельный счёт МСП для бухгалтерской отчётности. Обнуляется после выплат на р/с ИП/ЮЛ. |
| **Транзитный счёт** | Счёт Т-Банка для мультисплита платежей. Принадлежит банку, управляется через API. |
| **Кэшбэк** | Баллы/рубли, начисляемые клиенту МСП. Выдаётся точкой из чека по конструктору лояльности. |
| **Конструктор лояльности** | Инструмент МСП для настройки кэшбэка (%, условия, акции). |
| **Школа** | Событие для Представителей. Учат Мэры. |
| **Академия** | Событие для Мэров. Преподают Губернаторы. |
| **Каникулы** | Событие для Губернаторов. Оплачивает Компания. |
| **Юридический статус (legal_status)** | ИП / ООО / Самозанятый. Атрибут пользователя, определяющий канал и порог выплат. Независим от МЛМ-статуса (Представитель/Мэр/Губернатор). |
| **Push-канал (по графику)** | Автоматическая выплата по графику, который выбирает получатель. Доступна **только ИП/ООО** и **независимо от роли** (МСП, Представитель, Амбассадор). Порога нет — выплачивается любая сумма; налоги платит получатель. |
| **Pull-канал (по запросу)** | Выплата по запросу. Доступна **только Самозанятому** (независимо от роли). Порог 3 000 ₽: при ≥ 3 000 ₽ комиссию платит Компания, при < 3 000 ₽ мин. комиссия 30 ₽ удерживается из суммы вывода. |

## 2. Роли и иерархия

### 2.1. Дерево ролей

```
Основатель (UDID: osnovatel, Промокод: AAAAAA)
│
└── Амбассадор (уникальный префикс, выдаётся Основателем)
       │
       └── Представитель (любой пользователь с активной подпиской)
              │
              └── МСП (может быть одновременно с ролью Представителя)
                     │
                     └── Клиент МСП (покупатель)
```

### 2.2. Атрибуты ролей

| Роль | Условие получения | Ключевые атрибуты |
|---|---|---|
| **Основатель** | Создатель системы | UDID: `osnovatel`, Промокод: `AAAAAA`, Префикс: `AA` (зарезервирован) |
| **Амбассадор** | Создан Основателем вручную | Уникальный префикс (2 символа), собственный промокод `PPXXXX` |
| **Представитель** | Регистрация по чужому промокоду + активная подписка | Промокод `PPXXXX`, UDID-счёт |
| **Мэр** | Статус Представителя: ≥ 30 подключённых МСП | Все атрибуты Представителя + бейдж + доступ к Школе как наставник |
| **Губернатор** | Статус Представителя: 3+ городов × 30+ МСП + выручка сети ≥ 15 млн ₽/мес | Все атрибуты Мэра + доступ к Академии как преподаватель + право на Каникулы |
| **МСП** | Регистрация (бесплатно, по любому промокоду или своему) | Каталог, МСП-счёт, конструктор лояльности |

### 2.3. Принцип сосуществования ролей

**Роли НЕ взаимоисключающие.** Один пользователь может быть:
- Владельцем МСП + Представителем (если приглашает других)
- Амбассадором + МСП (если сам продаёт на платформе)
- Мэром + МСП (если его МСП входит в его же сеть)

Каждая роль даёт свои начисления по своим правилам.

### 2.4. Принцип начисления дохода: 2 уровня, без каскада (архитектурное решение)

**LOVII осознанно НЕ является классическим многоуровневым МЛМ.** Это зафиксированное решение, разработчику и ИИ-агенту не следует достраивать логику выплат по цепочке "спонсор спонсора" ни при каких условиях.

**Правило:**
- Представитель получает 40% пула **только** с транзакций точек, зарегистрированных **лично по его промокоду** (прямая регистрация, 1 уровень).
- Амбассадор получает 20% пула со всех транзакций всей своей ветки (branch-wide, независимо от глубины).
- Статус Мэр/Губернатор считается по всей ветке вниз (раздел 5.3), но **не даёт дополнительных денежных начислений** — только привилегии (раздел 5.5, раздел 6).

**Почему так:**
1. Личный доход 40% с лично подключённых точек — достаточная финансовая мотивация без каскадных выплат.
2. Отсутствие выплат за уровнями снижает риск квалификации схемы как финансовой пирамиды (в РФ выплаты, завязанные на рекрутинг рекрутёров, — юридически чувствительная зона).
3. Система проще в разработке и аудите: на каждой транзакции всегда ровно 3 стороны (Компания / Представитель / Амбассадор), без обхода дерева предков.
4. Статус (Мэр/Губернатор) — это про привилегии и признание, а не про надбавку к проценту.

## 3. Промокоды

### 3.1. Формат

```
[PP][XXXX]
  │   │
  │   └── 4 символа, случайная генерация по алфавиту
  └────── 2 символа, префикс ветки (наследуется от пригласившего)
```

**Алфавит (33 символа):** `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`  
**Исключения:** `0`, `1`, `I`, `O` (визуальная неоднозначность)

### 3.2. Правила генерации

| Сценарий | Алгоритм |
|---|---|
| Регистрация с промокодом `INVITER_CODE` | `PREFIX = INVITER_CODE[0:2]`<br>`SUFFIX = random(33^4)`<br>`PROMO = PREFIX + SUFFIX` |
| Регистрация без промокода | `PREFIX = "AA"` (Основатель)<br>`SUFFIX = random(33^4)`<br>`PROMO = "AA" + SUFFIX` |
| Создание Амбассадора Основателем | Основатель выбирает свободный 2-символьный префикс<br>`SUFFIX = random(33^4)`<br>`PROMO = PREFIX + SUFFIX` |

### 3.3. Ёмкость системы

| Уровень | Ёмкость |
|---|---|
| Один префикс (1 Амбассадор) | 33⁴ = **1 185 921** кодов |
| Всего префиксов | 33² = **1 089** (включая `AA` Основателя) |
| Общий потенциал | ~**1,29 млрд** промокодов |

### 3.4. Коллизии

**Определение:** сгенерированный `PREFIX + SUFFIX` уже занят в системе.

**Поведение:**
1. Пользователь не получает уведомлений о коллизии.
2. Система автоматически:
   - Проверяет уникальность суффикса в рамках префикса.
   - При коллизии → переключается на **дополнительный префикс** того же Амбассадора.
   - Например: основной `BJ` → дополнительный `B1` → `B2` и т.д.
3. Новые коды с дополнительными префиксами валидны и участвуют в той же ветке Амбассадора.

**Лимит префиксов на Амбассадора:** не менее 3 (настраивается).

### 3.5. Смена промокода

**Правила:**
- Не чаще **1 раза в 30 дней**.
- Меняется **только суффикс**, префикс остаётся (пользователь остаётся в той же ветке).
- Прошлые начисления остаются у прежнего промокода (не пересчитываются).
- Подписка сохраняется.
- Структура привязки к вышестоящему не меняется.

**Алгоритм:**
```
1. Проверить: с последней смены прошло ≥ 30 дней
2. Сгенерировать новый SUFFIX (random)
3. Обновить запись: old_SUFFIX → new_SUFFIX
4. Все начисления по новым транзакциям → на UDID-счёт владельца
5. Старые начисления (до смены) → без изменений
```

### 3.6. Резервирование

| Промокод | Владелец | Изменяемость |
|---|---|---|
| `AAAAAA` | Основатель | **Неизменяемый**, зарезервирован навсегда |

## 4. Подписка

### 4.1. Назначение

Подписка — это «премиум-аккаунт», который:
- Даёт право **приглашать** других пользователей.
- Фактически = статус **«Представитель»**.
- Определяет **активность промокода** (владелец получает начисления или нет).

### 4.2. Тарифы

| Тариф | Стоимость | Кому доступен |
|---|---|---|
| Базовая подписка | **599 ₽/мес** | Все пользователи |
| Подписка по промокоду Амбассадора | **199 ₽/мес** (акция) | По промокоду Амбассадора |

### 4.3. Состояния подписки

| Состояние | Условие | Поведение |
|---|---|---|
| **Активна** | Оплачен текущий период | Начисления по промокоду → UDID-счёт владельца |
| **Истекла** | Период закончился, не оплачен | Начисления → в Компанию (LOVII) |
| **Не оплачена** | Никогда не оплачивалась | Начисления → в Компанию (LOVII) |

### 4.4. Способы оплаты

| Способ | Описание |
|---|---|
| Банковская карта / СБП | Прямая оплата через Т-Банк |
| С UDID-счёта | Списание с внутреннего баланса (если достаточно средств) |
| Комбинированная | Частично с UDID-счёта, частично картой |

**Минимальный период оплаты:** 1 месяц.  
**Максимальный период оплаты:** 12 месяцев (включая оплату с UDID-счёта).

### 4.5. Связь подписки и промокода

```
Промокод существует всегда (создан при регистрации)
        │
        ▼
Подписка определяет активность:
        │
        ├── Активна → начисления владельцу промокода
        │
        └── Неактивна → начисления в Компанию
```

**Важно:** промокод можно **сменить** даже при неактивной подписке (с соблюдением лимита 1/30 дней), но без подписки он не приносит дохода.

### 4.6. Подписка НЕ входит в сплит 40/40/20

**Решение:** доход от подписок (599 ₽/мес или 199 ₽/мес по промокоду Основателя) — это **100% выручка Компании**. Оплата подписки **не создаёт** запись `PoolDistribution` и не делится между Представителем/Амбассадором.

Только два источника формируют пул, который делится 40/40/20 (раздел 7):
1. Транзакции клиентов через МСП.
2. Комиссия с кэшбэка.

## 5. Статусы Представителя

### 5.1. Лестница

```
Представитель → Мэр → Губернатор
```

### 5.2. Условия перехода

| Статус | Условие | Бейдж | Доступ к событиям |
|---|---|---|---|
| **Представитель** | По умолчанию (при наличии активной подписки) | 🥈 | Школа (как ученик) |
| **Мэр** | ≥ 30 подключённых МСП | 🥇 | Школа (как наставник) + Академия (как ученик) |
| **Губернатор** | 3+ городов × 30+ МСП + выручка сети ≥ 15 млн ₽/мес | 👑 | Академия (как преподаватель) + Каникулы |

### 5.3. Расчёт показателей

**Количество МСП** = количество МСП, зарегистрированных по промокодам Представителя **и его подчинённых** (вся ветка).

**Города** = уникальные города из адресов МСП в ветке.

**Выручка сети** = суммарный GMV всех МСП в ветке за последние 30 дней.

### 5.4. Автоматический переход

Статус пересчитывается **ежедневно** в 03:00 по МСК. При достижении условий новый статус присваивается автоматически.

При понижении показателей ниже порога — статус **не понижается** (one-way progression).

### 5.5. Бонусы и плюшки

Статусы дают доступ к **бонусам, премиям и плюшкам от Компании**:
- Расширенная аналитика
- Приоритетная поддержка
- Участие в событиях
- Брендированные материалы
- **Финансовая доля остаётся 40%** — статус не меняет %, только открывает возможности.

### 7.1. Слой 1: Маршрутизация платежа (1000 ₽)

```
Клиент платит 1000 ₽
   │
   ├── Банк-эквайер
   │      ├── Карта: 2,59% (без учета НДС) + НДС 22% = 3,16%  → 31,60 ₽
   │      ├── T-Pay: 2,59% (НДС не облагается)                → 25,90 ₽
   │      └── СБП:   0,7% (НДС не облагается)                 → 7,00 ₽
   ├── Торговая точка (90% нагрузки)            → 900 ₽
   └── Пул LOVII (10% − банк)
          ├── Карта: 10% − 3,16% = 6,84%        → 68,40 ₽
          ├── T-Pay: 10% − 2,59% = 7,41%        → 74,10 ₽
          └── СБП:   10% − 0,7% = 9,3%          → 93,00 ₽

**Картовый эквайринг:** 2,59% + НДС 22% = 3,16% эффективно (ФЗ №425-ФЗ, с 01.01.2026). T-Pay и СБП НДС не облагаются.
```

**Пул LOVII** = основа для распределения.

### 7.2. Слой 2: Распределение пула (40/40/20)

| Получатель | Доля | Пример с 68,40 ₽ (карта) | Пример с 74,10 ₽ (T-Pay) | Пример с 93,00 ₽ (СБП) |
|---|---|---|---|---|
| **Компания (LOVII)** | 40% | 27,36 ₽ | 29,64 ₽ | 37,20 ₽ |
| **Представитель** (владелец промокода МСП) | 40% | 27,36 ₽ | 29,64 ₽ | 37,20 ₽ |
| **Амбассадор** (префикс ветки) | 20% | 13,68 ₽ | 14,82 ₽ | 18,60 ₽ |

**Никто другой не получает** — только эти 3 уровня (см. раздел 2.4).

**Источник промокода для распределения:** `rep_udid` и `amb_prefix` определяются **регистрационным промокодом МСП** (тот, под которым МСП зарегистрировался в системе), а **не** промокодом, который клиент вводит при оплате заказа. Эти данные хранятся на стороне сервера и подтягиваются по `msp_id` — клиент не передаёт `promo_code` в запросе транзакции (см. API_SPEC.md, раздел 3.4).

**Проверка активности сторон перед начислением:**
- Представитель: проверяется активность подписки (`is_subscription_active`). Если истекла — 40% уходит Компании (раздел 4.3, TC-027).
- Амбассадор: проверяется `is_active` (не деактивирован Основателем). У Амбассадора нет подписки — он назначается вручную (раздел 3.2). Если деактивирован — 20% уходит Компании до переназначения.

### 7.3. Слой 3: Кэшбэк (если МСП настроил в конструкторе)

**Условие:** кэшбэк начисляется **только если МСП сам настроил** его через конструктор лояльности.

**Механика:**
```
1. Клиент платит 1000 ₽
2. По слою 1: точка получает 900 ₽
3. Точка выдаёт кэшбэк из чека: например, 15% = 150 ₽
4. 150 ₽ → клиенту (баллы / на UDID-счёт)
5. LOVII берёт 25% от 150 ₽ = 37,5 ₽ (платит точка сверху)
6. 37,5 ₽ распределяется:
   - LOVII 40%      → 15,00 ₽
   - Представитель 40% → 15,00 ₽
   - Амбассадор 20%    → 7,50 ₽
```

**Расчёт комиссии LOVII за кэшбэк:**
```
LOVII_комиссия = Сумма_кэшбэка_клиенту × 25%
LOVII_40%      = LOVII_комиссия × 40%
Представитель  = LOVII_комиссия × 40%
Амбассадор     = LOVII_комиссия × 20%
```

### 7.3.1. Конструктор лояльности и промо-механики (решения владельца 2026-09-22)

**Настройка — из приложения.** Базовые механики МСП настраивает прямо в `lovii-app`
(раздел «Акции» в кабинете точки, как в демо-эталоне `lovii-demo`); сложные механики —
в кабинете `lovii-b2b`. Оба входа пишут в один конструктор (один источник правил).

**Потолки — на усмотрение точки.** Платформа **не** устанавливает предельные проценты
кэшбэка и скидок: значение выбирает сама точка. Платформа показывает честную оценку
стоимости программы и оставляет за собой модерацию злоупотреблений (админка).

**База кэшбэка — фактически оплаченная сумма.** Кэшбэк считается с суммы, которую
покупатель реально платит: после применённых скидок и акций.

**Скидки и натуральные акции — за счёт точки.** Кэшбэк, скидки, подарки и комбо — расход
точки; точка не принимает и не выплачивает деньги напрямую, поэтому любые натуральные
акции — её решение. Комиссия LOVII за кэшбэк начисляется, как в §7.3.

**Комбо — категория витрины точки.** Акции, скидки и комбо живут на витрине точки;
комбо-товары образуют автоматическую категорию «Комбо», которая всегда идёт первой
в списке категорий точки (если иных категорий нет — категория «Комбо» всё равно есть).

**Ротация и актуальность.** Акции на главной приложения показываются ротацией.
Изменения из конструктора применяются **без задержки** (сразу после сохранения).

### 7.5. Self-referral (Представитель = сам МСП)

Разрешено технически, не является ошибкой (симметрично уже описанному в edge case 22 сценарию "Амбассадор = сам МСП"). Если владелец точки зарегистрировал свою же точку под собственным промокодом — он получает свои стандартные 40% как обычный Представитель, без дополнительных ограничений.

### 7.6. Округление

Все суммы округляются **до копейки (2 знака), `ROUND_HALF_UP`**, на каждом шаге расчёта (company/rep/ambassador — отдельно). Остаток от округления (если сумма трёх долей не сходится с пулом до копейки) добавляется в долю Компании — так `company + rep + ambassador == pool` сходится ровно всегда, без исключений.

```python
from decimal import Decimal, ROUND_HALF_UP

def round_kop(x: Decimal) -> Decimal:
    return x.quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)

def split_pool(pool: Decimal) -> dict:
    rep = round_kop(pool * Decimal('0.40'))
    amb = round_kop(pool * Decimal('0.20'))
    company = round_kop(pool) - rep - amb  # остаток идёт сюда
    return {"company": company, "representative": rep, "ambassador": amb}
```

### 8.2. МСП-счёт (отчётный)

|---|---|
| **Владелец** | МСП (юрлицо / ИП / Самозанятый) |
| **Валюта** | Рубли |

### 8.4. Каналы выплат, юридический статус и комиссия банка

<!-- fact-guard: allow — BRD §8.4 содержит каноничные пороги/ставки вывода; канон: PARAMS.md §Юр.модель, money_flow_public.md v2.0.3 -->

**Позиционирование:** LOVII — финтех- и инфраструктурный партнёр для МСП, Представителей и Амбассадоров. Условия вывода (порог, периодичность, комиссия банка) определяются **исключительно юридическим статусом получателя** (`legal_status`) и **не зависят от МЛМ-роли** (МСП / Представитель / Амбассадор — разделы 2, 5). Налоги с полученной выручки получатель платит **самостоятельно**; LOVII удерживает только комиссию банка на вывод (и только в оговорённом ниже случае — см. «Кто платит комиссию»).

**Юридический статус (`legal_status`: ИП / ООО / Самозанятый)** — отдельный атрибут пользователя, независимый от МЛМ-статуса (Представитель/Мэр/Губернатор, раздел 5).

**Логика вывода по статусу (эталон — `money_flow_public.md` v2.0.3, Договор Т-Банк № МР-08.26/АКС_01, Приложение № 3):**

> **⚠️ Вывод средств доступен только при активной подписке.** Если подписка не активна —
> баланс доступен **только для оплаты товаров** внутри платформы у любого МСП **и для
> оплаты тарифа**.

| Статус получателя | Порог вывода | Периодичность | Комиссия банка (Т-Банк) | Кто платит комиссию |
|---|---|---|---|---|
| **ИП / ООО** (независимо от роли: МСП, Представитель или Амбассадор) | **нет** — выплачивается любая сумма | По согласованному **графику, который выбирает сам получатель** | 0,5% («перечисление третьему лицу», п. 3.4) | Компания |
| **Самозанятый** (независимо от роли: МСП, Представитель или Амбассадор) | **3 000 ₽** (ниже — см. правило оплаты комиссии) | По запросу | 1% мин 30 ₽ («перевод Получателю») | ≥ 3 000 ₽ → Компания; < 3 000 ₽ → самозанятый (30 ₽ удерживается из суммы вывода) |

**Почему порог самозанятого — 3 000 ₽, а не 8 000 ₽.** У Т-Банка для «перевода Получателю» действует ставка 1% с минимумом 30 ₽. Точка безубыточности, где процентная комиссия достигает плоского минимума: `30 / 0,01 = 3 000 ₽`. При выводе **≥ 3 000 ₽** комиссия 1% ≥ 30 ₽, плоский минимум не срабатывает, и её полностью платит Компания. При выводе **< 3 000 ₽** плоский минимум (30 ₽) «весит» больше процента, поэтому он **удерживается из суммы вывода** — самозанятый получает `сумма − 30 ₽`, а Компания комиссию сверху не доплачивает. ИП/ООО работают по ставке 0,5% без флэт-минимума (по договору — «перечисление третьему лицу»), поэтому для них порога нет и любая сумма выплачивается по графику.

**Выбор графика выплат (ИП / ООО).** Получатель со статусом ИП/ООО выбирает график выплат в настройках аккаунта (например: ежедневно / еженедельно / ежемесячно / по достижении заданной суммы). Система (cron) исполняет выплаты строго по выбранному графику; порог отсутствует, выплачивается любой накопленный остаток. МЛМ-роль (МСП / Представитель / Амбассадор) на график не влияет.

**Формула комиссии (Т-Банк):**

```python
from decimal import Decimal, ROUND_HALF_UP

LEGAL_ENTITY_RATE   = Decimal('0.005')   # ИП/ООО: перечисление третьему лицу, 0,5%
SELF_EMPLOYED_RATE  = Decimal('0.01')    # Самозанятый: перевод Получателю, 1%
SELF_EMPLOYED_MIN   = Decimal('30')      # минимальная комиссия для самозанятого
SELF_EMPLOYED_FLOOR = Decimal('3000')    # компания платит комиссию при выводе ≥ этого

def bank_payout_commission(amount: Decimal, legal_status: str) -> tuple[Decimal, str]:
    # Возвращает (комиссия, плательщик).
    # Плательщик "company" — комиссия удерживается из средств LOVII;
    # плательщик "user"    — комиссия вычитается из суммы вывода самозанятого.
    if legal_status == "Самозанятый":
        commission = max(round_kop(amount * SELF_EMPLOYED_RATE), SELF_EMPLOYED_MIN)
        payer = "company" if amount >= SELF_EMPLOYED_FLOOR else "user"
        return commission, payer
    return round_kop(amount * LEGAL_ENTITY_RATE), "company"
```

**Примеры расчёта (платит / удерживается):**

| Статус | Сумма вывода | Комиссия банка | Что получает получатель |
|---|---|---|---|
| ИП/ООО (любая роль) | 100 ₽ по графику | 0,50 ₽ (0,5%) | 100 ₽ (платит Компания) |
| ИП/ООО (любая роль) | 25 000 ₽ по графику | 125 ₽ (0,5%) | 25 000 ₽ (платит Компания) |
| Самозанятый ≥ 3 000 | 10 000 ₽ | 100 ₽ (1%) | 10 000 ₽ (платит Компания) |
| Самозанятый = 3 000 | 3 000 ₽ | 30 ₽ (1%) | 3 000 ₽ (платит Компания) |
| Самозанятый < 3 000 | 2 000 ₽ | 30 ₽ (мин.) | 1 970 ₽ (2 000 − 30, платит самозанятый) |
| Самозанятый < 3 000 | 50 ₽ | 30 ₽ (мин.) | 20 ₽ (50 − 30, платит самозанятый) |

### 8.5. Оплата подписки с UDID-счёта

**Алгоритм:**
```
1. Пользователь инициирует оплату подписки
2. Проверить: UDID_баланс ≥ стоимость_подписки × период
3. Если да:
   - Списать с UDID-счёта
   - Активировать подписку на указанный период
4. Если нет:
   - Предложить оплату картой / СБП
   - Или частичное списание + остаток картой
```

## 9. Edge Cases (граничные случаи)

| 26 | Перевод с UDID-счёта несуществующему UDID | Отклонить, вернуть ошибку `UDID_NOT_FOUND` |

| 28 | МСП-счёт: ошибка выплаты на р/с (банк отклонил) | Retain на счёте, уведомить МСП, повторить через 24ч |

### 9.6. События

| # | Сценарий | Ожидаемое поведение |
|---|---|---|
| 29 | Представитель подал заявку на Школу, но подписка истекла | Отклонить заявку |
| 30 | Губернатор не может лететь на Каникулы по мед. показаниям | Перенос на следующий год, без потери права |

### 9.7. Дополнительные edge cases (v1.1)

| # | Сценарий | Ожидаемое поведение |
|---|---|---|
| 31 | МСП со статусом Самозанятый пытается запросить push вместо pull | Отклонить, `400` — push доступен только ИП/ООО |
| 32 | Клиент передал в запросе транзакции `promo_code`, отличный от регистрационного кода МСП | Игнорировать поле от клиента (если вообще присутствует); распределение всегда идёт по серверным данным МСП |
| 33 | Амбассадор деактивирован Основателем | Его 20% уходит Компании до момента переназначения нового Амбассадора на префикс |
| 34 | Представитель зарегистрировал свою же точку под собственным промокодом (self-referral) | Разрешено, получает свои 40% как обычный Представитель (раздел 7.5) |
| 35 | Оплата подписки (599₽ или 199₽) | Не создаёт запись `PoolDistribution`, распределение 40/40/20 не применяется (раздел 4.6) |
| 36 | Расчёт пула даёт сумму с остатком при округлении до копейки (например, `pool = 0.03 ₽`) | Остаток от округления идёт в долю Компании, сумма трёх долей всегда точно равна pool (раздел 7.6) |
| 37 | Возврат/чарджбэк после того, как начисление уже выведено Представителем | *Открытый вопрос — требует отдельного решения бизнеса.* Предлагаемый дефолт: разрешить уход `balance` в отрицательное значение, заблокировать новые pull-запросы до погашения, не блокировать сам аккаунт |
| 38 | Массовая регистрация МСП под одним промокодом за короткий период | Не блокируется автоматически на MVP, но должно логироваться для ручной проверки (антифрод-бэклог, см. ниже) |
| 39 | Дробление одной крупной транзакции на много мелких | Не блокируется автоматически на MVP, логировать для ручной проверки |

**Антифрод — бэклог (не блокирует MVP, но должно быть в системе логирования):**
- Аномальный прирост МСП под одним промокодом за короткий период.
- Мониторинг доли чарджбэков на Представителя/МСП.
- Паттерны дробления транзакций.

## 10. Бизнес-правила (сводка для разработчика)

```python
# Псевдокод ключевых правил
from decimal import Decimal, ROUND_HALF_UP

# 1. Регистрация
def register(inviter_code: str | None) -> User:
    if inviter_code is None:
        prefix = "AA"  # Основатель
    else:
        validate(inviter_code)
        prefix = inviter_code[:2]
    
    suffix = generate_unique_suffix(prefix, max_attempts=10)
    promo = prefix + suffix
    return User(udid=new_udid(), promo=promo, prefix=prefix)


# 2. Смена промокода
def change_promo(user: User) -> str:
    if days_since_last_change(user) < 30:
        raise PromoChangeTooEarly()
    
    new_suffix = generate_unique_suffix(user.prefix, max_attempts=10)
    new_promo = user.prefix + new_suffix
    user.promo = new_promo
    user.last_promo_change = now()
    return new_promo


# 3. Расчёт пула
def round_kop(x: Decimal) -> Decimal:
    return x.quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)

def calculate_pool(order_amount: Decimal, payment_method: str) -> Decimal:
    # Базовые ставки эквайринга (карты — без НДС; T-Pay и СБП НДС не облагаются)
    BASE_RATE = {
        "card": Decimal('0.0259'),   # 2,59% без учёта НДС
        "tpay": Decimal('0.0259'),   # 2,59% НДС не облагается
        "sbp":  Decimal('0.007'),    # 0,7%  НДС не облагается
    }
    # НДС применяется ТОЛЬКО к картам (ФЗ №425-ФЗ, с 01.01.2026)
    VAT_RATE = {
        "card": Decimal('0.22'),     # карты: +22% НДС → 3,16% эффективно
        "tpay": Decimal('0'),        # T-Pay: НДС не облагается
        "sbp":  Decimal('0'),        # СБП:   НДС не облагается
    }
    base = BASE_RATE[payment_method]
    vat_rate = VAT_RATE[payment_method]
    bank_rate = base * (1 + vat_rate)            # эффективная ставка банка
    bank_commission = order_amount * bank_rate   # отдельная ветка НДС для карт

    if payment_method == "card" and bank_commission < Decimal('3.49'):
        bank_commission = Decimal('3.49')

    platform_load = Decimal('0.10')  # 10% нагрузка на МСП
    pool = order_amount * platform_load - bank_commission
    return max(round_kop(pool), Decimal('0'))


# 3.1 Определение сторон распределения — ТОЛЬКО по регистрационному промокоду МСП,
#     клиент не передаёт promo_code в запросе транзакции (см. раздел 7.2)
def resolve_distribution_parties(msp_id: str) -> tuple[str, str]:
    msp = get_user(msp_id)
    promo = get_promo_code_by_owner(msp.udid)   # промокод, под которым МСП зарегистрирован
    rep_udid = promo.invited_by_owner_udid
    amb_prefix = promo.prefix
    return rep_udid, amb_prefix


# 4. Распределение пула
def distribute_pool(pool: Decimal, rep_udid: str, amb_prefix: str) -> dict:
    rep = round_kop(pool * Decimal('0.40'))
    amb = round_kop(pool * Decimal('0.20'))
    company = round_kop(pool) - rep - amb  # остаток округления — в Компанию (раздел 7.6)

    # Представитель: проверка активной подписки
    if not is_subscription_active(rep_udid):
        company += rep
        rep = Decimal('0')

    # Амбассадор: проверка активности (назначается вручную, подписки не имеет)
    ambassador_udid = get_ambassador_by_prefix(amb_prefix)
    if ambassador_udid is None or not is_active(ambassador_udid):
        company += amb
        amb = Decimal('0')

    return {
        "company": company,
        "representative": rep,
        "ambassador": amb
    }


# 5. Расчёт кэшбэк-комиссии
def calculate_cashback_fee(cashback_amount: Decimal) -> dict:
    fee = round_kop(cashback_amount * Decimal('0.25'))
    return {
        "total_fee": fee,
        "company": round_kop(fee * Decimal('0.40')),
        "representative": round_kop(fee * Decimal('0.40')),
        "ambassador": round_kop(fee * Decimal('0.20'))
    }


# 7. Комиссия банка на выплату (см. раздел 8.4: платит Компания, кроме вывода
#    самозанятым < 3 000 ₽ — тогда 30 ₽ удерживается из суммы вывода)
def bank_payout_commission(amount: Decimal, legal_status: str) -> tuple[Decimal, str]:
    if legal_status == "Самозанятый":
        commission = max(round_kop(amount * Decimal('0.01')), Decimal('30'))
        payer = "company" if amount >= Decimal('3000') else "user"
        return commission, payer
    return round_kop(amount * Decimal('0.005')), "company"


# 8. Определение режима выплаты — по legal_status, независимо от МЛМ-роли
def resolve_payout_mode(user: User) -> str:
    if user.legal_status in ("ИП", "ООО"):
        return "scheduled"   # по графику, выбирает получатель, порога нет
    return "on_request"      # самозанятый, порог 3 000 ₽ (раздел 8.4)


# 6. Проверка статуса
def check_status(user: User) -> str:
    msp_count = count_msp_in_branch(user.udid)
    cities = count_cities_in_branch(user.udid)
    network_gmv = calculate_branch_gmv(user.udid, days=30)
    
    if cities >= 3 and msp_count >= cities * 30 and network_gmv >= 15_000_000:
        return "Губернатор"
    elif msp_count >= 30:
        return "Мэр"
    else:
        return "Представитель"
```
