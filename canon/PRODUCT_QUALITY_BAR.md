# Продуктовый стандарт качества Lovii (обязателен для каждого агента)

> Установлено владельцем 2026-09-12 после «крика о помощи»: наш продукт станет
> известен всему миру. Всё, что видно пользователю, — публичное лицо и витрина
> практик. Профиль клиента (показатели, балансы) будут СКРИНИТЬ и отправлять
> друзьям. Документ обязателен к применению в любой задаче с видимым
> пользователю результатом (экраны app, кабинеты, письма, боты, веб).

## 0. Главный принцип — скрин-тест

> «Отправил бы я скрин этого экрана в сторис — рядом со скрином топового банка?»

Если нет — работа НЕ закончена, независимо от зелёных тестов. Профиль клиента,
балансы и показатели проектируются как объект гордости: крупный акцент, чистая
композиция, премиальная сдержанность (референсы: Revolut, Monobank, Т-Банк).

## 1. Definition of Done — чек-лист любого видимого изменения

**Дизайн и эстетика**
- Сверка с каноном: `lovii-demo` (эталон экранов) + `lovii-design` (токены).
  Новые цвета/градиенты/типографика — только через токены lovii-design, не
  кастомить локально (правило «демо = канон»).
- Сетка, отступы, радиусы, типографика — по демо; никаких «примерно».
- Три состояния КАЖДОГО экрана: загрузка (скелетон), пустое (продающее + CTA),
  ошибка (честный текст + действие). Пустое состояние — не тупик, а приглашение.
- Иконки — из набора проекта; эмодзи в UI — только там, где канон уже их принял.
  Как найти/взять/восстановить/добавить иконку в lovii-app — инструкция в
  `lovii-app/src/components/icons/README.md` (набор глифов не удалялся —
  в уборке 2026-09-13 удалены только неиспользуемые .vue-обёртки; новые
  контурные UI-иконки — через lucide: сначала демо, затем LvIcon).
- Тексты: русский, краткий, без канцелярита; не обещать того, что код не делает
  («мгновенно», «автоматически» — только если правда).

**Продуктовая логика**
- Цифры честные: реальные данные или ноль с пояснением; демо-заглушки в
  прод-путях запрещены.
- Форматы денег/чисел — платформенные (копейки → formatPrice); дат — ru.
- Все показатели, которыми пользователь хвастается, читаемы с первого взгляда.

**Техническая реализация**
- Адаптив ОБЯЗАТЕЛЕН: mobile-first (390px+), проверять планшет/десктоп
  (>768px) — это PWA и веб-версия, экран не разваливается на широких.
- a11y: контраст WCAG AA, тап-таргеты ≥44px, фокус и подписи у интерактивов.
- Производительность: lazy-чанки, скелетоны вместо блокирующих спиннеров,
  SW-кэш не прячет новые API (см. грабли PWA).
- Типизация, тесты, гейты — по протоколу репо; перед «готово» — визуальная
  проверка скриншотами на staging (три состояния).

## 2. Ресёрчи — обязательный слой перед кодом

- Папка ресёрчей и артефактов: **`lovii_docs/artifacts/`** (GitHub SSOT).
  Именование: `RES-NNN-<slug>.md`. Каждый новый ресёрч регистрируется одной
  строкой в `artifacts/REGISTRY.md`.
- Перед реализацией нового экрана/фичи агент ОБЯЗАН:
  1. Открыть `artifacts/REGISTRY.md` и прочитать относящиеся ресёрчи;
  2. В task-файле привести раздел «Ресёрчи-источники» с путями;
  3. Если практик по теме нет — сделать ресёрч лучших мировых практик
     (категория продукта: финтех — Revolut/Monobank/Т-Банк; маркетплейс — и
     т.п.) и положить в artifacts ДО кода. Канон-доки (BRD/PRD/PARAMS/FINANCIAL_
     CONTOUR/PUSH_NOTIFICATIONS_SPEC/MINI_APPS_RESEARCH) остаются в `canon/` —
     на них ссылаемся как раньше.

## 3. Self-review агента перед статусом «сделано»

1. Скрин-сет: три состояния каждого затронутого экрана.
2. Чек-лист §1 пройден по пунктам (в отчёте указать «чек-лист продукт-бара ✓»).
3. Сверка с демо-каноном (не «похоже», а совпадение токенов/компонентов).
4. Гейты репо зелёные.

## 4. Для приёмщиков (владелец, zcode, Super Z)

«Технически работает» ≠ принято. Эстетика, адаптив и продуктовая логика —
часть приёмки наравне с кодом. Замечания по бару — в приёмке task-файла.
