# Справочник операций платформы: типы, роли, направления

> Собрано из кода ядра 2026-09-29 (Enums `LedgerEntryType`, `SplitRole`,
> `FinancialTransactionType`, `OrderStatus`, `PaymentStatus` + действия
> `DistributeOrderPoolAction`, `ProcessChargebackController`, `ReverseOrderPoolAction`).
> Назначение — единый источник «что за операция и к чему относится» для
> владельца, агентов и разбора инцидентов. Суммы в копейках, ledger —
> append-only, баланс счёта = сумма знаковых проводок.

## 0. Три контура учёта

| Таблица | Что учитывает | Пример записи |
|---|---|---|
| `ledger_entries` | **рублёвый контур**: деньги на счетах (номинальный, точки, оператор, клиенты-PAY) | «приход чека +100 000» |
| `wallet_transactions` | **балловый контур** (кэшбэк-баллы клиента) | «earn +10 000» |
| `chargeback_logs` | журнал чарджбэков (дельта + fee + кто провёл) | одна строка на платёж |

## 1. Рублёвый ledger: тип проводки × роль × направление

Роль (`split_role`) отвечает на вопрос «кому/за что», тип — «какая операция».
Пара «плюс на одном счёте / минус на другом» — одна хозяйственная операция.

| Тип | Роль | Откуда → Куда | Что означает |
|---|---|---|---|
| `payment_income` | `inbox` | банк → **номинальный счёт** | Приход чека 100% при подтверждённой оплате |
| `acquiring_fee` | `acquiring` | номинальный → банк | Эквайринг по каналу оплаты (карта 3,16%, баллы 0) |
| `order_income` | `point` | номинальный → **счёт точки (ИНН)** | Выручка точки — 90% чека |
| `pool_share` | `company` / `representative` / `ambassador` | номинальный → **оператор** | Пул 40/40/20 от остатка платформы |
| `cashback` | `cashback` | **счёт точки** → номинальный | Кэшбэк клиенту: точка выдаёт его из своей доли чека |
| `cashback` | `client` | номинальный → **кошелёк клиента** | Выплата кэшбэка клиенту (мост в балловый контур) |
| `cashback_fee` | `cashback_fee` | **счёт точки** → номинальный | Комиссия LOVII 25% от кэшбэка, платит точка |
| `cashback_fee` | `company` / `representative` / `ambassador` | номинальный → **оператор** | Расщепление fee 40/40/20 |
| `chargeback_reversal` | зеркалит роль исходной ноги | обратные знаки | Разворот всех ног сплита при чарджбэке/возврате |
| `chargeback_bank_fee` | `point` | **счёт точки** | Комиссия банка за чарджбэк — целиком на точке (канон §5.5 Правило 2) |
| `subscription_payment` | — | источник каскада → оператор | Оплата подписки Представителя (100% оператору) |
| `payout` | — | счёт получателя → банк | Выплата наружу (дневной реестр), сумма отрицательная |
| `payout_commission` | — | получатель → платформа | Удержание 30 ₽ при выплате < 3 000 ₽ |
| `adjustment` | — | по проводке | Ручная корректировка администратором |
| `external_flow` (только в отчёте `ledger:tree`) | — | вне леджера | Возврат банку/плательщику при чарджбэке — «внешний мир» для инварианта Σ=0 |

**Чтение заказа на 1000 ₽ (кэшбэк 10%, карта):** приход 1000 → эквайринг −31,60 →
точке 900 → кэшбэк 100 (с точки клиенту) → fee 25 (с точки, 40/40/20) →
пул 68,40 (40/40/20). Точка netto 775, клиент +100 баллами.

## 2. Балловый контур (`wallet_transactions`)

| Тип | Знак | Смысл |
|---|---|---|
| `earn` | + | Начисление кэшбэка за заказ |
| `spend` | − | Оплата баллами (идут точке) |
| `refund` | + | Возврат списанных баллов (зеркало spend при отмене/чарджбэке) |
| refund при chargeback | − | Возврат **начисленного** кэшбэка (зеркало earn) |
| `transfer` | ± | P2P-перевод PAY-баллов |
| `fee` | − | Комиссия перевода (сейчас 0%) |
| `adjustment` | ± | Ручная корректировка админом |
| `subscription_debit` / `..._fallback` | − | Списание подписки с карты PAY |

## 3. Статусы заказа (`orders.status`) — жизненный цикл

`created` (создан) → `submitted` (отправлен в точку) → `accepted` (принят точкой) →
`preparing` → `ready` → самовывоз: `completed`; доставка: `handed_to_delivery` →
`on_the_way` → `completed`. Отклонение: `cancelled` (кем-то отменён),
`failed` (не дошёл/ошибка).

Параллельный технический статус `submission_status` (`pending/submitted/failed/retrying`)
— только про доставку заказа в учётную систему точки, покупателю не показывается.

**Важно:** `status` — про готовность/выдачу заказа, НЕ про деньги. Деньги
описывает платёж.

## 4. Статусы платежа (`payments.status`)

`new` → `pending` → `authorized` (банк держит сумму) → `confirming` → `confirmed`
(деньги получены — здесь срабатывает сплит и кэшбэк).
Неуспех: `rejected` / `expired` / `canceled` / `failed`.
После успеха: `refunded` (возврат), `reversed`, **`chargeback`** (оспаривание —
легальный переход после `confirmed`).

## 5. Правила чтения

1. Одна хозяйственная операция = несколько знаковых проводок на разных счетах;
   смотреть по одной строке нельзя.
2. Инвариант: Σ всех проводок заказа = эквайринг (и bank fee при чарджбэке) —
   только эти деньги «уходят из системы».
3. Кэшбэк платит точка (− на её счёте) + 25% fee платформе. Платформа
   зарабатывает на пуле остатка и fee.
4. Проверка любого заказа: `php artisan ledger:tree <source_type> <payment_id>`
   → дерево с узлами и Σ=0 (внешние вливания адресуются `external:*`).
