## 0. Зачем это

Владелец работает с двумя ИИ-исполнителями одновременно:

- **Координатор** — агент AutoCoder на этом Mac: ведёт очередь задач, готовит контекст
  для сессий, принимает работу (ревью + независимый прогон), мержит, закрывает задачи,
  ведёт канон и гигиену веток.
- **Арена** — внешний кодинг-агент: исполняет по одной задаче за сессию и сдаёт
  ветку + PR с отчётом.

Если тебя (агента или параллельную сессию) просят «работать через Арену», «сдавать
как арена» или продолжать работу этого контура — **прочитай этот документ и следуй
ему**. Не изобретай свой процесс и не переспрашивай устройство: оно здесь.

## 1. Роли

| Роль | Кто | Полномочия и границы |
|---|---|---|
| Владелец | человек | продуктовые решения, «го» на чувствительные шаги, выбор волны; может делегировать («решай сам») |
| Координатор | AutoCoder | очередь (issues + эпик), контекст-блоки, приёмка, мерж, закрытие задач, канон, удаление слитых веток |
| Арена | внешний агент | одна задача за сессию: ветка от свежего `main` → реализация → тесты/CI → PR с полным отчётом |
| Аудитор/верификатор | внешний (super-z) | read-only аудиты и большие доки; независимая верификация фиксов по реестру находок (✅/⚠️/❌/🔁, живые пробы); подключается владельцем |

Общение координатор ↔ Арена — **через владельца** (ретрансляция контекста и результатов).

## 2. Цикл одной задачи (золотой путь)

1. **Очередь.** Задача существует как issue в GitHub-репозитории; живой приоритет и
   правила — в эпик-issue (пример: `#13` в mock-services).
2. **Контекст.** Координатор пишет короткий контекст-блок для сессии; владелец
   передаёт его Арене.
3. **Сессия Арены.** Старт от свежего `main`; своя ветка `arena/<сессия>-<тема>`;
   реализация; тесты зелёные до и после; PR в `main` с отчётом **в описании**
   (что сделано / что нет / развилки / риски) и строкой `Closes #N`.
4. **CI.** Все проверки зелёные (тесты, docker/compose — где есть).
5. **«Проверь».** Владелец сигналит координатору; тот проверяет **независимо**:
   fetch ветки, ревью дифа, собственный полный прогон, выборочные сверки с кодом.
6. **Приёмка.** Комментарий-приёмка в issue (доказательства + рулинги по развилкам);
   мерж squash; issue закрывается; слитая ветка удаляется; канон обновляется.
7. **Следующая волна.** Координатор обновляет очередь и выдаёт следующий контекст.

> Для **фикс-волн**: после приёмки и мержа независимый аудитор (super-z) перепроверяет исправления по реестру находок — свежий клон, статусы по каждой позиции, живые пробы security-утверждений; результат — отчётом в `docs/audit/`.

## 3. Каналы и ограничения (важно)

- **У Арены нет права комментировать issues** (GitHub-приложение выдано с `Issues: read`).
  Поэтому весь отчёт — в **описании PR**, а вопросы — через владельца координатору **до кода**.
  Комментарии в issues от имени контура публикует координатор.
- **«Сдано» = видно на GitHub**: ветка + PR (+ зелёный CI). Локальные коммиты не считаются.
- **Сессии Арены разовые**: одна сессия = одна задача = одна ветка; предыдущие ветки не
  продолжаются. Следующая сессия стартует от свежего `main`; координатор гарантирует,
  что предыдущее влито до старта следующего (поэтому задачи идут последовательно).
- Владелец — ретранслятор; координатор — точка контакта для трактовок и рулингов.

## 4. Дисциплина исполнения (для любого исполнителя, включая Арену)

- Тесты зелёные **до и после**; zero-dep (в mock-services — Node ≥18, без npm-зависимостей);
  существующие контракты не ломать без явного указания в задаче.
- Копирайт/SPDX-шапки — в каждом новом/тронутом файле (правило бойскаута).
- Провайдеро-нейтральность: «фирменные» профили — только через env; дефолты нейтральные.
- **Неясность/трактовка → вопрос ДО кода** (через владельца координатору). Свою
  трактовку молча не подставлять.
- Отчёт обязателен, включая «что НЕ сделано» и «риски». Отсутствие отчёта = не сдано.
- Фикс-волны: ID находок аудита — в commit subject (`fix(PA-50): …`) — вход прицельной независимой верификации.

## 5. Приёмка (как это делает координатор)

- Независимая проверка: свой fetch + ревью ключевых путей + **свой** полный прогон +
  выборочные spot-checks против кода. Отчёт исполнителя — не доказательство.
- Эпистемика: observed / candidate / reproduced / confirmed; статус не повышается «на слово».
- Находки вне задачи не теряются: оформляются в очередь отдельными issue.
- Рулинги координатора по трактовкам фиксируются в комментариях issue (и в каноне).

## 7. Чек-лист: «меня просят поработать через Арену»

1. Прочитай этот документ целиком (и эпик-issue контура).
2. Возьми задачу из очереди; свои не выдумывай.
3. Соблюдай цикл §2 и ограничения §3.
4. Не пушь в `main`; не трогай чужие ветки; не создавай конкурирующих процессов.
5. Вопросы — через владельца координатору **до** кода.
6. Сдал → ждёшь «Проверь» → координатор ведёт приёмку (сам не мержи).
