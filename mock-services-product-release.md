# Продуктовый релиз mock-services — зафиксированный состав

Дата фиксации: 2026-10-14 · Статус: состав УТВЕРЖДЁН владельцем (контрольная сборка просмотрена)
Решение владельца: в dev-репозитории rucorp/mock-services больше НЕ релизим; продуктовый
релиз собирается и публикуется в ОТДЕЛЬНОМ продуктовом репозитории после завершения
разработки (ожидаем ответы арены и sz).

## Состав продуктового релиза (утверждён, менять только решением владельца)

Рантайм и код:
- `services/` — 9 адаптеров (tbank-mock, kassa-mock/Ferma, yookassa-mock, atol-mock,
  alfa-mock, sber-mock, vtb-mock, first-ofd-mock, kontur-ofd-mock);
  в каждом: server.js + selftest.js + README.md
- `packages/core/` — общее ядро (index.js + selftest.js)
- `protocols/` — JSON-манифесты протоколов (нужны selftest'ам и check:drift)
- `scripts/docker-healthcheck.js` — единственный скрипт, идущий в образ
- `package.json` (zero dependencies)

Compose-файлы:
- `docker-compose.yml` — локальная разработка (8 сервисов, из исходников)
- `docker-compose.include.yml` — полный стенд, 9 сервисов, профиль `mock`, digest-пин
- `docker-compose.staging.yml` — лёгкий стенд «банк + касса» (tbank :3100 + Ferma :3101), digest-пин

Документация:
- `README.md` — быстрый старт, матрица возможностей, дорожная карта
- `docs/integration/` — гайды «интеграция за 10 минут» по каждому провайдеру
- `docs/openapi/` — OpenAPI 3.1 спецификации
- `LICENSE` (Apache-2.0), `NOTICE`

## Что НЕ входит (исключено из продуктового релиза навсегда)

- `docs/canon/**` — внутренние спеки (MOCK_SERVICES_SPEC, SZ-карточки)
- `docs/reference/**` — конспекты документации провайдеров
- `AGENTS.md`, внутренние брифы

Инфраструктура разработки (остаётся только в dev-репо):
- `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`
- `.github/` (workflows CI)
- dev-скрипты: check-protocol-drift, check-docs-links, compose-selftest, docker-smoke, sync-upstream

## Механика релиза (как договорились)

1. Dev-репозиторий: разработка, CI, теги НЕ публикуем как «релизы».
2. Перед публикацией в продуктовом репо — контрольная сборка (по составу выше),
   владелец просматривает, возвращает список исключений.
3. Продуктовый репозиторий: только ПО (состав выше) + ссылка на публичный dev-репозиторий.
4. Docker-образ GHCR `ghcr.io/rucorp/mock-services` остаётся каналом поставки;
   digest-пин обязателен.
