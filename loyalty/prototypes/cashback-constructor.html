01Что есть сейчас

Лояльность в платформе реализована на контуре баллов: wallet + wallet_transactions с типами earn / spend / refund / adjustment и идемпотентностью по unique-индексу (wallet_id, order_id, type). Начисление ведёт LoyaltyService::earnFromOrder.

02Проблема

Партнёр не может ни выключить кэшбэк у себя, ни задать свой процент, ни выделить товарную группу. При этом кэшбэк списывается именно из его доли — то есть расход несёт партнёр, а решает платформа. Это и продуктовый дисбаланс, и потерянный рычаг: конкурентные акции по категориям не запустить без правки БД.

03Целевая модель — две сущности

MVP-конструктор даёт партнёру ровно два рычага. Всё остальное (сегменты, уровни, акции по расписанию) — фазы 2–3.

Сущность 1
Кэшбэк по умолчанию

Один процент на магазин (мерчант). Включатель, значение, период. Это «пол» программы — что начисляется на весь заказ, если товар не попал ни в одну группу.

Сущность 2
Группы товаров

Именованный набор с собственным процентом. Состав: категории каталога мерчанта и/или отдельные товары. Переопределяет процент по умолчанию для попавших в набор позиций.

05Алгоритм начисления

Резолвинг выполняется один раз на заказ, без N+1 в request path (требование стража производительности SZ-060).

1
Правила мерчанта — 1 запрос
активные правила, где merchant_id = M OR merchant_id IS NULL, с учётом окна дат
2
Состав групп — 2 запроса
карты «категория → группа» и «товар → группа» для мерчанта
3
Матчинг позиции
группа = сначала по товару, затем по категории, иначе null
4
Процент
правило группы → правило «по умолчанию» мерчанта → платформенное → 0
5
Сумма
Σ round(item.total_price × % / 100) → orders.bonus_earned

Идемпотентность и возвраты не меняются: контракт wallet_transactions (wallet_id, order_id, type) остаётся, повторный вебхук банка по-прежнему даёт no-op.

06UX кабинета — mobile-first

В lovii-b2b появляется группа навигации «Лояльность» и страница-конструктор (не таблица CRUD). 07Что видит покупатель

Фаза 1, без изменений app: начисление уже видно в ленте баллов (wallet/transactions, комментарий «Кэшбэк за заказ №N»). Расширяем комментарий именем правила — прозрачность без правок мобильного клиента.

Фаза 2 (lovii-app): поле cashback_percent из API каталога, бейдж «Кэшбэк N%» в карточке товара и строка «Начислим N баллов» в чекауте. Это отдельная задача с визуальными гейтами `PRODUCT_QUALITY_BAR`.

11Открытые вопросы

Потолок кэшбэка
какой максимум в % и где он задаётся? Предложение: 30%, настройка админки.
Состав групп
только категории или ещё точечные товары? Предложение: оба режима.
Кто платит
подтверждаем списание из доли точки (как T-014)? Предложение: да.
Фолбэк при выключенном кэшбэке
0% или платформенное правило? Предложение: явный 0%.
