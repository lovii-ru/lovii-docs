# 10 · План реализации для ИИ-агентов

> Работа разбита на эпики и задачи с явными зависимостями, критериями готовности (DoD) и тестами. Порядок эпиков — порядок сборки. Оценки — в «агент-днях» условной производительности (1 агент-день ≈ 1 PR с тестами). Стек не фиксирован ([README](README.md) §«Стек»): обязательны контракты — JSON Schema Spec, OpenAPI, DDL PostgreSQL, golden-тесты.

---

## 0. Общие правила

**Definition of Done (для каждой задачи):**
1. Код + тесты (unit ≥ 80 % по движку/леджеру; контрактные тесты по OpenAPI; golden-тесты зелёные).
2. Обновлены документы пакета, если менялся контракт (Spec, API, DDL) — в том же PR.
3. Линтеры/типы без ошибок; миграции применяются с нуля и повторно.
4. Тексты интерфейса — русский, из [06](06-ui-spec.md) §4 либо добавлены туда.
5. PR описывает: что сделано, как проверить, какие инварианты ([03 §10](03-rules-engine.md)) затронуты.

**Инварианты, которые нельзя нарушать:** см. [AGENTS.md](AGENTS.md) §2.

**Ветки/PR:** одна задача = один PR; название `loyalty/E{n}-T{m}-краткое-описание`; PR ссылается на ID задачи.

## 1. Дорожная карта

| Фаза | Срок | Эпики | Результат |
|---|---|---|---|
| **MVP** | 8 недель | E0–E8 | 9 механик, кабинет, QR-поток, кошелёк с лотами, аналитика с holdout, пилот в 1 локации |
| **Пилот** | +6 недель | E9 | 3 локации, ≥ 50 ТСП с кампаниями, отчёт по метрикам [01 §3.2](01-product-overview.md) |
| **V2** | +12 недель | E10–E13 | остальные 9 механик, кассовые адаптеры, A/B, партнёрства |

Параллелизация: после E1 и E2 фронтенд (E4, E6) и интеграции (E5) идут параллельно; E3 (шаблоны) — независимые задачи, по одной на агента.

## 3. Стратегия тестирования

| Уровень | Что | Инструменты (пример) |
|---|---|---|
| Unit | Движок (условия, действия, стекинг, округления), компиляторы шаблонов, леджер | тест-фреймворк стека; property-based для инвариантов |
| Golden | `examples/testcases/*.json` — фиксированные контексты → ожидаемый результат; обновление только осознанное (ревью diff) | раннер E0-T4 |
| Контрактные | OpenAPI ↔ реализация; JSON Schema ↔ примеры кампаний | schemathesis / Prism / ajv |
| Интеграционные | PostgreSQL (testcontainers): транзакции commit/reverse, гонки, RLS | |
| E2E | Мастер → публикация → QR-оплата → кошелёк → возврат | Playwright/Cypress |
| Нагрузочные | quote/commit по целям [09 §1](09-nfr-security-compliance.md) | k6 |
| Безопасность | authz-матрица ролей, rate-limit, SAST/SCA | |
| Доступность | axe на экранах кабинета и клиентских компонентах | |

Минимальный набор golden-кейсов для MVP — в [`examples/testcases/`](examples/testcases/README.md).

## 4. Критерии готовности MVP к пилоту

- [ ] 9 механик MVP + `platform_base` проходят golden-тесты и e2e.
- [ ] Первая кампания создаётся с телефона за ≤ 5 мин (медиана в юзабилити-тесте с 5 ТСП).
- [ ] QR-оплата с quote/commit/reverse в проде платформы; деградация без Loyalty не ломает оплату.
- [ ] Кошелёк показывает лоты и сгорания; история операций объясняет источник.
- [ ] Аналитика с holdout; отчёт по кампании и обзор точки.
- [ ] Антифрод-правила E8-T1 включены; аудит-лог; условия акций публикуются.
- [ ] Нагрузочные цели достигнуты; алерты настроены; runbook на отказ сервиса.
- [ ] Юридическая проверка пунктов [09 §4](09-nfr-security-compliance.md) с отметкой «принято / изменить».
