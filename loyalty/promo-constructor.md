## 1. Продуктовая рамка

Партнёр получает не «поле с процентом», а **конструктор акций**: он собирает правило из
трёх частей — **триггер → награда → условия**, и по желанию **публикует** его на витрину
(товаром-комбо или карточкой в промо-блоке).

Ключевая продуктовая идея: **комбо — это товар**. Комбо живёт на витрине как обычная
позиция (со своей ценой, скидкой и составом), поэтому каталог, корзина, заказ, чекаут и
квитанция работают без новой логики. Меняется только способ его создать (конструктор)
и рендер состава.

## 2. Механики (триггер × награда)

### Триггеры

| ID | Триггер | Условие срабатывания | Пример партнёра |
|---|---|---|---|
| T1 | `item` | в корзине есть товар / товар группы | «кэшбэк 10% на витамины» |
| T2 | `cart_sum` | сумма чека ≥ N ₽ | «купил от 2 000 ₽ → напиток в подарок» |
| T3 | `combo` | в корзине одновременно товары из набора | «бургер + напиток = комбо со скидкой» |
| T4 | `nth` *(Ф3)* | N-й товар / N-я покупка | «каждый 5-й кофе бесплатно» |
| T5 | `time` *(Ф3)* | часы/дни, «счастливые часы» | «−20% до 20:00» |
| T6 | `segment` *(Ф3)* | сегмент клиента (новый/VIP) | «новичкам 15% на первый заказ» |

### Награды

| ID | Награда | Что делает | Область |
|---|---|---|---|
| R1 | `cashback_percent` | % баллами | заказ / товар / группа |
| R2 | `discount_percent` | скидка % | комбо-набор / чек / самая дорогая позиция |
| R3 | `discount_fixed` | скидка ₽ | комбо-набор |
| R4 | `gift` | товар за 0 ₽ | позиция + лимит кол-ва |
| R5 | `cashback_fixed` *(Ф3)* | фикс. баллы | любой |

### Условия и лимиты
период (`starts_at`/`ends_at`), дни недели, «не более X на заказ», «раз на клиента»,
потолок %, правило стекирования.

## 3. Правила стекирования (по умолчанию)

1. **Скидки и кэшбэк — разные линии.** Скидка уменьшает чек; кэшбэк считается от суммы
   **после скидки** (параметр правила — можно считать от исходной).
2. **Между скидками** — по умолчанию «лучшая для клиента»; партнёр может включить
   «суммировать до лимита».
3. **Кэшбэк** — приоритет: правило на чек > правило на группу > правило на товар > умолчание.
   Суммирование групповых — до потолка платформы.
4. **Подарок** — не более N позиций на заказ; не суммируется с другой скидкой на тот же товар.
5. Всё непокрытое — **0**, а не догадка.

## 4. Модель данных (lovii-core, схема `public`)

### 4.1 `promo_rules` — единая таблица правил

Текущую `loyalty_rules` **обобщаем** (не плодим сущности). Миграция переносит глобальную
строку как правило `type='cashback'` c `merchant_id = NULL`.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | bigint PK | |
| `merchant_id` | bigint NULL → merchants | NULL = платформенное |
| `group_id` | bigint NULL → loyalty_product_groups | только для `type='cashback'` |
| `type` | enum `cashback, threshold, combo, gift` | вид механики |
| `name` | string | |
| `trigger` | jsonb | `{kind, min_sum, groups[], products[], weekdays[]}` |
| `reward` | jsonb | `{kind, value, scope, gift_product_id, gift_qty}` |
| `limits` | jsonb | `{cap_percent, max_per_order, per_customer, stack}` |
| `storefront` | jsonb | `{publish, title, subtitle, badge, deadline_text, banner}` |
| `priority` | smallint | разрешение пересечений |
| `is_active`, `starts_at`, `ends_at`, `timestamps` | | как сейчас |

### 4.2 Комбо = оффер

Комбо **не** отдельная таблица каталога: это `merchant_offers` с `offer_type = 'bundle'`
плюс состав:

- `merchant_offer_bundle_items` — `offer_id`, `component_offer_id`, `qty` (unique offer+component)

Тогда витрина, корзина, заказ, чекаут и квитанция работают штатно; конструктор лишь
создаёт/обновляет такой оффер, а `price` = Σ компонентов − скидка.

### 4.3 Что переносится из базового конструктора без изменений
`loyalty_product_groups`, `loyalty_group_categories`, `loyalty_group_products` (SZ-070).

## 5. Где что видит покупатель

| Точка контакта | Что показываем |
|---|---|
| Карточка товара | бейдж «Кэшбэк N%»; у комбо — «Комбо −X%» и состав |
| Каталог точки | комбо-товар рядом с обычными позициями, старая цена зачёркнута |
| Главная, промо-блок | карточки акций партнёра (из `storefront.publish`) |
| Корзина | под позицией «Кэшбэк N% · +K баллов»; в итоге — «Кэшбэк за заказ», «Подарок» |
| Чекаут | те же строки до подтверждения — покупатель видит выгоду заранее |
| Квитанция | скидка комбо, начисленный кэшбэк, подарок |

Честность: суммы считаются из реальных правил, без «примерно» и без demo-заглушек в
прод-путях (`PRODUCT_QUALITY_BAR` §1).

## 6. UX конструктора (mobile-first, lovii-b2b)

Раздел **«Промо»** в кабинете партнёра:

1. **Кэшбэк** — по умолчанию + группы товаров (базовый конструктор).
2. **Акции** — список правил с типом и статусом («На витрине»), `+ Акция`.
3. **Мастер акции** — 3 шага: механика → настройка → публикация.
   - *Сумма чека*: порог (чипы 500/1000/2000/3000) → награда (кэшбэк +N% / подарок) → публикация.
   - *Комбо*: выбрать 2+ товара из каталога точки → скидка % → предпросмотр витрины → опубликовать.
4. **Предпросмотр покупателя** — карточка комбо и карточка промо-блока.
5. **Итог** — средний кэшбэк, покрытие каталога, число активных акций.

Требования: тап-таргеты ≥44px, три состояния, стек вместо широких таблиц, липкая кнопка.

## 7. Метрики продукта

- доля чеков с промо; средний чек с промо vs без;
- uplift оборота точки; цена программы (выплаты из доли точки + комиссия 25%);
- конверсия комбо-товара; доля корзин, дошедших до порога чека.

## 9. Открытые вопросы (к владельцу)

1. Комбо — **статичный оффер** (цена на витрине) или **динамическая скидка в корзине**?
   _Предложение: Ф2 — статичный оффер; Ф3 — динамика._
2. Кэшбэк считать от суммы **до или после** скидки? _Предложение: после._
3. Кто платит подарок и скидку — доля точки (как кэшбэк)? _Предложение: да._
4. Потолок скидки (предлагаю 50%) и кэшбэка (30%).
5. Может ли платформа снимать партнёрскую акцию (модерация)? _Предложение: да, из админки._

## Решения владельца (2026-09-22) — канон `BRD.md` §7.3.1

- **Комбо — авто-категория «Комбо» внутри витрины точки**, всегда **первая** в списке
  категорий (если других категорий нет — она всё равно есть и содержит комбо-офферы).
- **Акции на главной ротируются.**
- **Применение без задержки** — сохранение в конструкторе сразу меняет витрину.
- **Потолков нет**; скидки и натуральные акции — за счёт точки; кэшбэк считается от
  фактически оплаченной суммы.
- Базовые механики настраиваются **из приложения**, сложные — из `lovii-b2b`.
