# 00. Что не хватает для запуска — карта пробелов и очередь задач

> **Назначение:** живой документ «чего не хватает до запуска + какая задача
> следующая». Обновляется после каждого мержа в staging / приёмки владельца.
> Это выжимка над 13 модулями ([README](README.md)); полные факты — в модулях,
> канон-цели — в `lovii_docs/canon/` (BACKLOG.md, BACKLOG_REVIEW.md,
> RELEASE_READINESS.md, PARAMS.md, FINANCIAL_CONTOUR.md).
> Срез: **2026-09-19**. Формат вердикта: 🔴 блокер запуска · 🟡 P2 (сразу после/
> параллельно) · 🟢 операционка · ✅ закрыто.

## Как пользоваться

1. Порядок в «Очереди» — рекомендованный: сверху то, без чего запуск невозможен
   или что дороже всего обойдётся промедлением.
2. У каждого пункта — «готово, когда»: критерий приёмки. Нет критерия — нет задачи.
3. После каждого мержа/приёмки: отметить ✅, перенести новое из session-доков.
4. Владельческие развилки (юрист, банк, «го» на прод) помечены 👤 — их не
   закрыть кодом, запускать их надо заранее.

## 🔴 Блокеры запуска (по порядку)

### Б-1 · 404-стена под нагрузкой (SZ-060) — инженерия
Нагрузка с одного IP (~137–650 rps) упирается в лимит и получает **404 на всё** —
стена 404 вместо деградации. До любого публичного трафика: понять, где режется
(nginx/cloudflare-уровень или rate-limit ядра), сделать честную деградацию
(429 + Retry-After, статические страницы) и перегнать стресс.
**Готово, когда:** стресс-прогон той же интенсивности без 404-стены; отчёт в session-доке.

### Б-2 · Прод-деплой не отработан ни разу — операционка
Поток: фича→staging→master (`gh workflow run ci.yml --ref master`) — исполнен 0 раз.
Первый прод-выкат делать сухим прогоном по чеклисту prod-env:
- `OTP_DEV_BYPASS=false` (в config default **true** — [06](06-vhod-otp.md));
- боевые токены ботов MAX/Telegram + вебхук MAX на проде (`OTP_MAX_TRANSPORT=bot_api`);
- `YANDEX_GEOCODER_API_KEY` + REFERER в `/opt/lovii-core/.env` и `VITE_YANDEX_MAP_API_KEY` в сборку app;
- боевой терминал Т-Банка (env), `INTERNAL_ADMIN_SECRET` в core+admin (совпадают);
- `OPERATOR_PARTNER_ID=265`, `payments.split.rep_subscription_gate` — решить, включать ли на проде сразу;
- VAPID-ключи пушей прод-пары, SMTP Яндекс (From = noreply).
**Готово, когда:** все 4 репо выкачены в prod, смоук-чеклист пройден (вход OTP без байпаса, витрина, заказ, вебхук Т-Банка), чеклист зафиксирован в `lovii-docs/deploy.md`.

### Б-3 · Верификация юрлиц — только ручной UPDATE — инженерия 👤
Каждый новый МСП = SQL/Tinker руками (`partners.verified_at`). Ресурса «Партнёры»
нет ни в admin, ни в b2b ([09](09-kabinet-b2b.md), [10](10-admin.md)).
**Готово, когда:** в админке есть минимальный ресурс партнёров с кнопкой
«Верифицировать» (и историей), право у super_admin; путь проверен на живой заявке.

### Б-4 · Авто-матчинг верификационного платежа 1 ₽ — инженерия
Код VER-<partner_id>-<суффикс> существует, входящие платежи никто не парсит —
`awaiting_payment → verifying` в коде нет переходов ([05](05-rol-i-kabinety.md),
[12](12-finkontur-v-kode.md)). С Б-3 даёт самосервисный онбординг МСП.
**Готово, когда:** входящий платёж с кодом VER автоматически двигает заявку
(идемпотентно), тест на дубль и на чужой платёж.

### Б-5 · Банковский контур выплат: тестовый контур Т-Банка → исполнение — инженерия 👤
Каркас выплат стоит, но деньги из банка не уходят: реестр — руками, внешняя карта
в каскаде подписки = failed `external_unavailable`. Владелец: доступы и регламент
есть, ждём тестовый контур (BACKLOG_REVIEW §C2 #6).
**Готово, когда:** тестовый контур подключён, push-реестр и pull-выплата
исполняются через API банка в тесте, потом боевой прогон на малой сумме.

### Б-6 · 54-ФЗ (фискализация) — инженерия + юрист 👤
Чека нет: квитанция «не является фискальным документом» ([03](03-zakazy.md)).
Публичный приём денег без ККТ/ОФД невозможен. Нужно: решение по провайдеру
(агентская схема уже в каноне), спека, интеграция, чек покупателю.
**Готово, когда:** фискальный чек выдаётся на оплату (или владельцем зафиксирован
пилот с «нефискальным» периодом и его рамки).

### Б-7 · Юрдокументы подписки и верификации — юрист 👤
- Раздел LOVII PASS в Публичную оферту (599/199, price lock, льготы) — подписка
  уже продаётся в коде; согласие на рекуррент пока не нужно (оплата только с
  внутреннего счёта), чек 54-ФЗ — к Б-6.
- Оферта присоединения: формулировка «верификация» + самозанятые-декларация
  (утверждено владельцем, не внесено).
- Текст ПЭП-документа — каркас есть, нужно утверждение.
**Готово, когда:** юрист сдал тексты, опубликованы.

  (один раз отрепетировать). 👤
- **Мониторинг/алерты** — RUM-точки есть, в проде не живут; Horizon/queue-алерты,
  бот-поллеры end-to-end не проверены.
- **Runbook прода** — `lovii-docs/deploy.md` дополнить прод-процедурой
  (rollback, канареечный %: первые 1/5/25/100%).
- **Зачистка данных**: дубль `email_notification_log`, Kuper-маппинги 1,41 млн строк
  (924 МБ — архив), черновики-дубли юрлиц Grand/Статус-92 (T-008), мёртвые медиа-ссылки
  (SZ-051 очищает).
- **Прод-чеклист контента**: активное правило `loyalty_rules` (без него кэшбэк = 0),
  честные тексты оферт, «Каникулы с компанией» — P3 (после M1).

## Очередь (рекомендованный порядок работ)

| Порядок | Задача | Кто | Почему в этом порядке |
|---|---|---|---|
| 1 | Б-1 404-стена (SZ-060) | агент (core/infra) | Дешевле всего чинить до трафика; без неё первый же наплыв = недоступная витрина |
| 2 | Б-3 верификация UI + Б-4 авто-матчинг | агент (admin+core) | Открывает самосервисный онбординг МСП — без этого каждый партнёр = ручная работа владельца |
| 3 | Б-2 прод-деплой dry-run | агент + 👤 владелец | Технически ничего не ждёт; к банку/юристу лучше идти с работающим продом |
| 4 | Б-5 тестовый контур Т-Банка | 👤 владелец → агент | Ждёт банк; когда придёт доступ — сразу исполнение выплат |
| 5 | Б-6 54-ФЗ + Б-7 юрист | 👤 юрист/владелец | Длинные циклы — запускать параллельно с пп.1–3, не после |
| 6 | П-1…П-4 (пуши, гео-зоны, идемпотентность, баллы в чекауте) | агент | Быстрые задачи с заметным эффектом для пилота |
| 7 | П-5…П-9 (P2P, промо, price-lock, доходы, orders.method) | агент | После стабилизации пилота |

**Принцип:** пп. 1–3 — кодом (агент), пп. 4–5 — ждут внешних сторон (банк, юрист),
поэтому стартуют первыми по времени, но не блокируют пп. 1–3. Пилот M1 технически
возможен уже после пп. 1–3 + Б-6-решения по чекам (или явного решения владельца
о «нефискальном» пилоте).

## Архив решений (чтобы не переспрашивать)

- Оплата подписки — только с внутреннего счёта; рекуррент и карты — после запуска (18.09).
- ПЭП Push-OTP — достаточно до реальных чеков (§C2 #4).
- Банковский API выплат — доступы есть, ждём тестовый контур (§C2 #6).
- P2P дефолт-максимум 3 000 ₽, переопределяется суперадмином (§C2 #2).
- Регистрация без промокода — свободна, фолбэк AA2222 (§C2 #3).
- Смена промокода — только Owner, никакой другой роли в MVP (§C2 #7).
- Pull-выплата ≥ 3 000 ₽ — 1% платит ОПЕРАТОР, без floor (§C2 #1; PARAMS §1.6 устарел).
