> **Назначение:** живой документ «чего не хватает до запуска + какая задача

> Это выжимка над 13 модулями ([README](README.md)); полные факты — в модулях,
> канон-цели — в `lovii_docs/canon/` (BACKLOG.md, BACKLOG_REVIEW.md,
> RELEASE_READINESS.md, PARAMS.md, FINANCIAL_CONTOUR.md).
> Срез: **2026-09-22** (после ревизии задачи 90 — `REVISION_2026-09-21.md` — и
> волн zcode 20–21.09). Формат вердикта: 🔴 блокер запуска · 🟡 P2 (сразу после/
> параллельно) · 🟢 операционка · ✅ закрыто.

## Как пользоваться

1. Порядок в «Очереди» — рекомендованный: сверху то, без чего запуск невозможен
   или что дороже всего обойдётся промедлением.
2. У каждого пункта — «готово, когда»: критерий приёмки. Нет критерия — нет задачи.
3. После каждого мержа/приёмки: отметить ✅, перенести новое из session-доков.
4. Владельческие развилки (юрист, банк, «го» на прод) помечены 👤 — их не
   закрыть кодом, запускать их надо заранее.

## 🔴 Блокеры запуска (по порядку)

### ✅ Б-1 · 404-стена под нагрузкой (SZ-060) — ЗАКРЫТО 19.09
«Стена» была **артефактом жгута v1**: пути без префикса `/api/v1` (14 204 из
14 363 запросов = Laravel-404 по 14 мс) + TLS-handshake на каждый запрос.
По access-логу caddy сервер не отдавал ни 429, ни 502 — лимитера не существует.
Перемер жгутом v2 (`lovii-app/scripts/stress/`, session 122): честная деградация очередью, 0 ошибок до 200 VU; ёмкость поднята
(fpm dynamic 24 + mem 2G, core 346ea21) — потолок 175 → **~235 rps**,
следующий узел — Postgres (тюнинг — P2 при росте трафика). Per-IP 429 на грани
сознательно не добавлен (вернуться при анти-абьюзе).

### Б-8 · Реферальная система — спека получена (диктовка владельца 19.09), аудит готовности сделан

**Канон от владельца:** глубины нет — только «представители под амбассадором»; код
амбассадора — 6 символов, стартовый **AA2222** (профиль Основателя, +79119287478);
амбассадора назначает основатель; амб выдаёт свой код, реп — свой личный; после
регистрации по реферальному коду пользователь может купить LOVII PASS, и **в этот
момент генерируется его личный промокод** для подключения МСП и пользователей.
Профиль Основателя должен иметь: роль основатель, амб AA2222, статус репа +
активную подписку «без отклонений», три МСП со своими ИНН, доступ к счёту
платформы со всеми операциями и распределениями по каждому платежу/списанию,
и **два** кода для шаринга (амб-код + личный реп-код).

**Аудит продукта 19.09 — готово (модель совпадает):**
- личный код при покупке PASS генерируется (префикс от привязанного кода →
  AA-XXXX у рекруитов; фолбэк AA; идемпотентно) — SubscriptionBillingService:226–247;
- QR в кабинете репа есть (`?ref=КОД`, AppQrCode);
- цепочка «регистрация по коду → покупка PASS → свой код → реп-кабинет» замкнута;
- Основатель = владелец активного AA2222 (ListBalanceAccountsQuery:131–141);
- амб видит префикс ветки с копированием + структуру репов.

**Гэпы (карточка SZ-061):**
- **G1 · два кода Основателя**: сейчас AA2222 = и амб-код, и единственный реп-код;
  механика личного кода пропустит выдачу (skip при активном коде). Нужен регламент
  «амб-код ≠ личный реп-код» + выдача второго кода Основателю. Развилка: амб-код

- **G3 · счёт платформы**: счёта `owner_type=platform` нет; Основателю виден
  только баланс номинального зеркала (platform_nominal, 1326 операций на
  staging). Нужен Founder-экран «Платформа»: ledger-операции с распределением

  подписка / выплата) — данные в `ledger_entries` полные.

- **G5 · профиль Основателя на staging**: подписка ✓ (активна до 19.10), реп ✓

**Ответы владельца (19.09, вечер):** экономика без изменений (п.2); смена
