# LOVII «как есть» — описание фактического поведения платформы по модулям

> Цель: выписать весь функционал и его логику **как есть** (по коду, не по планам),
> затем по каждому модулю вносить правки владельца и выписывать «чего не хватает».
> Это **рабочие заметки** (workspace, класс W), не канон SSOT: числа и правила
> ссылаются на дома канона (`lovii_docs/canon/PARAMS.md`, `BRD.md` и т.д.).
> После сверки владельцем найденные расхождения правятся в домах канона/коде,
> а не в этих файлах.

Срез кода: **2026-09-17** (локальный staging = точка интеграции, GitHub push закрыт).

> Дополнение 2026-09-18 (Super Z): после BACKLOG_REVIEW №1–№2 (реализация
> zcode, core `030f6e5`/`b21ac96`, app `e147433`) актуализированы: **02**
> (минимум заказа), **04** (домен подписки SZ-052), **05** (настройки точки +
> геокодинг адреса), **09** (команда b2b), **13** (правило ИНН в заявке);
> в «Кандидатах» 03/07 — ссылка на карточку T-009. Остальной срез — 2026-09-17.

## Формат каждого дока

1. «Что это» — модуль в двух словах.
2. «Путь покупателя» — что видит пользователь.
3. «Как работает» — API, данные, бизнес-правила (каждый факт с `file:line`).
4. «Чего нет / ограничения» — фактические заглушки.
5. «Кандидаты в „не хватает“» — открытые вопросы для фазы правок (решает владелец).
6. «Сверка владельцем» — вердикты и правки по факту ревью (дописывается по ходу).
