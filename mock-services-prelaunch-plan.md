# mock-services — мастер-план перед публикацией продукта (pre-launch)

Обновлён: 2026-10-14 (вечер) · Статус: решения §4 приняты; волны #110/#111/#112 оформлены
Цель продукта: **любой желающий может установить стенд и начать тестирование своих
интеграций без доступа к внутренней ИС.** Каналы: продуктовый репо (чистый) + образ GHCR
+ compose «одной командой» + гайды «за 10 минут».

## 0. Принципы (в т.ч. экономия)

- Dev-репо = разработка; продукт — отдельный репо после завершения разработки
  (состав утверждён: `mock-services-product-release.md`).
- **Экономия кредитов:** все мелкие правки — одним батчем у координатора (без сессий
  Арены); Арена — только на волны MS-04, MS-06 и (если вкл.) Такском; SZ — один раунд
  проб на волну + финальная приёмка кандидата; никаких «попутных» рефакторингов.
- «Самодостаточность» доказывается **прогоном с нуля на чистой машине по публичным
  докам** (dogfood, §2.3), а не заявлениями.

## 2. Продуктовая упаковка (после заморозки)

1. **Финализация состава**: контрольная сборка из замороженного main (шаблон —
   `mock-services-release-candidate-0.7.0.zip`) → просмотр владельцем.
2. **Адаптация под автономность** (обязательный блок — без него нет «самодостаточности»):
   - `package.json`: скрипты только для входящих в состав файлов — `npm test` и
     `npm start:*` должны работать в чистом клоне продукта (без check:links/check:drift/
     compose-selftest/dev-скриптов);
   - README продукта: один экран = одна команда запуска + curl-пример (MS-33 добить);
     убрать ссылки на исключённые файлы (CONTRIBUTING/SECURITY/CHANGELOG/AGENTS);
     все относительные ссылки проверить по составу;
   - дисклеймер: «неофициальный тестовый инструмент, не связан с банками/провайдерами;
     товарные знаки — владельцам»; заголовки — стандарт владельца (без изменений);
   - quickstart для include-контура (все сервисы) в README продукта.
3. **Dogfood «с нуля»** — главная приёмка: чистая машина (CHUWI/VM) → по ПУБЛИЧНОЙ
   документации: скачать compose → поднять → curl-проверка 1–2 сервисов + колбэк в
   «своё приложение» → находки → правки → повторный прогон.
4. **Образ 1.0.0**: сборка из замороженного состояния → GHCR `:1.0.0` (+digest) →
   анонимный pull проверен. Механика сборки: [предложение — минимальный CI в продуктовом
   репо; альтернатива — разовая сборка из dev].

## 3. Публикация (механика)

1. Создать продуктовый репо: **[РЕШЕНИЕ §4.2]** (предложение: `rucorp/mock-services-dist`)
   — чистая история, только утверждённый состав.
2. Коммит «v1.0.0» + минимальный issue-шаблон («вопрос по интеграции»).
3. GitHub Release v1.0.0: ноты с таблицей **всех** сервисов (не подмножеств!), образ+digest,
   «запуск одной командой», ссылка на dev-репо.
4. GHCR-гигиена: удалить старые теги (0.5.x/0.6.x/sha-*) — ручной шаг владельца
   (у токена нет scope packages).
5. (Опц.) анонс-заготовка: «3 шага: curl → up → гайд за 10 минут».
